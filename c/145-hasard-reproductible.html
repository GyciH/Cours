Le concept

Le hasard reproductible

Un générateur de hasard, dans un ordinateur, n'a rien de hasardeux : c'est une suite calculée à partir d'un nombre de départ, la graine. C'est une chance. Avec la même graine, un dessin génératif se retrouve à l'identique demain, sur une autre machine. Encore faut-il choisir, transmettre et consommer cette graine avec soin.

45 min de lecture et de QCM Prérequis · 67, 131 Exemples · Cuttlefish, SnapSet

L'idée en une phrase

Une graine fixe rend le hasard rejouable ; tout ce qui modifie l'ordre des tirages, un fil de plus, un tirage sauté, change pourtant la suite.

L'analogie

Un jeu de cartes mélangé une fois pour toutes et photographié : on peut redistribuer la même main, à condition de tirer les cartes dans le même ordre.

À la fin, tu sais

  1. donner une graine et la garder stable ;
  2. éviter les graines consécutives ;
  3. tirer depuis plusieurs fils ;
  4. attacher un tirage à son élément.
À retenir Dans un composant Grasshopper, une graine en entrée est un engagement : même entrée, même dessin. Sans graine, chaque recalcul redessine autre chose.

Schéma 1 · Choisir les graines

Des graines voisines, des débuts voisins

Il est tentant de créer un générateur par élément avec la graine G + k. Avec l'algorithme hérité qu'utilise .NET pour les graines, les premiers tirages de ces générateurs sont liés entre eux.

Exemple autonome · C#, un générateur maître qui distribue les grainesvar maitre = new Random(graine); var graines = Enumerable.Range(0, n).Select(_ => maitre.Next()).ToArray(); // puis new Random(graines[k])

Pourquoi ce pas fixe

L'algorithme hérité (Knuth, soustractif) dérive son état de la graine par une suite d'opérations simples : une graine plus grande d'un cran décale tout d'une quantité presque constante (déduit des mesures).

Grave ou pas

Pour un test qui essaie 1 500 graines, la couverture reste bonne : toutes les petites suites ont été atteintes. Pour colorier mille cellules, une couleur par graine k, le motif se verrait.

Piège courant Tirer pile ou face avec new Random(k).Next(2) pour k = 0, 1, 2… On obtient 1, 0, 1, 0… presque sans faute : 40 graines ont donné une alternance quasi parfaite (mesuré).

Schéma 2 · Plusieurs fils

Un Random partagé finit par ne rendre que des zéros

Random garde son état dans des champs ordinaires, sans verrou. Deux fils qui tirent en même temps peuvent l'écrire à moitié chacun ; il ne s'en remet pas.

Exemple autonome · C#, un générateur par tâche, graines tirées d'avancevar graines = Enumerable.Range(0, n).Select(_ => maitre.Next()).ToArray(); Parallel.For(0, n, i => { var r = new Random(graines[i]); Traiter(i, r); }); // reproductible et sûr

Pourquoi tirer d'avance

L'ordre dans lequel les fils s'exécutent change d'une exécution à l'autre. Une graine par élément, fixée avant de paralléliser, rend chaque résultat indépendant de cet ordre.

Hasard ou secret

Pour un mot de passe, un jeton, un sel : RandomNumberGenerator, cent fois plus lent mais imprévisible. Random est fait pour être rejoué, donc deviné (cours 63).

Piège courant Utiliser un Random de classe dans un Parallel.For. Après 8 millions de tirages concurrents, 1 000 tirages sur 1 000 valaient zéro, trois fois de suite, sans aucune exception (mesuré).

Schéma 3 · Consommer les tirages

Un tirage par élément, toujours

Le hasard rejouable suppose que chaque élément reçoive toujours le même tirage. Il suffit qu'un tirage dépende d'une condition pour que tous les suivants glissent d'un cran.

Exemple autonome · C#, tirer d'abord, décider ensuiteforeach (var cellule in cellules) { double angle = rand.NextDouble() * Math.PI; // tiré même si la cellule est ignorée if (!Valide(cellule)) continue; Hachurer(cellule, angle); }

Encore plus robuste

Dériver le tirage de l'identité de l'élément plutôt que de sa place : un hachage de (graine, numéro) ne dépend plus de l'ordre ni du nombre des tirages précédents.

Entre versions de .NET

.NET garde l'ancien algorithme pour les graines, par compatibilité ; la documentation ne promet pourtant pas qu'il en sera toujours ainsi. Pour une suite garantie à vie, on écrit son propre générateur.

Piège courant Ne tirer que pour les éléments utiles. Une seule cellule sautée a changé les 89 angles suivants sur 100 ; en tirant toujours, aucun (mesuré).

Glossaire

Générateur pseudo-aléatoire
Une suite calculée qui imite le hasard à partir d'un état de départ.
Graine
Le nombre qui fixe l'état de départ d'un générateur.
Reproductibilité
Obtenir le même résultat à partir des mêmes entrées.
xoshiro256**
Un générateur moderne et rapide, utilisé par .NET sans graine.
Générateur maître
Un générateur qui ne sert qu'à tirer les graines des autres.
