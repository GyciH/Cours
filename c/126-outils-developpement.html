Le concept

Les outils de développement

Tout ce que ce bloc a mesuré, les DevTools de Chrome le montrent sans écrire une ligne : la boucle, les mises en page, le stockage, le réseau, la mémoire. Encore faut-il savoir quel panneau ouvrir, dans quelles conditions mesurer, et ce que l'outil lui-même change à ce qu'on observe.

45 min de lecture et de QCM Prérequis · 121 à 125 Exemples · Magpie web construit

L'idée en une phrase

Poser la question, choisir le panneau, mesurer sur la version construite et sur une machine bridée, puis vérifier que l'outil ne fausse pas la mesure.

L'analogie

Les instruments d'un atelier de métrologie. Un pied à coulisse ne mesure pas une température ; et un comparateur mal posé appuie sur la pièce qu'il contrôle.

À la fin, tu sais

  1. choisir le bon panneau ;
  2. lire les tâches longues ;
  3. mesurer le code qui sert ;
  4. ne pas fausser la mémoire.
À retenir Une mesure vaut ce que valent ses conditions : mode développement ou construit, cache plein ou vide, processeur réel ou bridé. Les noter à côté du chiffre, comme ce bloc l'a fait.

Schéma 1 · Le panneau Performance

Les tâches longues

Le panneau Performance enregistre tout ce que fait le fil principal et marque d'un triangle rouge chaque tâche de plus de 50 ms. On a relevé les mêmes tâches au démarrage de Magpie, processeur réel puis bridé.

Exemple autonome · JavaScript, poser ses propres repèresperformance.mark("tester-debut"); const resultat = await envoyer(graphe); performance.measure("Tester", "tester-debut"); // apparaît dans la piste Timings du panneau

Lire une trace

Le graphique en flammes empile les appels : la largeur est le temps, la hauteur la profondeur. On cherche la barre large la plus basse qui vienne de notre code, pas de React.

Brider

La roue dentée du panneau propose de ralentir le processeur par 4 ou par 6, et le réseau. Ton poste de développement est plus rapide que la machine d'un apprenant.

Piège courant Mesurer sous npm run dev. React y tourne en mode développement, plus lent, et StrictMode y fait chaque rendu deux fois. Les chiffres de cette page viennent d'une version construite.

Schéma 2 · Coverage et Sources

Le code qui a servi

Le panneau Coverage compte, pendant un enregistrement, quels octets de chaque fichier ont été exécutés. On l'a fait au démarrage de Magpie, sur un écran large où la 3D se charge d'office.

Exemple autonome · vite.config.js, des cartes sans les publierexport default defineConfig({ build: { sourcemap: "hidden" }, // .map produites, non annoncées : on les charge soi-même });

Les cartes de code source

Un fichier .map relie chaque caractère minifié à sa ligne d'origine. Sources montre alors App.jsx et ses noms, et une erreur cite la vraie ligne.

Points d'arrêt

Dans Sources, un clic sur un numéro de ligne arrête le code à cet endroit ; un clic droit en fait un arrêt conditionnel, ou un logpoint qui écrit sans modifier le fichier.

Piège courant Lire « non exécuté » comme « inutile ». Coverage ne voit que ce qui a tourné pendant l'enregistrement : le code d'un bouton qu'on n'a pas cliqué paraît mort, et sert pourtant.

Schéma 3 · Mémoire et console

L'outil qui retient

Afficher un objet dans la console le garde en vie, pour qu'on puisse le déplier plus tard. On a mesuré ce que coûtent dix grosses réponses passées à console.log puis oubliées par la page.

Exemple autonome · JavaScript, ne journaliser qu'en développementif (import.meta.env.DEV) console.log("Réponse :", resultat); // retiré de la version construite else console.info("Réponse :", resultat.errors?.length ?? 0, "erreur(s)"); // un résumé, pas l'objet

Instantanés de tas

Memory prend une photo de tous les objets vivants. Deux photos, avant et après un geste répété, comparées : ce qui a grandi, et le chemin qui le retient.

Application

Le panneau Application liste localStorage, IndexedDB, le cache et le manifeste ; on y lit et on y efface ce que le cours 123 a rangé, clé par clé.

Piège courant Chercher une fuite mémoire sans vider la console. Les objets qu'elle affiche restent vivants : l'instantané les montre retenus, et on accuse le code d'une fuite que l'outil a créée.

Glossaire

Un travail de plus de 50 ms sur le fil principal.
Bridage
Le ralentissement simulé du processeur ou du réseau.
Couverture
La part du code exécutée pendant un enregistrement.

Le fichier .map qui relie code minifié et code d'origine.
