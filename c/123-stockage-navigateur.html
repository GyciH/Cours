Le concept

Le stockage du navigateur

Recharger la page efface la mémoire de JavaScript. Pour retrouver un parcours là où on l'a laissé, il faut ranger ses données dans un magasin que le navigateur garde sur disque. Il en offre plusieurs, chacun lié à une origine, avec ses limites : taille, types acceptés, partage entre onglets.

45 min de lecture et de QCM Prérequis · 117, 121 Exemples · Magpie web, useParcours

L'idée en une phrase

Ce qui doit survivre à un rechargement se range par origine, sous forme de chaînes pour localStorage, d'objets pour IndexedDB, et peut toujours disparaître.

L'analogie

Un tiroir de bureau par client. Petit, rapide à ouvrir, mais on n'y glisse que des feuilles ; pour les gros dossiers, il y a l'armoire, qu'on ouvre en prenant un ticket.

À la fin, tu sais

  1. choisir le bon magasin ;
  2. estimer ce qui tient dans le quota ;
  3. gérer plusieurs onglets ;
  4. échouer sans casser la page.
À retenir Le stockage du navigateur est un cache, pas une base de données : l'utilisateur peut l'effacer, le navigateur aussi. Ce qui ne doit jamais se perdre vit aussi sur le serveur.

Schéma 1 · Le quota

Cinq millions de caractères

localStorage ne range que des chaînes, et sa taille est limitée par origine. On l'a rempli jusqu'à l'erreur, avec trois sortes de caractères, puis on a mesuré ce que pèse une progression Magpie.

Exemple autonome · JavaScript, mesurer ce qu'on occupelet n = 0; for (let i = 0; i < localStorage.length; i++) { const k = localStorage.key(i); n += k.length + localStorage.getItem(k).length; } console.log(n, "caractères occupés sur environ 5 242 880");

Des chaînes seulement

On passe par JSON. Mesuré : JSON.stringify change une Date en texte, une Map en {}, NaN et Infinity en null. Relire ne rend donc pas toujours l'objet de départ.

Échouer sans casser

Plein, setItem lève QuotaExceededError. Magpie entoure chaque lecture et chaque écriture d'un try (useParcours.js:18 à 30) : la page continue, la progression reste en mémoire.

Piège courant Ranger un objet sans le sérialiser. localStorage.setItem(k, objet) ne lève aucune erreur : il range la chaîne « [object Object] », et la relecture rend ce texte au lieu des données.

Schéma 2 · Origines et onglets

Qui voit quoi

Tous les onglets d'une même origine partagent le même localStorage. Ils ne se préviennent que par un événement, que le code doit écouter. Sinon, chacun écrase le travail de l'autre.

Exemple autonome · JavaScript, suivre ce qu'un autre onglet a écritaddEventListener("storage", (e) => { if (e.key === cle && e.newValue) progression = JSON.parse(e.newValue); // un autre onglet a écrit });

sessionStorage

Même interface, mais un magasin par onglet : il survit au rechargement, pas à la fermeture. Utile pour un brouillon propre à un onglet, inutile pour reprendre un parcours le lendemain.

Navigation privée

Un contexte séparé part d'un magasin vide (mesuré) et le perd en fermant. Certains navigateurs refusaient même d'écrire : c'est le cas que prévoit le commentaire de useParcours.js:29.

Piège courant Ouvrir le même parcours dans deux onglets. Chacun garde sa copie en mémoire et réécrit l'objet entier : le dernier qui enregistre efface ce que l'autre a fait, sans le dire.

Schéma 3 · L'autre magasin

localStorage ou IndexedDB

IndexedDB range des objets entiers, sans passer par du texte, et sans bloquer le fil principal. En échange, tout y est asynchrone. On a rangé la même progression dans les deux.

Exemple autonome · JavaScript, ranger un graphe dans IndexedDBconst db = await new Promise((ok) => { const r = indexedDB.open("magpie", 1); r.onupgradeneeded = () => r.result.createObjectStore("graphes"); r.onsuccess = () => ok(r.result); }); db.transaction("graphes", "readwrite").objectStore("graphes").put(graphe, idExercice);

Durer

Par défaut, le stockage est « au mieux » : si le disque manque de place, le navigateur peut l'effacer. navigator.storage.persist() demande à le garder ; le navigateur peut refuser.

Savoir où on en est

navigator.storage.estimate() rend l'usage et le quota de l'origine, magasin par magasin. Il compte IndexedDB et le cache, mais pas localStorage, qui a sa propre limite.

Piège courant Écrire dans localStorage à chaque pointermove. Chaque écriture sérialise et bloque le fil : quelques millisecondes soixante fois par seconde deviennent une saccade. Magpie attend 500 ms de calme (App.jsx:54).

Glossaire

Origine
Le schéma, l'hôte et le port d'une page ; l'unité de partage du stockage.
Quota
La place qu'un magasin accorde à une origine.
Sérialiser
Changer un objet en texte pour le ranger, ici avec JSON.
Clonage structuré
La copie d'objets que fait IndexedDB, sans passer par du texte.
Stockage au mieux
Gardé tant que le navigateur n'a pas besoin de la place.
