Le concept

Les scripts Node d'outillage

Magpie a deux petits scripts dans outils/ : l'un recopie un parcours de ton dossier de travail vers le binaire, l'autre recopie la skill et les agents vers .claude/. Ils sont bâtis sur le même patron : une source, un artefact qui en est la copie, et un mode --check qui dit si les deux ont divergé.

45 min de lecture et de QCM Prérequis · 29, 30, 41 et 45 Exemples · outils/publier-parcours.mjs, outils/sync-claude.mjs (Magpie)

L'idée en une phrase

Quand un même contenu doit exister à deux endroits, on n'en édite qu'un ; l'autre est fabriqué par un script, et un second mode du même script vérifie, sans rien toucher, que la copie est à jour.

L'analogie

Le tirage d'une photo. On retouche le négatif, jamais le tirage ; et l'on peut toujours poser le tirage à côté du négatif pour voir s'il est encore fidèle.

À la fin, tu sais

  1. trouver la racine du dépôt depuis un script, où qu'on le lance ;
  2. lire options et variables d'environnement ;
  3. synchroniser deux dossiers : écrire, sauter, supprimer ;
  4. rendre un code de sortie qu'un hook ou une CI comprend.
À retenir L'artefact ne s'édite pas à la main : « l'éditer à la main revient à écrire dans un dossier de sortie, et la prochaine publication l'écrasera » (publier-parcours.mjs, lignes 15–17). Les deux scripts le disent dans leur en-tête, et --check le fait respecter.

Schéma 1 · Trouver ses repères

Où est le dépôt, où est la source ?

Un script peut être lancé depuis n'importe quel dossier. Il calcule donc la racine du dépôt à partir de son propre fichier, puis cherche la source par une chaîne de replis, du plus explicite au plus général.

Magpie · outils/publier-parcours.mjs · 26–27 et 39–55const RACINE = dirname(dirname(fileURLToPath(import.meta.url))); const check = process.argv.includes("--check"); … const APPDATA = process.env.APPDATA ?? join(homedir(), ".config"); … const SOURCE = process.env.MAGPIE_APPDATA ?? dossierRegle() ?? join(APPDATA, "Magpie");

import.meta.url

Dans un module ES, import.meta.url est l'adresse du fichier en cours, en file://. fileURLToPath en fait un chemin, et deux dirname remontent de outils/publier-parcours.mjs à la racine. Le dossier courant n'intervient pas.

Lire les réglages de Grasshopper

dossierRegle ouvre Grasshopper/Magpie.xml, y cherche l'élément DossierTravail par une expression régulière, et décode les entités XML (lignes 41–51). Le script trouve ainsi le même dossier que le plugin.

Piège réel Deux règles qui divergent. Le plugin revient au dossier par défaut quand le dossier réglé a disparu (disque débranché) ; un script qui ne le ferait pas publierait depuis un autre endroit que celui où l'auteur travaille. D'où la ligne 50 : existsSync(dossier) ? dossier : null, « même règle ».

Schéma 2 · Trois listes

Écrire, sauter, supprimer

Synchroniser, c'est comparer deux listes : ce qui devrait être dans l'artefact (les attendus) et ce qui y est (les présents). De là sortent trois sortes de fichiers, et chacune a son geste.

Magpie · outils/publier-parcours.mjs · 29–32 et 91–102// Les parcours à embarquer. Un seul pour octobre — et c'est volontairement une // liste explicite, pas un balayage du dossier : le %AppData% de l'auteur contient // aussi ses brouillons, qui n'ont rien à faire dans le binaire livré. const PARCOURS = ["G2V_01"]; … for (const id of PARCOURS) { const brut = lire(PARCOURS_DIR, id); attendus.set(join(PARCOURS_DIR, `${id}.json`), brut); const def = JSON.parse(brut.toString("utf8")); for (const exId of def.ExerciseIds ?? []) attendus.set(join(EXERCICES, `${exId}.json`), lire(EXERCICES, exId)); }

Comparer octet par octet

readFileSync sans encodage rend un Buffer, et Buffer.equals compare les octets. Un fichier identique est sauté : rien n'est réécrit, et la date de modification ne bouge pas.

Refuser ce qui ne se relit pas

lire parse chaque JSON avant de le publier (lignes 73–89). Un fichier cassé arrête tout : « le dire ici coûte une ligne ; le découvrir en salle, une séance ».

Piège courant Oublier les fichiers en trop. Un exercice retiré du parcours mais resté dans plugin/Resources continuerait d'être servi par la source embarquée, alors que plus rien ne le cite (lignes 116–117). Recopier ne suffit pas : il faut aussi supprimer.

Schéma 3 · Vérifier sans toucher

--check et les codes de sortie

Le même parcours des fichiers sert deux modes. Sans option, le script écrit. Avec --check, il n'écrit rien, compte les divergences et sort avec un code que peut lire une autre machine.

Magpie · outils/publier-parcours.mjs · 145–153if (check) { if (divergences) { console.error( `\n${divergences} divergence(s) entre ${SOURCE} et plugin/Resources.\n` + `Lance « node outils/publier-parcours.mjs », puis recompile le .gha.`, ); process.exit(1); } console.log("Les parcours embarqués sont à jour."); }

Trois codes, trois sens

0 : à jour, ou recopié. 1 : divergence trouvée par --check. 2 : la source elle-même pose problème (dossier introuvable, fichier absent ou illisible). Un hook de pré-commit ou une CI n'a besoin que de ce nombre.

Un message qui dit quoi faire

Une divergence ne se contente pas de « erreur » : le message donne la commande à lancer, et l'étape d'après (« puis recompile le .gha »). Les sorties normales vont sur console.log, les problèmes sur console.error.

Piège réel Corriger un exercice dans %AppData% et oublier de le republier : le binaire livre l'ancienne version. C'est « exactement la panne que ce chantier ferme » (lignes 12–13). --check la rend visible avant le commit, au lieu de la laisser arriver en salle.

Glossaire

Artefact
Un fichier fabriqué depuis une source, qu'on régénère au lieu de l'éditer.
Code de sortie
Le nombre qu'un programme rend en finissant : 0 pour « tout va bien ».
Variable d'environnement
Un réglage passé au programme par le système, lu par process.env.
Buffer
Un tableau d'octets bruts en Node, sans encodage de texte.
Hook de pré-commit
Un script que git lance avant chaque commit, et qui peut le refuser.
