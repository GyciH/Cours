Le concept

Chargement d'assemblies

Magpie se livre en quatre .gha : Apprenant, Auteur, Serveur, Dev. Tous ont besoin du même moteur, Magpie.Core. Le défi : n'installer qu'un fichier par version, et n'avoir qu'un seul moteur en mémoire, quelle que soit la combinaison installée.

50 min de lecture et de QCM Prérequis · 24 ressources embarquées · 26 tests Exemples · ChargeurCore, Directory.Build.targets (Magpie)

L'idée en une phrase

Une assembly est un fichier .dll (ou .gha) de code .NET compilé. Le runtime la charge au premier usage d'un de ses types ; s'il ne la trouve pas, il demande au programme de la fournir, par l'événement AssemblyResolve.

L'analogie

Quatre colocataires arrivent chacun avec sa cafetière. On n'en branche qu'une, la plus récente, et tout le monde s'en sert. Celle qui est branchée le reste jusqu'au prochain déménagement.

À la fin, tu sais

  1. suivre ce que fait .NET quand il lui manque une assembly ;
  2. embarquer une DLL dans un .gha à la compilation ;
  3. lire la version d'une assembly sans la charger ;
  4. éviter qu'un type public force un chargement trop tôt.
À retenir Une assembly chargée dans le contexte par défaut ne se décharge plus. Tout le système de Magpie découle de cette règle : choisir la bonne version avant le premier chargement, et la partager ensuite.

Schéma 1 · Quand .NET cherche une assembly

Introuvable sur le disque, fournie sur demande

Chaque .gha est compilé contre Magpie.Core mais ne le copie pas à côté de lui (Private="false" dans ses ProjectReference). Au premier besoin, le runtime ne le trouve pas : c'est voulu.

plugin/Directory.Build.targets · 10–22, condensé<ItemGroup Condition="'$(TargetExt)' == '.gha'"> <Compile Include="$(MSBuildThisFileDirectory)Chargeur\ChargeurCore.cs" Link="Chargeur\ChargeurCore.cs" /> </ItemGroup> <Target Name="EmbarquerMagpieCore" AfterTargets="ResolveProjectReferences" Condition="'$(TargetExt)' == '.gha'"> <ItemGroup> <EmbeddedResource Include="@(_ResolvedProjectReferencePaths)" Condition="'%(Filename)' == 'Magpie.Core'" LogicalName="Magpie.Core.dll" /> </ItemGroup> </Target>

Un fichier importé par MSBuild

Directory.Build.targets est lu de lui-même par tout projet situé sous plugin\. Les quatre .gha reçoivent donc le même chargeur, compilé par lien (cours 26), et la même ressource, sans rien écrire dans leur .csproj.

AfterTargets, pour la bonne DLL

Le plugin cible net7.0-windows et net7.0. La cible attend que les références soient résolues : la DLL de Core embarquée est celle de la cible en cours de compilation, pas l'autre.

Piège courant Laisser traîner un Magpie.Core.dll dans un dossier de Grasshopper. .NET le trouverait avant de lever AssemblyResolve : le chargeur ne serait jamais appelé, et la version servie serait celle du fichier oublié (en-tête de ChargeurCore.cs).

Schéma 2 · Choisir sans charger

Lire la version de chaque Core embarqué

Le chargeur ouvre chaque Magpie*.gha des dossiers de Grasshopper comme un simple fichier, extrait la ressource Magpie.Core.dll, lit son numéro de version, et ne charge que la plus récente.

ChargeurCore.cs · 168–182, condenséusing (var pe = new PEReader(File.OpenRead(fichier))) { var md = pe.GetMetadataReader(); foreach (var h in md.ManifestResources) { var r = md.GetManifestResource(h); if (!r.Implementation.IsNil || md.GetString(r.Name) != Ressource) continue; var rva = pe.PEHeaders.CorHeader.ResourcesDirectory.RelativeVirtualAddress; var lecteur = pe.GetSectionData(rva).GetReader(); lecteur.Offset = (int)r.Offset; return lecteur.ReadBytes(lecteur.ReadInt32()); // longueur, puis octets } }

Lire n'est pas charger

PEReader et MetadataReader (System.Reflection.Metadata) lisent le format d'un exécutable .NET octet par octet. Aucun code n'est exécuté, rien n'entre dans le runtime : on peut inspecter dix fichiers et n'en garder aucun.

Charger depuis des octets

AssemblyLoadContext.Default.LoadFromStream charge la DLL depuis la mémoire, dans le contexte que partagent tous les plugins. Aucun fichier sur le disque n'est verrouillé ; en contrepartie, l'assembly n'a pas d'emplacement (Location vide).

Piège courant Croire qu'une mise à jour s'applique tout de suite. Le Core déjà chargé reste jusqu'à la fermeture de Rhino. Et un ancien .gha tourne alors avec un Core plus récent : Core peut ajouter des membres, jamais en retirer ni en renommer.

Schéma 3 · Le chargement qui arrive trop tôt

Grasshopper lit tes types avant ton code

Pour trouver les composants d'un .gha, Grasshopper commence par GetExportedTypes, qui prépare tous les types publics. C'est avant même PriorityLoad, donc avant que le chargeur soit branché.

Admin/MagpieExerciseEditor.cs · 56–63, condensé// UN ENTIER, PAS L'ÉNUMÉRATION DE CORE, dans le champ. Ce type est public : Grasshopper // le charge (GetExportedTypes) avant toute ligne de notre code […] private int _mode = (int)ValidationMode.ExactOrderedList; public ValidationMode Mode { get => (ValidationMode)_mode; private set => _mode = (int)value; }

Pourquoi une valeur, pas une classe

Pour préparer un type, .NET calcule la place de ses champs. Un champ de type référence occupe toujours la taille d'une adresse. Un champ de type valeur (enum, struct) a la taille de ce type : il faut donc charger l'assembly qui le définit.

La propriété garde son type

Le reste du code écrit toujours ed.Mode == ValidationMode.GeometryTolerance. Seul le stockage change : un int, converti à la lecture et à l'écriture. Une propriété n'a pas de place à calculer.

Piège courant L'échec silencieux. Grasshopper écarte le .gha entier ; le seul indice est « Could not load file or assembly 'Magpie.Core' » dans l'historique de Rhino. Constaté le 20/10/2026 sur MagpieExerciseEditor.Mode et MagpieParcoursLauncher.Entree.Provenance.

Glossaire

Assembly
Un fichier de code .NET compilé : .dll, ou .gha pour Grasshopper.
Résolution
La recherche, par le runtime, d'une assembly demandée par son nom.
Contexte de chargement
L'espace où vivent les assemblies chargées ; Default est partagé.
Type valeur
Une enum ou une struct : stockée en place, sa taille dépend du type.
Idempotent
Qu'on peut appeler plusieurs fois avec le même effet qu'une seule.
