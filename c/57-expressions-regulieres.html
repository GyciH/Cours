Le concept

Les expressions régulières

Une expression régulière (regex) est un petit langage pour décrire une famille de textes : « un dièse puis six chiffres hexadécimaux », « le mot partial suivi d'un nom qui commence par Sur ». Le moteur dit si un texte en fait partie, où, et ce qu'il contient.

50 min de lecture et de QCM Prérequis · 25 et 56 Exemples · Convertisseurs, EcrivainGeneration, generer-modele.js (SnapSet)

L'idée en une phrase

On écrit un motif avec des briques (classes de caractères, répétitions, ancres, groupes) ; le moteur le compare au texte caractère par caractère et revient en arrière quand une piste échoue.

L'analogie

Un gabarit de découpe posé sur une planche. Le gabarit ne connaît pas la planche, il décrit seulement une forme ; on le fait glisser jusqu'à ce qu'il tombe juste, et on garde les morceaux découpés (les groupes).

À la fin, tu sais

  1. lire un motif brique par brique ;
  2. choisir $ ou \z, gourmand ou paresseux ;
  3. capturer des morceaux et remplacer avec $1 ;
  4. reconnaître ce qu'une regex ne sait pas faire.
À retenir Une regex vérifie une forme, pas un sens. Elle dit « six chiffres hexadécimaux », pas « une couleur que GH_Skin connaît ». Pour un format plat (code couleur, numéro de version, nom de méthode) elle est parfaite ; pour un langage imbriqué (JSON, C#), il faut un vrai analyseur.

Schéma 1 · Les briques

Quatre familles suffisent

Une classe dit quel caractère est accepté, un quantificateur combien de fois, une ancre où (sans consommer de caractère), un groupe rassemble un morceau pour le répéter ou le récupérer. Tout le reste se combine à partir de là.

Exemple autonome · C#bool ok = Regex.IsMatch("#FF8800", @"^#[0-9A-F]{6}\z"); // true Match m = Regex.Match("version 2.13", @"(\d+)\.(\d+)"); string majeure = m.Groups[1].Value; // "2" string mineure = m.Groups[2].Value; // "13" int n = Regex.Matches("a1 b22 c333", @"\d+").Count; // 3

Les quatre verbes

IsMatch répond oui ou non, Match rend le premier résultat et ses groupes, Matches les rend tous, Replace réécrit chaque résultat. Groups[0] est toujours le texte trouvé en entier.

Le @ devant la chaîne

En C#, "\d" serait une séquence d'échappement de chaîne. La chaîne verbatim @"\d" garde l'antislash tel quel pour le moteur. En JavaScript, on écrit le motif entre barres : /\d+/g.

Piège courant Le point est une brique, pas un point. 1.5 accepte « 105 ». Pour un vrai point on écrit \., et pour insérer un texte venu d'ailleurs dans un motif on passe par Regex.Escape, qui neutralise tous les caractères spéciaux.

Schéma 2 · Comment le moteur cherche

Gourmand, paresseux, retour arrière

Par défaut, * et + sont gourmands : ils prennent le plus possible, puis rendent des caractères un à un si la suite du motif échoue. Ajouter ? les rend paresseux : le moins possible d'abord. Ce va-et-vient s'appelle le retour arrière.

Exemple autonome · C#var bloc = new Regex(@"/\*.*?\*/", RegexOptions.Singleline); // . traverse aussi les \n var sur = new Regex(@"^[\w ]+\z", RegexOptions.None, TimeSpan.FromMilliseconds(200)); // au-delà : RegexMatchTimeoutException var lineaire = new Regex(@"^(a+)+b\z", RegexOptions.NonBacktracking); // .NET 7 et suivants

Singleline et Multiline

Deux options indépendantes aux noms trompeurs. Singleline laisse le point accepter \n. Multiline fait de ^ et $ des débuts et fins de ligne. On peut avoir les deux, ou aucune.

Pourquoi ça explose

Dans (a+)+, une suite de « a » peut se découper de 2n−1 façons, et le moteur les essaie toutes avant d'admettre l'échec. Un motif sans quantificateurs imbriqués ne connaît pas ce problème.

Piège courant Appliquer un motif à quantificateurs imbriqués sur un texte saisi par l'utilisateur. Rhino se fige pendant que le moteur explore des milliards de pistes. Un délai maximal, ou l'option NonBacktracking, garantit que la recherche s'arrête.

Schéma 3 · Capturer et remplacer

Les groupes servent deux fois

Les parenthèses capturent : chaque groupe reçoit un numéro, de gauche à droite, et le remplacement peut les réutiliser avec $1, $2. Voici la fonction displayName de SnapSet qui fabrique un libellé lisible à partir d'une clé du schéma.

Exemple autonome · C#var d = Regex.Match("2026-10-24", @"(?<a>\d{4})-(?<m>\d\d)-(?<j>\d\d)"); string jour = d.Groups["j"].Value; // "24" string fr = Regex.Replace("2026-10-24", @"(\d{4})-(\d\d)-(\d\d)", "$3/$2/$1"); // "24/10/2026" string net = Regex.Replace(texte, @"\s+", " "); // blancs multiples → un seul string dbl = Regex.Replace("a1 b2", @"\d", x => (int.Parse(x.Value) * 2).ToString()); // "a2 b4"

Nommer ses groupes

(?<jour>…) se lit Groups["jour"] : le code survit à l'ajout d'un groupe en tête, ce que Groups[1] ne fait pas. (?:…) regroupe sans numéroter, pour ne pas décaler les autres.

Quand ne pas en écrire

Pour « commence par », StartsWith est plus clair. Pour un langage imbriqué (accolades, chaînes, commentaires), un analyseur est nécessaire : Roslyn pour le C#, JSON.parse pour le JSON.

Piège courant En JavaScript, "aa".replace(/a/, "b") donne « ba » : sans le drapeau g, seul le premier résultat est remplacé. En C#, Regex.Replace remplace tout par défaut. Même idée, deux comportements.

Glossaire

Motif
L'expression qui décrit la famille de textes cherchée.
Ancre
Une position (début, fin, frontière de mot) qui ne consomme aucun caractère.
Groupe capturant
Une partie entre parenthèses dont le texte trouvé est conservé et numéroté.
Gourmand
Un quantificateur qui prend le plus possible avant de rendre ; paresseux : l'inverse.
Retour arrière
Le moteur défait un choix pour essayer le suivant quand la suite échoue.
