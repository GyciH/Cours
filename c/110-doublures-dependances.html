Le concept

Doublures et dépendances

Le code utile parle presque toujours à quelque chose d'extérieur : un serveur, une base, le disque, l'horloge. Pour le tester vite et sans dépendre de cet extérieur, on le remplace par une doublure, comme une doublure de cinéma remplace l'acteur pour une scène. Le cours suit le cas de Magpie, dont le serveur web dépend de Rhino Compute.

45 min de lecture et de QCM Prérequis · 109 Exemples · Magpie web

L'idée en une phrase

On isole le code testé de ce qu'il ne contrôle pas, en lui donnant une imitation de sa dépendance dont on choisit les réponses.

L'analogie

Un banc d'essai de moteur. On ne monte pas le moteur dans une voiture pour le tester : un frein simule la route, une sonde simule le réservoir, et l'on peut provoquer à volonté la côte, la panne d'essence ou le froid.

À la fin, tu sais

  1. nommer les six sortes de doublures ;
  2. utiliser un enregistrement réel ;
  3. monter un faux serveur ;
  4. repérer une couture dans le code.
À retenir Une doublure ne prouve que ce qu'elle imite. Plus elle s'éloigne du vrai service, plus le test peut être vert alors que l'ensemble ne marche pas : quelques tests de bout en bout, contre le vrai service, restent nécessaires.

Schéma 1 · Rejouer le réel

Un enregistrement comme doublure

La doublure la plus fidèle est une vraie réponse, capturée une fois sur le vrai service puis rangée avec les tests. Magpie fait ainsi pour l'aperçu 3D : la réponse de Compute à un graphe de neuf objets est un fichier JSON lu par les tests.

Code réel · magpie/web/test/apercu.test.mjs, ligne 9const fixture = JSON.parse(readFileSync(new URL("./fixtures/apercu-compute.json", import.meta.url), "utf8"));

Dire d'où vient l'enregistrement

Le commentaire en tête d'apercu.test.mjs (lignes 2–3) dit que la fixture a été « enregistrée sur un vrai Compute » et liste les objets. Sans cette trace, personne ne saurait la refaire.

Le chemin relatif au test

new URL("./fixtures/…", import.meta.url) trouve le fichier à côté du test, d'où qu'on lance node --test. Un chemin relatif simple dépendrait du dossier courant.

Piège courant Modifier la fixture à la main pour faire passer un test. Elle ne représente plus Compute, mais l'idée qu'on s'en fait : le test devient un bouchon déguisé en enregistrement. On la régénère sur le vrai service.

Schéma 2 · Un faux qui marche

Provoquer les pannes à volonté

Un faux est une version simplifiée mais fonctionnelle de la dépendance. Ici, un petit serveur HTTP qui imite Compute : selon le scénario, il répond bien, répond une erreur, tarde, ou n'est pas là. Les cas de panne, difficiles à obtenir avec le vrai service, deviennent des tests ordinaires.

Exemple autonome · Node, le cœur du faux Computehttp.createServer((req, res) => { if (mode === "lent") return setTimeout(() => repondre(200, {}), 3000); if (mode === "html") return res.writeHead(502).end("<html>Bad Gateway</html>"); repondre(200, { values: [], errors: [], warnings: [] }); }).listen(6599);

Un délai raccourci pour le test

Avec le délai réel de 20 s (ligne 35), le cas « Compute muet » ferait attendre 20 s. Réglable par l'environnement, il passe à 1 s pour le test (mesuré : 1 015 ms).

Ce que le faux a révélé

Quand Compute répond une page HTML, le proxy la recopie dans message et la transmet au navigateur avec le code 502 (ligne 210). Rien d'anormal à la lecture du code ; le faux le montre en 27 ms.

Piège courant Laisser le faux serveur tourner après le test. Le port reste pris, le test suivant échoue avec « address already in use », sans rapport avec le code testé. On l'arrête dans un after(), même en cas d'échec.

Schéma 3 · Les coutures

Prévoir la place de la doublure

Une couture est un endroit où l'on peut changer ce que fait le code sans le modifier : un paramètre, un réglage, un import. Le choix de la couture décide de la taille du test : une fonction seule en quelques millisecondes, ou tout un serveur.

Exemple autonome · node:test, un espion à la place de fetchconst faux = mock.fn(async () => ({ ok: false, status: 500 })); assert.equal(await resoudre("<a/>", faux), "erreur 500"); assert.equal(faux.mock.callCount(), 1); // espion : appelé une fois assert.equal(faux.mock.calls[0].arguments[1].method, "POST");

Bouchon ou simulacre

Le bouchon répond ; on vérifie le résultat du code. Le simulacre vérifie la façon d'être appelé. Le second casse à chaque réécriture interne, même juste : on le garde pour les effets visibles (un e-mail envoyé, un appel facturé).

Séparer démarrage et logique

Un fichier qui exporte ses fonctions et un autre qui fait listen() : le test importe le premier sans démarrer de serveur. C'est la couture qui manque à compute-proxy.mjs.

Piège courant Doubler ce qu'on est en train de tester. Un test de validation.mjs qui remplace validateSubmission par un bouchon ne vérifie plus que le bouchon. On ne double que les dépendances, jamais le sujet du test.

Glossaire

Doublure
Un objet qui remplace une dépendance pendant un test.
Fixture
Une donnée préparée pour les tests, ici une réponse enregistrée.
Faux (fake)
Une version simplifiée qui fonctionne vraiment.
Simulacre (mock)
Une doublure qui vérifie comment elle est appelée.
Couture (seam)
Un point où changer le comportement sans toucher au code.
