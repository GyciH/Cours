Le concept

Les génériques

Écrire une méthode une fois, pour des types qu'on ne connaît pas encore : c'est un paramètre de type, le T de List<T>. Le compilateur vérifie chaque usage, et .NET évite d'emballer les valeurs. Une contrainte dit quels types sont admis.

45 min de lecture et de QCM Prérequis · 01, 03 Exemples · SnapSet, Magpie plugin

L'idée en une phrase

Un générique garde le type exact d'un bout à l'autre : pas de conversion vers object, pas de boîte, et une erreur de type se voit à la compilation plutôt qu'à l'usage.

L'analogie

Un gabarit de perçage réglable. Le même outil sert pour chaque pièce ; la butée, la contrainte, empêche d'y glisser une pièce qu'il percerait de travers.

À la fin, tu sais

  1. repérer une mise en boîte ;
  2. choisir la bonne contrainte ;
  3. comparer sans emballer ;
  4. lire une erreur de variance.
À retenir Une contrainte trop large laisse passer à la compilation ce qui échouera à l'exécution. La plus étroite qui couvre les vrais usages est la bonne.

Schéma 1 · Sans boîte

Ce qu'évite List<int>

Avant les génériques, une liste rangeait des object. Un int devait être emballé dans un petit objet pour y entrer. On a compté le temps et la mémoire, puis le prix d'une comparaison.

Exemple autonome · C#, ne signaler que ce qui changevoid Poser<T>(ref T champ, T valeur) { if (EqualityComparer<T>.Default.Equals(champ, valeur)) return; // aucune boîte, même pour un double champ = valeur; Redessiner(); }

Valeur ou référence

Un int, un double, un Point3d sont des valeurs. Les passer là où on attend un object crée une boîte sur le tas. C'est invisible dans le code, et coûteux dans une boucle.

Un code par type valeur

Le compilateur à la volée produit une version de List<T> pour int, une pour double ; les types référence partagent une seule version.

Piège courant Écrire object.Equals(a, b) ou a.Equals((object)b) dans une méthode générique. Le code compile, mais chaque appel emballe ses deux valeurs : 48 octets par comparaison mesurés.

Schéma 2 · Les contraintes

Dire quels types sont admis

Sans contrainte, on ne peut presque rien faire de T. Chaque contrainte ouvre des possibilités et ferme la porte à des types. On a essayé la même méthode avec deux contraintes.

Exemple autonome · C#, la contrainte qui dit toutpublic static T Depuis<T>(string texte, T defaut) where T : struct, Enum => Enum.TryParse<T>(texte, true, out var v) && Enum.IsDefined(typeof(T), v) ? v : defaut;

Plusieurs paramètres

GeometryTypeRegistry.cs enregistre chaque géométrie par une paire de types, la donnée et son paramètre, chacun avec ses contraintes (lignes 56 à 58).

new() a un prix

new T() passe par un appel indirect : une vingtaine de nanosecondes au lieu d'une. Négligeable à côté d'une désérialisation ; à éviter dans une boucle serrée.

Piège courant Mettre where T : struct pour dire « une énumération ». int, double et Point3d passent aussi : l'erreur attend l'exécution, au lieu de bloquer la compilation.

Schéma 3 · La variance

Un sac de chaînes est-il un sac d'objets ?

Une chaîne est un objet. Une liste de chaînes n'est pas une liste d'objets : on pourrait y glisser un nombre. Mais une suite qu'on ne fait que lire peut l'être. On a demandé au compilateur.

Exemple autonome · C#, lire une liste sous un type plus largeList<GH_Point> points = Lire(); IEnumerable<IGH_Goo> donnees = points; // permis : IEnumerable<out T> ne fait que rendre des T foreach (var d in donnees) Console.WriteLine(d.TypeName);

out et in

out T : l'interface ne fait que rendre des T, elle accepte un type plus précis. in T : elle ne fait qu'en recevoir, comme IComparer<in T>, et accepte un type plus large.

Func et Action

Func<out TResult> et Action<in T> suivent la même règle : un Func<string> peut servir là où un Func<object> est attendu.

Piège courant Passer un string[] à une méthode qui attend object[] et qui y écrit. Ça compile ; la première écriture d'un autre type lève ArrayTypeMismatchException, loin de l'appel fautif.

Glossaire

Paramètre de type
Le T d'une classe ou d'une méthode générique, fixé à l'usage.
Contrainte
La condition que T doit remplir, écrite après where.
Mise en boîte
La copie d'une valeur dans un objet, pour la traiter comme object.
Covariance
Accepter un type plus précis là où l'on ne fait que lire.
Contravariance
Accepter un type plus large là où l'on ne fait que recevoir.
