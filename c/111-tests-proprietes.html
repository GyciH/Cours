Le concept

Tests de propriétés

Un test par exemple vérifie une réponse qu'on a calculée à la main. Un test de propriété énonce une règle qui doit tenir pour toute entrée, puis tire des centaines d'entrées au hasard pour essayer de la mettre en défaut. Quand il y arrive, il simplifie le cas jusqu'au plus petit qui échoue encore.

45 min de lecture et de QCM Prérequis · 109 Exemples · Magpie, SnapSet

L'idée en une phrase

On décrit ce qui doit toujours être vrai, et la machine cherche un contre-exemple à notre place, sur bien plus de cas qu'on n'en écrirait.

L'analogie

Un essai de fatigue. On ne vérifie pas une pièce sous trois charges choisies : on la secoue des milliers de fois avec des charges variées, et si elle casse, on cherche la plus petite charge qui la casse encore.

À la fin, tu sais

  1. énoncer une propriété ;
  2. lire un contre-exemple réduit ;
  3. comparer deux implémentations ;
  4. reconnaître les quatre formes classiques.
À retenir Les tests de propriétés ne remplacent pas les exemples : un exemple documente un cas qu'on veut voir écrit noir sur blanc ; une propriété garde la règle générale. Les deux se complètent.

Schéma 1 · Chercher, puis réduire

Un contre-exemple lisible

Un tirage au hasard trouve vite un cas qui casse, mais rarement un cas simple. La réduction (shrinking) essaie des variantes plus petites (moins d'éléments, valeurs plus proches de zéro, écart plus faible) et garde chacune tant que l'échec persiste.

Exemple autonome · JavaScript, la propriété tirée mille foislet g = 42; const rnd = () => ((g = (g * 1103515245 + 12345) % 2147483648) / 2147483648); for (let k = 0; k < 1000; k++) { const att = tirerListe(), i = tirerIndice(att), d = (rnd() < .5 ? -1 : 1) * (0.02 + rnd()); if (verdict(decaler(att, i, d), att)) return echec(k, att, i, d); // devait refuser }

La graine

Le hasard d'un test doit être rejouable : un générateur à graine fixe (ici 42) redonne la même suite. Une bibliothèque affiche la graine d'un échec pour qu'on le rejoue à l'identique.

Tirer des deux côtés

Le signe de l'écart est tiré lui aussi. C'est ce qui a trouvé le défaut du mutant au 2e essai : un écart négatif, le côté que les tests par exemples n'essayaient pas.

Piège courant Recopier l'implémentation dans la propriété. Si l'on vérifie la tolérance avec la même formule que le code, une erreur de formule passe des deux côtés. La propriété s'écrit à partir de la règle (« plus que la tolérance, dans un sens ou l'autre »).

Schéma 2 · Deux correcteurs

Le test différentiel

Quand deux programmes doivent faire la même chose, chacun sert d'oracle à l'autre. Magpie corrige les réponses deux fois : dans le plugin Grasshopper (C#) et sur le serveur web (JavaScript). Le commentaire de validation.mjs dit qu'il « reproduit » le plugin ; une propriété le vérifie.

Exemple autonome · les deux lectures d'un nombre, côte à côteNumber("") // 0 (JavaScript) Number("0x10") // 16 double.TryParse("", NumberStyles.Float, …) // false (C#) double.TryParse("1,5", …, fr-FR, out v) // true, v = 1.5

Pourquoi Number est trop gentil

Number convertit la chaîne vide et les blancs en 0, accepte l'hexadécimal, et refuse la virgule. Le plugin a fait le choix inverse sur chaque point, exprès (AnswerValues.cs:38, 40–41).

Comment le mesurer

La fonction C# a été recopiée dans un petit programme .NET 8, la culture réglée sur fr-FR, et les mêmes saisies passées des deux côtés. Rien n'a été modifié dans le plugin.

Piège courant Croire qu'un portage est fidèle parce que ses tests reprennent ceux de l'original. Les deux suites testent les mêmes exemples choisis ; les désaccords se cachent dans les entrées que personne n'a choisies.

Schéma 3 · Trouver la propriété

Quatre formes qui reviennent

Le plus difficile est d'énoncer la règle sans calculer la réponse. Quatre formes couvrent la plupart des cas : l'aller-retour, l'invariance, le déterminisme, et la comparaison à un oracle.

Exemple autonome · xUnit, une propriété sur des données tirées[Theory, MemberData(nameof(DessinsTires))] // 200 dessins à graine fixe public void LeTexteEstDeterministe(DescriptionDessin d) => Assert.Equal(GenerateurDessin.TexteDessin(d), GenerateurDessin.TexteDessin(d));

Les générateurs

Tirer des listes de nombres est simple ; tirer un dessin SnapSet valide (une racine, des enfants, des tags uniques) demande un générateur qui respecte les règles, sinon chaque essai est rejeté avant d'être testé.

Theory, déjà une table

SnapSet compte 71 [Theory] et 353 [InlineData] : des tables d'exemples. Passer de la table au tirage, c'est remplacer la liste écrite par un générateur.

Piège courant Tirer sans contrainte et filtrer après. Si neuf essais sur dix sont des entrées invalides écartées, la propriété ne voit presque rien. On construit des entrées valides dès le tirage.

Glossaire

Propriété
Une règle qui doit tenir pour toute entrée valide.
Contre-exemple
Une entrée qui met la propriété en défaut.
Réduction (shrinking)
La simplification d'un contre-exemple qui garde l'échec.
Oracle
Ce qui dit la bonne réponse : une règle, ou une autre implémentation.
Générateur
Le code qui tire des entrées au hasard, valides par construction.
