Quand un apprenant clique sur « Vérifier », le backend de Magpie envoie son graphe à Rhino Compute et attend la réponse, parfois plusieurs secondes. Pendant ce temps, il doit continuer à servir les autres. JavaScript n'a qu'un fil d'exécution : tout repose sur l'attente sans blocage.

55 min de lecture et de QCM Prérequis · 29 JavaScript pour un développeur C# Exemples · compute-proxy.mjs, app.cjs, src/api.js (Magpie)

L'idée en une phrase

Une promesse (Promise) représente une valeur qui arrivera plus tard. await suspend la fonction jusqu'à son arrivée et rend la main entre-temps. C'est le Task<T> et le await que tu connais en C#.

L'analogie

Un serveur de restaurant. Il prend une commande, la transmet en cuisine et s'occupe des autres tables. Quand le plat est prêt, on l'appelle et il reprend cette commande là où il l'avait laissée. Un seul serveur, aucune table abandonnée.

À la fin, tu sais

  1. lire async, await et une promesse, à partir de C# ;
  2. borner une attente dans le temps avec AbortController ;
  3. distinguer module ES (import) et CommonJS (require) ;
  4. suivre une requête dans un serveur Node.
À retenir Node.js exécute du JavaScript hors du navigateur, avec ses propres modules : node:http pour servir, node:fs pour les fichiers, node:sqlite pour la base de Magpie. Le langage est le même des deux côtés ; seuls les outils disponibles changent.

Schéma 1 · Promesses et async/await

Ce que tu sais déjà, sous d'autres noms

Les mots-clés sont les mêmes qu'en C#, et ils jouent le même rôle. Une fonction async rend toujours une promesse, même quand elle écrit return d'une simple valeur.

compute-proxy.mjs · 195–205, condenséasync function callCompute(xml) { const controller = new AbortController(); const timeoutId = setTimeout(() => controller.abort(), COMPUTE_TIMEOUT_MS); try { const response = await fetch(`${COMPUTE_TARGET}/grasshopper`, { method: "POST", …, signal: controller.signal, }); const text = await response.text(); …

Deux attentes, pas une

fetch se résout dès que les en-têtes de la réponse arrivent. Le corps, lui, arrive ensuite : response.text() est une seconde promesse, d'où le second await.

setTimeout, un rappel

setTimeout(fonction, délai) range la fonction pour plus tard et rend la main aussitôt. Ici, dans 20 s (COMPUTE_TIMEOUT_MS), elle annulera l'appel, sauf si on l'a désarmée avant.

Piège courant Oublier await. const text = response.text(); ne contient pas le texte mais la promesse du texte. JSON.parse(text) échoue alors sur « [object Promise] ». Aucune erreur à l'écriture : c'est l'exécution qui le révèle.

Schéma 2 · Les modules

Un fichier, un module

Chaque fichier JavaScript est un module : ce qu'il ne marque pas export reste privé. Un autre fichier l'utilise par import. C'est l'équivalent, par fichier, de public et de using.

app.cjs · 7–16const { existsSync } = require("node:fs"); const { join } = require("node:path"); const envFile = join(__dirname, ".env"); if (existsSync(envFile)) process.loadEnvFile(envFile); import("./compute-proxy.mjs").catch((err) => { console.error("Démarrage du backend Magpie impossible :", err); process.exit(1); });

Deux systèmes, deux extensions

Module ES (.mjs, ou .js avec "type": "module" dans package.json) : import, export. CommonJS (.cjs), l'ancien système de Node : require(), module.exports.

Pourquoi un app.cjs

L'hébergeur (Passenger, chez o2switch) démarre l'application avec require(), qui ne lit pas un module ES (en-tête du fichier). app.cjs sert de passerelle : import(), la forme dynamique, charge le vrai serveur et rend une promesse.

Piège courant Un secret dans le code. L'adresse de Compute, sa clé, le mot de passe d'administration sont lus dans process.env (les variables d'environnement), remplies depuis un .env jamais versionné. Sans mot de passe, l'administration reste fermée.

Schéma 3 · Un serveur Node

Une requête, des événements

http.createServer reçoit une fonction appelée à chaque requête. Le corps de la requête n'arrive pas d'un bloc : Node émet un événement data par morceau, puis end.

compute-proxy.mjs · 683–702, condenséconst parts = []; let received = 0; req.on("data", (c) => { received += c.length; if (received > maxBytes) { tooLarge = true; parts.length = 0; return; } parts.push(c); }); req.on("end", async () => { const body = Buffer.concat(parts).toString("utf-8"); if (tooLarge) throw new HttpError(413, `Requête trop volumineuse …`); if (req.url === "/api/solve" && req.method === "POST") await handleSolve(body, res); …

On s'abonne, Node appelle

req.on("data", f) est le += d'un événement C#. Node appelle f à chaque morceau reçu. Entre deux morceaux, le fil est libre pour les autres requêtes.

Borner aussi la taille

Un corps de plus de 1 Mo (16 Mo pour l'administration, qui envoie des graphes de départ) est refusé par un 413. Sans cette limite, un envoi énorme occuperait la mémoire du serveur.

Piège courant Une exception dans un rappel asynchrone n'est rattrapée par personne si on ne l'attend pas. D'où le try … catch à l'intérieur du rappel end : toute erreur y devient une réponse JSON avec son statut, et le serveur continue de tourner.
