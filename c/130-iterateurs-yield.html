Le concept

Les itérateurs et yield

Une méthode qui contient yield return ne rend pas une liste : elle rend une promesse de liste. Rien ne s'exécute à l'appel ; chaque élément est produit au moment où le foreach le demande. C'est économe, c'est paresseux, et c'est à chaque parcours que tout recommence.

45 min de lecture et de QCM Prérequis · 03, 127 Exemples · SnapSet, Magpie plugin

L'idée en une phrase

Un itérateur fabrique ses éléments à la demande, en reprenant son code là où il s'était arrêté ; on ne paie que ce qu'on lit, mais on le repaie à chaque lecture.

L'analogie

Une recette plutôt qu'un plat. On peut s'arrêter après la première assiette ; mais servir deux fois, c'est cuisiner deux fois.

À la fin, tu sais

  1. prévoir quand le code tourne ;
  2. éviter le double parcours ;
  3. fermer ce qu'un itérateur ouvre ;
  4. mesurer un yield récursif.
À retenir IEnumerable dit « on peut parcourir », pas « c'est déjà calculé ». Celui qui reçoit un itérateur et le lit deux fois fait tourner deux fois le code de celui qui l'a écrit.

Schéma 1 · Paresseux, et à chaque fois

Quand le code tourne vraiment

On a écrit un itérateur qui note chaque élément qu'il fabrique, puis on l'a parcouru de plusieurs façons : deux fois de suite, avec un break, et à la main.

Exemple autonome · C#, figer un parcours qu'on reliravar sources = Sources().ToList(); // le code de Sources tourne une fois, ici Console.WriteLine(sources.Count); foreach (var s in sources) Charger(s); // on relit la liste, pas la recette

Les erreurs aussi sont paresseuses

Une vérification d'argument écrite dans un itérateur ne lève qu'au premier MoveNext, loin de l'appel. D'où les méthodes qui vérifient d'abord, puis délèguent à un itérateur privé.

Les sources de Magpie

MagpieRepository.cs:78 décrit les sources par trois yield : local, cache, embarqué. Chaque lecture des Sources reconstruit ces trois objets, ce qui ne coûte presque rien.

Piège courant if (items.Any()) foreach (var i in items) … sur un itérateur qui lit des fichiers. Any lance la lecture, foreach la relance depuis le début : deux ouvertures pour un seul usage.

Schéma 2 · Le type caché

Ce que le compilateur écrit pour toi

Une méthode ne peut pas s'arrêter au milieu et reprendre. Le compilateur la transforme donc en classe, qui garde l'endroit où elle en est. On l'a retrouvée par réflexion.

Exemple autonome · C#, un tableau plutôt qu'un itérateurprivate static Widget[] Construire() // aucun type caché : un tableau existe déjà => new[] { new WidgetSignature(), new WidgetNavigation() };

Un automate

Chaque yield devient un état numéroté ; MoveNext saute à l'état suivant, exécute jusqu'au yield d'après, range l'élément dans Current et rend true.

Quand l'éviter

Pour deux ou trois éléments connus d'avance, un tableau est plus simple et n'ajoute aucun type à l'assembly. Magpie a fait ce choix pour ses widgets, après un échec de chargement.

Piège courant Garder un itérateur ouvert à la main (GetEnumerator, MoveNext) sans Dispose. Son finally ne s'exécute jamais : un fichier ouvert dans un using de l'itérateur reste ouvert (mesuré).

Schéma 3 · Le yield récursif

Un arbre, des itérateurs emboîtés

Parcourir un arbre en rappelant l'itérateur pour chaque enfant est élégant. Mais chaque élément remonte toute la pile d'itérateurs. On a comparé avec une pile explicite.

Exemple autonome · C#, le même parcours préfixe sans récursionvar pile = new Stack<IEnumerator<Guid>>(); pile.Push(MembresDe(racine).GetEnumerator()); while (pile.Count > 0) { var e = pile.Peek(); if (!e.MoveNext()) { pile.Pop(); continue; } yield return e.Current; pile.Push(MembresDe(e.Current).GetEnumerator()); }

Pourquoi ça grandit

À profondeur 100, un élément du bas passe par cent MoveNext imbriqués avant d'arriver au foreach. Le travail suit le nombre d'éléments fois leur profondeur.

Doit-on changer ?

Pas pour des arbres de quelques niveaux : la version récursive est la plus lisible, et ses millisecondes ne se voient pas. La pile sert aux arbres profonds.

Piège courant Appeler un parcours de sous-arbre pour chaque nœud d'un arbre. Chaque sous-arbre est reparcouru autant de fois qu'il a d'ancêtres : 8 secondes mesurées au lieu de 26 ms.

Glossaire

Itérateur
Une méthode à yield, qui produit ses éléments un par un, à la demande.
Évaluation paresseuse
Un calcul repoussé jusqu'au moment où l'on en a besoin.
Énumérateur
L'objet qui parcourt : MoveNext avance, Current donne l'élément.
Automate
La classe cachée qui retient l'état où l'itérateur s'est arrêté.
Parcours préfixe
Un parcours d'arbre qui rend chaque parent avant ses enfants.
