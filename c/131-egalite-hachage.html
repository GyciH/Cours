Le concept

L'égalité et le hachage

« Ces deux-là sont-ils égaux ? » cache deux questions : est-ce le même objet, ou la même valeur ? C# laisse chaque type choisir sa réponse, et tous les dictionnaires s'y fient. Quand Equals et GetHashCode ne disent pas la même chose, une clé rangée devient introuvable.

45 min de lecture et de QCM Prérequis · 128, 129 Exemples · SnapSet, Magpie plugin

L'idée en une phrase

Equals dit si deux choses sont égales, GetHashCode dit où ranger chacune ; un dictionnaire marche tant que deux choses égales sont rangées au même endroit.

L'analogie

Un vestiaire : le numéro du ticket (le hash) indique le crochet, puis on vérifie le manteau (Equals). Un ticket faux, et on cherche au mauvais crochet.

À la fin, tu sais

  1. dire quelle égalité un type offre ;
  2. tenir le contrat Equals / hash ;
  3. choisir un comparateur de chaînes ;
  4. comparer des nombres à virgule.
À retenir Une classe est égale à elle-même seulement ; un record, un struct ou une chaîne sont égaux par leur contenu. Redéfinir Equals oblige à redéfinir GetHashCode, avec les mêmes champs.

Schéma 1 · Le contrat

Le hash range, Equals confirme

Un HashSet ne compare pas la clé cherchée à toutes les autres : il calcule son hash, va au seau correspondant, et n'appelle Equals que là. On a cassé ce contrat de trois façons.

Exemple autonome · C#, une clé qui tient le contratpublic sealed record Cle(string Id, int Version); // Equals et GetHashCode écrits par le compilateur var vus = new HashSet<Cle> { new Cle("exo1", 2) }; bool deja = vus.Contains(new Cle("exo1", 2)); // True : même valeur, même seau

Le contrat en deux lignes

Si a.Equals(b), alors leurs hash sont égaux. L'inverse n'est pas exigé : deux valeurs différentes peuvent partager un hash, ce n'est qu'un peu plus lent.

Le compilateur prévient

Redéfinir Equals sans GetHashCode donne l'avertissement CS0659 (relevé à la compilation de l'essai). Un avertissement, pas une erreur : le code tourne, et rate ses recherches.

Piège courant Modifier une clé déjà rangée. Le record reste dans son ancien seau : Contains le cherche dans le nouveau et rend False, et Add le range une deuxième fois (Count passe à 2, mesuré).

Schéma 2 · Le mauvais hash

Quand tout tombe dans le même seau

Un hash qui ne distingue rien ne casse pas le résultat : il casse le temps. On l'a mesuré avec un hash constant, puis avec un struct qui n'a ni Equals ni GetHashCode.

Exemple autonome · C#, un struct prêt à servir de clépublic readonly struct Bord : IEquatable<Bord> { public float H { get; } public float D { get; } public float B { get; } public float G { get; } public bool Equals(Bord o) => (H, D, B, G).Equals((o.H, o.D, o.B, o.G)); public override bool Equals(object o) => o is Bord b && Equals(b); public override int GetHashCode() => HashCode.Combine(H, D, B, G); }

L'Equals par défaut d'un struct

Avec des champs float, le runtime compare champ par champ par réflexion, après avoir mis le struct dans une boîte : 312 octets alloués par appel (mesuré).

Son GetHashCode par défaut

Il n'a lu que le premier champ : mille bords qui ne diffèrent qu'à droite ont tous eu le même hash. Un string en tête fait pareil (mesuré).

Piège courant Prendre un struct maison comme clé de dictionnaire sans IEquatable ni GetHashCode. Le code est juste et les tests passent ; c'est à 2 000 clés qu'on attend près d'une seconde (mesuré).

Schéma 3 · Chaînes et nombres

Égaux selon qui compare

Pour une chaîne, « égal » dépend de la casse et de la langue ; pour un double, de l'arrondi. On a posé les mêmes paires à chaque comparateur.

Exemple autonome · C#, dire la règle au lieu de la subirvar ids = new HashSet<string>(StringComparer.OrdinalIgnoreCase); // Exo1 et exo1 : un seul exercice bool proches = Math.Abs(a - b) <= 1e-9 * Math.Max(Math.Abs(a), Math.Abs(b)); // pas a == b

Lequel choisir

Ordinal pour un identifiant de code, OrdinalIgnoreCase pour un nom de fichier sous Windows. La culture seulement pour trier du texte montré à quelqu'un : elle coûte plus de dix fois plus.

NaN est à part

L'opérateur == suit la norme IEEE : NaN n'égale rien. Equals suit le contrat : NaN s'égale lui-même, sinon une collection ne pourrait jamais le retrouver.

Piège courant Comparer deux chaînes sans dire comment, ou avec ToUpper(). Le résultat dépend alors de la langue du poste : « file » et « FILE » diffèrent sur un Windows turc (mesuré en tr-TR).

Glossaire

Égalité de référence
Deux variables désignent le même objet en mémoire.
Égalité de valeur
Deux objets ont le même contenu, champ par champ.
Hash
Un entier tiré du contenu, qui choisit le seau où ranger la clé.
Collision
Deux clés différentes au même hash : permis, mais à éviter en masse.
Comparateur
Un objet passé à une collection pour lui imposer une autre règle d'égalité.
