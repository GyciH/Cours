Le concept

React et Vite

Le front de Magpie ne retouche jamais la page à la main. Chaque composant est une fonction qui décrit ce que l'écran doit montrer pour un état donné ; quand l'état change, React rappelle la fonction et applique la différence. Vite, lui, sert ces fichiers pendant le développement et les assemble pour la mise en ligne.

55 min de lecture et de QCM Prérequis · 29 et 30 Exemples · App.jsx, QuickSearch.jsx, hooks/, vite.config.js (Magpie)

L'idée en une phrase

L'écran est une fonction de l'état : tu écris ce qu'il faut afficher, jamais comment passer d'un affichage à l'autre. Le passage, React le calcule.

L'analogie

Grasshopper. Tu ne redessines pas la géométrie quand tu bouges un curseur : tu as câblé une fois la définition, et le graphe se recalcule en aval. Un composant React est cette définition ; setState est le curseur qui bouge.

À la fin, tu sais

  1. lire un composant, son JSX et ses props ;
  2. employer useState, useEffect, useMemo et useRef ;
  3. reconnaître un hook maison comme useCatalog ;
  4. dire ce que fait Vite en développement et au build.
À retenir Un composant React est une fonction qui reçoit des props et rend du JSX. Ce qu'il doit retenir d'un rendu à l'autre passe par des hooks (useState…). Une règle fixe : on appelle les hooks en tête de fonction, toujours dans le même ordre, jamais dans un if.

Schéma 1 · Composants et props

Un arbre de fonctions

main.jsx monte un seul composant dans la balise <div id="root"> d'index.html. Tout le reste en découle : chaque composant en appelle d'autres dans son JSX et leur passe des props, comme des arguments.

App.jsx · 106–118 et 142–155, condenséreturn ( <div className="magpie-app-layout"> {layout.chromeOpen && <ExerciseHeader parcours={parcours} />} {!rotateHintClosed && ( <button onClick={() => setRotateHintClosed(true)}>✕</button> )} <ExercisePanel exercise={currentExercise} onSubmit={handleSubmit} … /> …

Le JSX, c'est du JavaScript

Les accolades insèrent une expression. cond && <X /> affiche X seulement si cond est vrai. On écrit className, car class est un mot réservé du langage. Vite traduit chaque balise en appel de fonction.

Les données descendent, les événements remontent

Les props arrivent en un seul objet, qu'on déstructure : function ExerciseHeader({ parcours }). Un enfant ne les modifie pas. Pour prévenir son parent, il appelle une fonction reçue en prop, comme onSubmit.

Piège courant Oublier key dans un map. Sans clé stable, React reconnaît les éléments d'une liste par leur position : supprime le premier, et l'état du deuxième glisse sur le premier. Magpie donne une identité, jamais l'index : key={ex.id} (ExerciseHeader.jsx, ligne 59).

Schéma 2 · Les hooks

Ce qu'une fonction retient entre deux appels

Une fonction ordinaire oublie tout à la sortie. Les hooks donnent au composant une mémoire, rangée par React à côté de lui. Leurs noms commencent tous par use, y compris ceux que tu écris toi-même.

hooks/useCatalog.js · 5–30, condenséexport default function useCatalog() { const [catalog, setCatalog] = useState([]); const [error, setError] = useState(null); useEffect(() => { let cancelled = false; fetchCatalog() .then((data) => { if (!cancelled) setCatalog(data); }) .catch((err) => { if (!cancelled) setError(err.message); }); return () => { cancelled = true; }; }, []); …

Un nouvel objet, jamais une retouche

React voit un changement quand la référence change. useLayoutPrefs écrit donc { ...p, [field]: !p[field] } (ligne 40) : une copie modifiée. Retoucher p en place ne redessinerait rien.

L'effet qui se retire

La fonction rendue par un effet est son nettoyage. Ici, elle lève le drapeau cancelled : si le composant disparaît avant la réponse du serveur, la réponse arrive dans le vide au lieu de toucher un état mort.

Piège courant En développement, <StrictMode> (main.jsx, ligne 10) monte, démonte puis remonte chaque composant : chaque effet s'exécute deux fois. C'est voulu. Un effet sans nettoyage, par exemple un addEventListener sans removeEventListener, se retrouve alors doublé et se voit tout de suite.

Schéma 3 · Vite

Deux façons de servir le même front

Le navigateur ne lit pas le JSX. En développement, Vite traduit chaque fichier à la demande et met la page à jour à chaque enregistrement. Pour la mise en ligne, npm run build produit une fois pour toutes des fichiers prêts, dans dist/.

vite.config.js · 1–12import { defineConfig } from "vite"; import react from "@vitejs/plugin-react"; export default defineConfig({ plugins: [react()], server: { proxy: { "/api": "http://localhost:5175", }, }, });

Le relais /api

Le front appelle toujours /api/… en relatif (src/api.js). En développement, Vite relaie ces appels vers le backend sur le port 5175. En ligne, c'est le backend lui-même qui sert la page : une seule origine, aucune adresse en dur.

lazy et Suspense

lazy(() => import("./Viewer3D.jsx")) (App.jsx, ligne 18) fait de l'aperçu 3D un fichier à part : three.js n'est téléchargé qu'à sa première ouverture. En attendant, <Suspense> affiche « Chargement de l'aperçu 3D… ».

Piège courant Modifier src/ et ne rien voir en ligne. Le backend sert dist/, pas les sources : il faut relancer npm run build. Sans build du tout, il répond « Front non construit : lancer npm run build » (compute-proxy.mjs, ligne 503).

Composant
Une fonction qui reçoit des props et rend du JSX.
JSX
Des balises dans le JavaScript, traduites en appels de fonction par Vite.
Hook
Une fonction use… qui donne au composant une mémoire ou un effet.
Rendu
Un appel du composant ; React en déduit les retouches de la page.
Build
L'assemblage des sources en fichiers prêts à servir, dans dist/.
