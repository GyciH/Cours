Le concept

La compression

Compresser sans perte, c'est réécrire un fichier plus court en exploitant ce qu'il a de prévisible : des répétitions, des symboles plus fréquents que d'autres. Le .gh de Grasshopper, le .docx, le PNG et les objets de Git reposent tous sur le même algorithme, deflate. Il gagne beaucoup sur du texte, rien sur ce qui est déjà compressé.

45 min de lecture et de QCM Prérequis · 115, 103 Exemples · Magpie plugin, exercices, dépôt

L'idée en une phrase

On ne compresse que ce qui se répète ou se devine ; un contenu déjà compressé ressemble au hasard, et le recompresser ne fait que l'alourdir d'un en-tête.

L'analogie

La nomenclature qui écrit « vis M6 × 20, 48 fois » au lieu de 48 lignes identiques. Elle raccourcit une liste répétitive ; appliquée à une liste déjà regroupée, elle n'a plus rien à regrouper.

À la fin, tu sais

  1. expliquer les deux idées de deflate ;
  2. choisir un algorithme et un niveau ;
  3. repérer une double compression ;
  4. prévoir ce que Git fera d'un fichier.
À retenir Le gain dépend du contenu, pas de l'algorithme : sur le binaire de A_01.gh, cinq compresseurs tiennent dans 4 %. Sur un brep déjà déflaté, tous perdent.

Schéma 1 · Algorithmes et niveaux

Plus fort, plus lent, à peine plus court

Chaque compresseur propose des niveaux : plus le niveau est haut, plus il cherche loin les répétitions. On a mesuré les plus courants sur le même contenu, celui d'un exercice Grasshopper de Magpie.

Exemple autonome · Python, écrire un deflate brut comme un .ghimport zlib c = zlib.compressobj(6, zlib.DEFLATED, -15) # niveau 6, -15 : sans en-tête zlib gh = c.compress(arbre) + c.flush() assert zlib.decompress(gh, -15) == arbre # sans perte : on retrouve chaque octet

Compresser, décompresser

Deflate est asymétrique : 1,4 ms pour compresser au niveau 6, 0,2 ms pour décompresser (mesuré). On écrit un .gh une fois, on le lit souvent : c'est le bon sens du compromis.

Brut, zlib, gzip

Même flux deflate, trois emballages. Le brut n'a rien (le .gh) ; zlib ajoute 2 octets devant et une somme de contrôle de 4 octets ; gzip un en-tête de 10 octets, un CRC et la taille. L'en-tête sert à détecter un fichier abîmé.

Piège courant Ouvrir un .gh avec zlib.decompress(brut), sans le -15. La fonction attend l'en-tête zlib, ne le trouve pas, et répond « incorrect header check ». Le fichier n'est pas abîmé : il est brut.

Schéma 2 · Compresser deux fois

Quand la compression alourdit

Magpie range les géométries de référence des exercices dans le JSON, sous forme d'un chunk GH_IO sérialisé, puis codé en base64. Serialize_Binary déflate toujours. On a décodé les huit géométries du dépôt.

Exemple autonome · Python, ne compresser que si l'on y gagnedef emballer(donnees): c = zlib.compress(donnees, 6) return (b"Z" + c) if len(c) < len(donnees) else (b"B" + donnees) # 1 octet dit lequel def deballer(b): return zlib.decompress(b[1:]) if b[:1] == b"Z" else b[1:]

L'entropie

Elle mesure l'imprévisibilité d'un octet, de 0 à 8 bits. Un contenu à 7,6 bits par octet n'a presque plus de marge : c'est la signature d'un flux déjà compressé, ou chiffré.

Le base64 par-dessus

Le base64 ajoute un tiers à ce qui sort de deflate (12 312 octets deviennent 16 416 caractères). Compresser après le base64 regagnerait une partie de ce tiers, jamais la compression perdue avant.

Piège courant Zipper un dossier de PNG, de .docx ou de .gh pour « gagner de la place ». Ils sont déjà déflatés : l'archive pèse presque autant que les fichiers. On compresse le texte, on range le reste tel quel (méthode « stored » du zip).

Schéma 3 · Ce que Git en fait

Le texte fond, le compressé reste

Git range ses objets compressés et, dans un pack, écrit beaucoup de versions comme une différence avec une version voisine. On a additionné, pour chaque type de fichier, la taille de toutes ses versions et la place qu'elles prennent dans le pack.

Exemple autonome · Git, la place réelle d'un objetgit rev-list --objects --all \ | git cat-file --batch-check="%(objectsize) %(objectsize:disk) %(rest)" # objectsize : taille du contenu objectsize:disk : place dans le pack

Le .docx, un zip de XML

Les 126 fiches .docx de Magpie contiennent 2 444 fichiers, tous déflatés : 127 Mo de XML qui tiennent en 20 Mo. Un seul styles.xml passe de 349 538 à 11 620 octets. Le texte y est, mais Git ne le voit pas.

Les PNG

Leur contenu est déflaté, mais faiblement : redéflater les 1 593 PNG au niveau 9 gagne 15 % (27,5 Mo à 23,5 Mo, mesuré). Un outil d'optimisation de PNG le ferait sans changer un pixel.

Piège courant Croire que Git stocke « seulement les différences » de tout fichier. Pour un .docx ou un .gh retouché, la différence avec la version voisine est presque tout le fichier : chaque version coûte sa taille pleine.

À surveiller · le poids du dépôt Mesuré sur ce clone : le pack pèse 71 274 Kio, dont 44 % de PNG, 26 % de .docx et 5 % de .gh, contre 0,3 % pour toutes les versions des sources C#. Glossaire

Sans perte
Une compression qui rend chaque octet d'origine.
Deflate
Renvois aux répétitions (LZ77) puis codage de Huffman.
Entropie
L'imprévisibilité moyenne d'un octet, de 0 à 8 bits.
Somme de contrôle
Un nombre calculé sur les données pour détecter une altération.
Pack
Le fichier où Git range ses objets compressés et différenciés.
