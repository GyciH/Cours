Le concept

La boucle d'événements

Dans un onglet, un seul fil d'exécution fait tout : il lance ton JavaScript, traite les clics, calcule la mise en page et dessine. Il le fait par tours, selon une règle fixe, la boucle d'événements. La connaître explique pourquoi une page « gèle », pourquoi un setTimeout(0) n'est pas immédiat, et où placer un calcul.

45 min de lecture et de QCM Prérequis · 30, 59 Exemples · Magpie web

L'idée en une phrase

Le navigateur ne peut rien faire d'autre pendant que ton code tourne ; une page fluide est faite de petits morceaux de travail qui lui rendent souvent la main.

L'analogie

Un seul opérateur au poste de commande d'une machine-outil : il lit les ordres, surveille l'écran et répond au téléphone. S'il lance un usinage de dix minutes sans lever les yeux, le téléphone sonne dans le vide.

À la fin, tu sais

  1. prévoir l'ordre de rappels mélangés ;
  2. reconnaître une tâche longue ;
  3. rendre la main pendant un calcul ;
  4. choisir entre setTimeout, rAF et debounce.
À retenir Un tour de boucle : une tâche, toutes les microtâches, puis, si l'écran attend une image, le rendu. Tout ce qui retarde une étape retarde les autres.

Schéma 1 · Qui passe en premier

Tâches, microtâches, image

Les promesses, setTimeout et requestAnimationFrame déposent chacun leur rappel dans une file différente. On les a programmés ensemble, dans le désordre, et on a relevé l'ordre réel.

Exemple autonome · JavaScript, rendre la main au navigateurconst rendreLaMain = () => new Promise((r) => setTimeout(r, 0)); // une tâche, pas une microtâche for (let i = 0; i < morceaux.length; i++) { traiter(morceaux[i]); if (i % 50 === 49) await rendreLaMain(); // clics et images passent entre deux paquets }

Les microtâches, toutes

La file des microtâches est vidée entièrement, y compris celles ajoutées en cours de route. C'est pourquoi await Promise.resolve() ne rend pas la main : on reste dans le même tour.

requestAnimationFrame

Il passe juste avant le dessin de la prochaine image, une fois par image. C'est le bon endroit pour lire une taille ou animer, et le mauvais pour attendre « un peu » : dans un onglet caché, il ne passe plus.

Piège courant Compter sur setTimeout(f, 0) pour une exécution « tout de suite ». Il attend la fin du code en cours et de toutes les microtâches, puis son tour dans la file ; imbriqué, il prend au moins 4 ms ; dans un onglet en arrière-plan, le navigateur peut le retarder d'une seconde ou plus.

Schéma 2 · La tâche longue

Quand la page ne répond plus

Un clic n'est pas traité quand il arrive, mais quand le fil se libère. On a cliqué avec une vraie souris simulée pendant que la page calculait, puis sur la page au repos.

Exemple autonome · JavaScript, repérer les tâches longuesnew PerformanceObserver((liste) => { for (const t of liste.getEntries()) console.warn("tâche longue", Math.round(t.duration), "ms"); }).observe({ type: "longtask", buffered: true }); // Chromium : toute tâche de plus de 50 ms

Ce que mesure l'utilisateur

Il ne voit ni la durée du calcul ni celle de la requête : il voit le temps entre son geste et l'image qui y répond. Chrome le note dans l'indicateur INP (Interaction to Next Paint).

Le réseau ne bloque pas

Un fetch qui dure 20 secondes ne gèle rien : le fil attend sans travailler, et la réponse arrive comme une tâche. Ce qui gèle, c'est le calcul, et le traitement d'une grosse réponse (un JSON.parse de plusieurs Mo).

Piège courant Marquer une fonction async pour la « rendre non bloquante ». Son corps s'exécute sur le même fil ; jusqu'au premier await d'une vraie attente, elle bloque autant qu'une fonction ordinaire, et une chaîne de microtâches bloque même le rendu.

Schéma 3 · Attendre le bon moment

Reporter, regrouper, dessiner à la demande

Bien utiliser la boucle, c'est aussi ne pas travailler pour rien : regrouper une rafale de modifications en une écriture, attendre que la mise en page soit faite, ne dessiner que ce qui change.

Exemple autonome · JavaScript, un debounce et sa sortie de secourslet minuteur = null; function planifier(f, ms) { clearTimeout(minuteur); minuteur = setTimeout(f, ms); } addEventListener("pagehide", () => { if (minuteur) { clearTimeout(minuteur); sauvegarder(); } });

Debounce ou throttle

Le debounce agit une fois, quand la rafale s'arrête. Le throttle agit au plus une fois par intervalle, pendant la rafale : pour un aperçu qui suit le geste, c'est lui qu'il faut.

Dessiner à la demande

Viewer3D ne fait pas tourner de boucle d'animation : il redessine sur l'événement change d'OrbitControls (ligne 106) et au redimensionnement. Une scène immobile ne coûte rien.

Piège courant Lancer une boucle requestAnimationFrame permanente pour une vue qui bouge rarement. Elle dessine 60 fois par seconde une image identique, chauffe le processeur graphique et vide la batterie d'un portable.

Glossaire

Boucle d'événements
La règle qui enchaîne tâches, microtâches et rendu sur un seul fil.
Microtâche
Un rappel de promesse, passé avant toute nouvelle tâche.
Tâche longue
Une tâche de plus de 50 ms, qui retarde clics et images.
Debounce
Agir une fois, quand une rafale d'événements s'arrête.
Throttle
Agir au plus une fois par intervalle pendant la rafale.
