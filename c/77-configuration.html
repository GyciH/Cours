Le concept

La configuration

Le même code tourne sur ton poste, sur celui d'un élève et chez o2switch. Ce qui diffère d'un lieu à l'autre (une adresse, un mot de passe, un dossier) ne s'écrit pas dans le code : c'est la configuration. Bien la ranger, c'est pouvoir déployer sans modifier une ligne, et ne jamais publier un secret par accident.

50 min de lecture et de QCM Prérequis · 63, 68 et 69 Exemples · compute-proxy, app.cjs, MagpieReglages (Magpie), CheminCible (SnapSet)

L'idée en une phrase

Chaque réglage a une portée (document, poste, serveur) qui décide où le ranger, une valeur par défaut sûre, et une vérification au plus tôt, pour qu'une faute de frappe se voie au démarrage et pas au premier élève.

L'analogie

Une voiture de location. Le moteur est le même pour tous ; le siège, les rétroviseurs et la radio se règlent par conducteur, et ne se règlent pas en démontant le tableau de bord.

À la fin, tu sais

  1. choisir où ranger un réglage ;
  2. lire l'ordre de priorité des sources ;
  3. valider une valeur venue de l'environnement ;
  4. garder les secrets hors du dépôt.
À retenir Un bon test : le dépôt pourrait-il devenir public demain sans rien révéler ? Si oui, les secrets sont bien hors du code. Le code peut alors décrire quels réglages existent (un fichier d'exemple), jamais leurs valeurs réelles.

Schéma 1 · Les variables d'environnement

Plusieurs sources, un ordre

Chaque processus reçoit un ensemble de variables nommées, héritées de celui qui l'a lancé (cours 69). Un serveur Node les lit dans process.env. Le backend de Magpie accepte en plus un fichier .env, et garde un défaut dans le code : trois sources, donc une règle de priorité.

Le fichier d'exemple

.env.example est versionné, .env ne l'est pas (.gitignore:380–382). L'exemple documente chaque réglage, sa valeur par défaut et son rôle, sans aucune valeur secrète : c'est le mode d'emploi du vrai fichier.

Toujours du texte

Une variable d'environnement est une chaîne, ou rien : PORT=80 donne "80", une absence donne undefined (mesuré). Tout nombre, booléen ou liste doit être converti, et la conversion peut échouer.

Piège courant Commiter un .env rempli « juste pour tester ». Même supprimé au commit suivant, il reste dans l'historique git et sur GitHub. Un secret publié se considère comme perdu : on le change, on ne se contente pas d'effacer le fichier.

Schéma 2 · Valider au démarrage

Une faute de frappe doit faire du bruit

Une valeur de configuration est une entrée comme une autre, écrite à la main par quelqu'un, parfois des mois après. Le moment le moins cher pour découvrir qu'elle est fausse, c'est le démarrage : avant le premier utilisateur, devant la personne qui vient de la taper.

Exemple autonome · JavaScript, lire un entier ou refuser de démarrerfunction entier(nom, defaut) { const brut = process.env[nom]; if (brut === undefined || brut === "") return defaut; const n = Number(brut); if (!Number.isInteger(n) || n < 0) throw new Error(`${nom} invalide : "${brut}"`); return n; }

Échouer tôt

Un serveur qui refuse de démarrer avec un message clair est un incident de cinq minutes. Un serveur qui démarre avec un délai inattendu ou une origine mal recopiée est un bug intermittent qu'on cherchera des jours.

Afficher ce qui est retenu

Au démarrage, le backend de Magpie écrit l'adresse de Compute et le délai effectivement retenus (compute-proxy.mjs:740). C'est la moitié du travail : on voit la valeur réelle, même si on n'est pas averti qu'une saisie a été écartée.

Piège courant Un défaut permissif : « sans mot de passe réglé, l'administration est ouverte ». Le jour où la variable est oubliée, la porte l'est aussi. Magpie fait l'inverse : sans MAGPIE_ADMIN_PASSWORD, l'administration est fermée (compute-proxy.mjs:71–73).

Schéma 3 · Les réglages du poste et du document

Ranger le réglage là où il ne se perdra pas

Un plugin n'a pas de variables d'environnement à lui. Ses réglages vivent soit avec le document, s'ils le concernent, soit dans le profil de l'utilisateur, s'ils concernent son poste. Le choix se décide en se demandant ce qui doit se passer quand on copie le fichier sur une autre machine.

magpie/plugin/Core/MagpieReglages.cs · lignes 22 et 38 à 39private static GH_SettingsServer Serveur => _serveur ??= new GH_SettingsServer("Magpie"); string regle = Serveur.GetValue(CleDossier, string.Empty); return !string.IsNullOrWhiteSpace(regle) && Directory.Exists(regle) ? regle : DossierParDefaut;

Pourquoi pas dans le dossier lui-même

Le commentaire de MagpieReglages.cs:12–15 le dit : un fichier de réglages rangé dans le dossier de travail serait introuvable dès qu'on déplace ce dossier. Le réglage qui désigne un lieu ne peut pas habiter ce lieu.

Relatif ou absolu

SnapSet stocke le dossier cible relatif au .gh (CheminCible.cs:35–36) : on peut déplacer ensemble le .gh et son projet, ou les cloner sur un autre poste. Un chemin absolu, lui, ne vaut que sur la machine qui l'a écrit (cours 68).

Piège courant Recréer en silence un dossier réglé qui a disparu. Si le disque externe est débranché, le travail s'écrit alors dans un nouveau dossier vide, à côté de l'ancien, et l'auteur croit l'avoir perdu. MagpieReglages.cs:30–32 revient plutôt au dossier par défaut, et sait dire pourquoi (ligne 45).

Glossaire

Variable d'environnement
Un couple nom-texte transmis à un processus par celui qui le lance.
Fichier .env
Un fichier de variables lu au démarrage, gardé hors du dépôt.
Défaut sûr
La valeur qui, en l'absence de réglage, ferme plutôt qu'elle n'ouvre.
Échouer tôt
Refuser de démarrer sur une configuration fausse, avec un message clair.
Portée
Ce que concerne un réglage : un document, un poste ou un serveur.
