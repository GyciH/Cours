Le concept

Tests d'instantané

Certaines sorties sont trop longues pour qu'on écrive à la main ce qu'on attend : un fichier .ghx, du code C# généré, un rapport. Le test d'instantané (snapshot) enregistre la sortie une fois, la fait relire, puis vérifie à chaque lancement qu'elle n'a pas bougé. Tout changement devient un diff à lire.

45 min de lecture et de QCM Prérequis · 109, 113 Exemples · Magpie web, SnapSet

L'idée en une phrase

On ne décrit pas la bonne sortie, on la montre une fois ; ensuite, le test signale toute différence, et c'est à nous de dire si elle est voulue.

L'analogie

Le plan tamponné « bon pour exécution ». On ne revérifie pas chaque cote à chaque tirage : on compare le nouveau tirage au plan validé, et toute différence passe par un nouvel indice de révision.

À la fin, tu sais

  1. écrire un instantané avec node:test ;
  2. neutraliser ce qui varie ;
  3. relire un diff d'instantané ;
  4. voir un fichier généré comme un instantané.
À retenir Un instantané ne sait pas si la sortie est juste ; il sait seulement qu'elle a changé. Il complète les assertions précises, il ne les remplace pas : SnapSet garde ses 495 Assert.Contains, qui disent chacun ce qui compte.

Schéma 1 · Ce qui varie

Un instantané doit être stable

Un instantané compare tout, octet par octet. Si la sortie contient une date, un GUID tiré au hasard ou un chemin de la machine, elle change à chaque lancement et le test échoue toujours : c'est un test instable par construction (cours 113).

Exemple autonome · node:test, un instantané stabletest("un Panel seul, sérialisé", (t) => { const texte = xml().replace(/(InstanceGuid"[^>]*>)[0-9a-f-]{36}/g, "$1<guid>"); t.assert.snapshot(texte.split("\n")); // une entrée par ligne }); // node --test --experimental-test-snapshots

Masquer ou fixer

Deux parades : remplacer la valeur variable par un repère (ici <guid>), ou la fixer à la source, comme le GuidFixe de SnapSet (cours 113). La seconde est meilleure quand le code le permet.

Une ligne par entrée

Sans le split, l'instantané est une seule chaîne de 2 187 caractères : le diff montre deux lignes géantes, illisibles. Découpé, il montre les deux lignes qui ont changé.

Piège courant Masquer trop large. Une expression qui remplace tous les GUID cache aussi celui du type de composant, qui, lui, ne doit jamais changer. On ne masque que la valeur qui varie, à son emplacement précis.

Schéma 2 · Relire le diff

Défaut, ou changement voulu ?

Quand l'instantané rougit, la question n'est pas « comment le faire passer », mais « cette différence est-elle celle que je voulais ». Le diff montre tout ce que le changement a touché, y compris ce qu'on n'avait pas prévu.

Exemple autonome · accepter un changement relunode --test --experimental-test-snapshots --test-update-snapshots \ test/serialisation.test.mjs git diff test/serialisation.test.mjs.snapshot # relire ce qui a été accepté git add test/serialisation.test.mjs.snapshot src/serializer/build-graph.mjs

Le diff dans le commit

Le fichier .snapshot est versionné avec le code. Dans la pull request, le relecteur voit le changement de code et son effet sur la sortie, côte à côte.

En .NET

La bibliothèque Verify (Verify.Xunit) fait de même : un fichier .verified.txt versionné, un .received.txt écrit en cas de différence, et un outil de comparaison pour accepter.

Piège courant Relancer avec --test-update-snapshots dès qu'un instantané rougit. Le test repasse, le défaut est entré dans la référence, et le test le protège désormais. On met à jour après avoir lu, jamais pour faire passer.

Schéma 3 · Le fichier généré versionné

Un instantané qui ne dit pas son nom

SnapSet produit deux fichiers C# à partir de son schéma JSON, par un script Node, et les versionne. Chaque changement du schéma apparaît donc deux fois dans un commit : dans le JSON, et dans le code généré. C'est le principe de l'instantané, appliqué par Git.

Exemple autonome · C#, compléter LotATests en vrai test d'instantanéforeach (var kv in g) // g : les deux fichiers régénérés dans une copie Assert.Equal(File.ReadAllText(Path.Combine(Racine, "schema", kv.Key)), kv.Value); // échoue si quelqu'un a changé ghstyle.schema.json sans relancer le générateur

Le marqueur « .g.cs »

Le suffixe annonce un fichier régénéré, qu'on ne modifie jamais à la main. La décision 2 de SnapSet fait la même distinction pour le code émis : Xxx.Dessin.g.cs régénéré, Xxx.cs jamais écrasé.

Comment c'est mesuré

Sur un clone, pour chacun des 12 commits qui touchent au schéma ou aux fichiers générés : sortie du commit, générateur relancé dans un dossier à part, comparaison ligne à ligne.

Piège courant Corriger à la main un fichier généré. La correction disparaît à la prochaine génération, souvent des semaines plus tard, et le défaut revient sans qu'aucun commit récent ne l'explique.

Glossaire

Instantané (snapshot)
Une sortie enregistrée, relue, qui sert de référence.
Fichier de référence
Le fichier versionné auquel on compare (golden file).
Masquage
Le remplacement d'une valeur variable par un repère fixe.
Fichier généré
Un fichier produit par un script, régénéré, jamais édité.
Mise à jour
L'acceptation volontaire d'une nouvelle référence.
