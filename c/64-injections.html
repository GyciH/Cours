Le concept

Les injections

Une injection se produit quand une donnée venue de l'extérieur est collée dans un texte qui sera interprété : une requête SQL, une page HTML, un chemin de fichier, un document XML. Si la donnée contient la syntaxe de ce langage, elle cesse d'être une donnée et devient une instruction.

50 min de lecture et de QCM Prérequis · 34 et 57 Exemples · compute-proxy.mjs, xml-builder.mjs, ImportParcours (Magpie)

L'idée en une phrase

On ne fabrique jamais du code par concaténation avec une donnée étrangère : on la passe à part (paramètre), ou à défaut on l'échappe pour le langage précis qui va la lire.

L'analogie

Un formulaire de virement où l'on écrirait le montant en toutes lettres dans la phrase « Je verse … euros à Paul ». Quelqu'un écrit « 10 euros à Paul, et 1000 euros à Marc, et 0 ». Un formulaire à cases séparées rend la ruse impossible.

À la fin, tu sais

  1. reconnaître une injection SQL ;
  2. écrire une requête paramétrée ;
  3. échapper selon le contexte ;
  4. bloquer une traversée de chemin.
À retenir Toute donnée qui franchit une frontière (formulaire, URL, fichier importé, corps de requête) est suspecte jusqu'à preuve du contraire. La question à se poser à chaque collage : « quel programme va lire ce texte, et que se passe-t-il si la donnée contient sa syntaxe ? »

Schéma 1 · L'injection SQL

Séparer le texte et les valeurs

Une requête préparée envoie à la base deux choses distinctes : un texte fixe avec des ?, puis les valeurs. Le texte est analysé seul ; les valeurs ne passent jamais par l'analyseur SQL et ne peuvent donc rien y ajouter.

Exemple autonome · Node et C#db.prepare("SELECT * FROM exercises WHERE id = ?").get(id); // better-sqlite3 db.prepare("UPDATE t SET a = ?, b = ? WHERE id = ?").run(a, b, id); cmd.CommandText = "SELECT * FROM exercises WHERE id = @id"; // ADO.NET cmd.Parameters.AddWithValue("@id", id); // JAMAIS : `SELECT * FROM exercises WHERE id = '${id}'`

Ce qui ne peut pas être un paramètre

Un nom de table ou de colonne, un sens de tri. Si l'utilisateur doit le choisir, on prend la valeur dans une liste blanche écrite dans le code : tri === "asc" ? "ASC" : "DESC".

Pourquoi c'est aussi plus rapide

Une requête préparée une fois peut être exécutée mille fois avec d'autres valeurs : la base ne la ré-analyse pas. C'est ce que fait la migration de db.mjs dans sa boucle de réinsertion.

Piège courant « Nettoyer » soi-même en retirant les apostrophes. On oublie toujours un cas (un autre guillemet, un encodage, un commentaire --), et on abîme les données légitimes, comme « l'arc » ou « O'Neil ». Le paramètre règle tout, sans rien retirer.

Schéma 2 · Échapper selon le contexte

Chaque langage a ses caractères dangereux

Quand le paramètre n'existe pas (une page HTML, un fichier XML, une URL), on échappe : on remplace chaque caractère qui a un sens dans ce langage par sa forme neutre. Il n'y a pas d'échappement universel : le bon dépend de qui lira le texte.

Exemple autonome · JavaScript et C#<p>{titre}</p> // React échappe : affiché tel quel el.textContent = titre; // DOM : texte, jamais interprété el.innerHTML = titre; // DANGER : interprété comme HTML WebUtility.HtmlEncode(titre) // C# new XElement("item", titre) // C# : LINQ to XML échappe pour toi

Le XSS

L'injection dans une page web s'appelle XSS : un titre d'exercice contenant <script> s'exécuterait chez chaque élève qui l'affiche. React échappe tout texte placé entre accolades ; le front de Magpie n'utilise jamais dangerouslySetInnerHTML.

Les bibliothèques le font

JSON.stringify, XElement, encodeURIComponent : chacune échappe pour son format. Écrire son propre échappement n'a de sens que pour un format sans bibliothèque, comme l'archive XML de Grasshopper.

Piège courant Échapper deux fois, ou pour le mauvais contexte. Une chaîne échappée pour HTML puis passée à React s'affiche avec des &amp; visibles. On garde la donnée brute aussi longtemps que possible et on échappe une seule fois, au dernier moment.

Schéma 3 · La traversée de chemin

Rester dans son dossier

Un serveur de fichiers colle le chemin demandé à son dossier racine. Avec des .., le chemin peut remonter et sortir de ce dossier : vers la base de données, les variables de configuration, n'importe quel fichier lisible. La parade : résoudre le chemin, puis vérifier qu'il commence bien par le dossier.

Exemple autonome · C#string racine = Path.GetFullPath(dossier) + Path.DirectorySeparatorChar; string cible = Path.GetFullPath(Path.Combine(racine, demande)); // résout les ".." if (!cible.StartsWith(racine, StringComparison.OrdinalIgnoreCase)) // Windows : casse ignorée throw new UnauthorizedAccessException();

Le séparateur final compte

Sans lui, …/dist accepterait aussi …/dist-secret/, qui commence par les mêmes lettres. Magpie compare donc avec DIST_DIR + sep, plus le cas du dossier lui-même.

Le « zip slip »

Une archive peut contenir une entrée nommée ../../Rhino/plugin.dll. Décompressée naïvement, elle écrit hors du dossier prévu. Même parade, appliquée à chaque entrée de l'archive.

Piège courant Chercher la chaîne ".." dans la demande pour la refuser. Les encodages (%2e%2e), les antislashs Windows et les chemins absolus passent à côté. On ne filtre pas la demande : on vérifie le résultat une fois résolu.

Glossaire

Injection
Une donnée insérée dans un texte interprété, qui en modifie le sens.
Requête paramétrée
Une requête au texte fixe dont les valeurs sont transmises à part.
Échappement
Remplacer les caractères spéciaux d'un langage par leur forme neutre.
XSS
Une injection de HTML ou de script dans une page affichée à d'autres.
Traversée de chemin
Sortir du dossier prévu avec des « .. » dans un chemin demandé.
