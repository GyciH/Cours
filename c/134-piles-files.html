Le concept

Piles et files

Beaucoup d'algorithmes ont la même boucle : prendre un élément à traiter, en découvrir d'autres, les mettre de côté. Tout se joue dans « de côté ». Une pile reprend le dernier rangé, une file le premier. La boucle est identique ; le parcours, le résultat et la mémoire ne le sont pas.

45 min de lecture et de QCM Prérequis · 18, 133 Exemples · Cuttlefish, SnapSet

L'idée en une phrase

Une pile sert à revenir en arrière, une file à avancer dans l'ordre ; et une pile explicite remplace sans risque une récursion trop profonde.

L'analogie

Une pile d'assiettes : on prend celle du dessus. Une file au guichet : on sert celui qui attend depuis le plus longtemps.

À la fin, tu sais

  1. choisir pile ou file ;
  2. dérécursiver un parcours ;
  3. lire une file circulaire ;
  4. garder l'ordre en empilant.
À retenir Pour le chemin le plus court, une file. Pour explorer à fond ou revenir sur ses pas, une pile. Pour une profondeur qu'on ne maîtrise pas, une pile à soi plutôt que la pile d'appels.

Schéma 1 · La pile d'appels

La récursion a une limite, la Stack non

Chaque appel de fonction ajoute un étage sur la pile d'appels du fil. Cette pile a une taille fixe. On a cherché, par dichotomie, à quelle profondeur elle cède.

Exemple autonome · C#, la même exploration sans récursionvar pile = new Stack<Case>(); pile.Push(depart); while (pile.Count > 0) { var c = pile.Pop(); foreach (var v in VoisinsLibres(c)) { Marquer(v); pile.Push(v); } // marquer à l'entrée }

Pourquoi on ne rattrape rien

Quand la pile d'appels déborde, il n'y a plus de place pour exécuter le moindre catch. .NET arrête le processus entier : dans Rhino, c'est Rhino qui se ferme.

Marquer à l'entrée

Marquer une case quand on l'empile, pas quand on la sort, évite de l'empiler plusieurs fois. Sinon la pile peut contenir bien plus que le nombre de cases.

Piège courant Écrire un parcours récursif d'une grille ou d'un graphe fourni par l'utilisateur. Sur une petite grille, tout va bien ; à 33 000 cases en enfilade, le programme disparaît sans message (mesuré).

Schéma 2 · La file circulaire

Deux index qui tournent

Retirer en tête d'une List décale tout (cours 133). Queue<T> évite le décalage : elle garde deux index, la tête et la queue, qui font le tour de son tableau.

Exemple autonome · C#, un parcours en largeur qui mesure les distancesvar d = new int[n]; Array.Fill(d, -1); d[depart] = 0; var file = new Queue<int>(); file.Enqueue(depart); while (file.Count > 0) { int c = file.Dequeue(); foreach (int v in Voisins(c)) if (d[v] < 0) { d[v] = d[c] + 1; file.Enqueue(v); } }

Par vagues

La file sort toutes les cases à distance 1, puis toutes celles à distance 2, et ainsi de suite. La première fois qu'on atteint une case, c'est par le chemin le plus court.

Ce que dit le tableau

Dans le premier état, la tête et la queue sont toutes deux à 2 : le tableau est plein, et le contenu se lit de la tête, en faisant le tour, 2, 3, 4, 5.

Piège courant Prendre une List et RemoveAt(0) comme file d'attente. À 100 000 éléments, la vider ainsi a pris des secondes ; Dequeue, moins d'une milliseconde (mesuré au cours 133).

Schéma 3 · Même boucle, autre forme

Ce que la structure décide à ta place

On a gardé la même boucle et changé seulement l'endroit où l'on reprend : chercher un chemin, creuser un labyrinthe, parcourir un arbre.

Exemple autonome · C#, garder l'ordre d'origine avec une pileforeach (var enfant in Enfants(noeud).Reverse()) pile.Push(enfant); // le premier sortira en premier

Le goût d'un labyrinthe

Le parcours en profondeur de Maze avance jusqu'à buter : il trace de longs couloirs. C'est un choix esthétique autant qu'algorithmique, et il tient à une Stack.

Pile et ordre

Une pile rend ses éléments à l'envers de leur arrivée. Pour sortir les enfants dans l'ordre du dessin, on les empile du dernier au premier.

Piège courant Chercher le plus court chemin en profondeur. Le parcours trouve bien un chemin, mais sur une grille ouverte il en a pris un de 4 950 pas au lieu de 198 (mesuré).

Glossaire

Pile
Une structure où l'on reprend toujours le dernier élément rangé.
File
Une structure où l'on reprend toujours le plus ancien.
Pile d'appels
La zone où chaque appel de fonction range ses variables ; sa taille est fixe.
Parcours en largeur
Une exploration par distances croissantes, menée avec une file.
Tampon circulaire
Un tableau dont les index de début et de fin font le tour.
