Le concept

Asynchrone : async, await, Task et Promise

Une requête réseau prend des centaines de millisecondes, parfois des secondes. Si le thread de l'interface l'attend, tout se fige. Avec async et await, la fonction rend la main pendant l'attente et reprend quand la réponse arrive, sans un thread de plus.

55 min de lecture et de QCM Prérequis · 21 et 31 Exemples · api.js, App.jsx, compute-proxy.mjs (Magpie), CapsuleExecution (SnapSet)

L'idée en une phrase

Une fonction async se découpe aux await : la partie avant s'exécute, la fonction rend une promesse de résultat (Promise en JS, Task en C#), et la suite est rangée dans la file pour plus tard.

L'analogie

Commander au comptoir d'une boulangerie qui donne un bipeur. On ne reste pas planté devant le four : on va s'asseoir, on lit, on répond à un message. Le bipeur sonne, on revient chercher la commande. Un seul client, aucune attente gaspillée.

À la fin, tu sais

  1. dire ce qui se passe à chaque await ;
  2. attraper une erreur et borner une attente ;
  3. lancer deux attentes ensemble ;
  4. éviter le double envoi et l'interblocage.
À retenir Asynchrone ne veut pas dire parallèle. await sert à attendre sans bloquer (réseau, disque, minuteur). Un calcul lourd, lui, occupe le processeur : il faut un autre thread (Task.Run, un Worker), et les objets de l'interface ne se touchent que depuis le thread de l'interface.

Schéma 1 · Ce que fait await

Une fonction en plusieurs morceaux

Le compilateur (C#) ou le moteur (JS) transforme la fonction en une suite d'étapes. Chaque await est une couture : on enregistre où on en est, on rend la main, et on reprendra au même endroit, avec les mêmes variables locales.

Exemple autonome · C#async Task<string> LireAsync(string chemin) { string texte = await File.ReadAllTextAsync(chemin); // rend la main ici return texte.Trim(); // reprend ici, plus tard } Task<string> tache = LireAsync("notes.txt"); // déjà rendue, pas encore finie string resultat = await tache; // .NET Core 2 et suivants pour ReadAllTextAsync

La boucle d'événements

JavaScript n'a qu'un thread. Il prend un travail dans la file (un clic, un minuteur, une réponse réseau), l'exécute jusqu'au bout ou jusqu'au prochain await, puis prend le suivant. Deux morceaux ne s'exécutent jamais en même temps.

Contagieux, et c'est voulu

Pour attendre une fonction async, il faut être soi-même async. La couleur remonte la pile jusqu'au gestionnaire d'événement. En C#, ce gestionnaire est le seul endroit où async void est acceptable.

Piège courant Oublier await. if (verifier()) avec verifier asynchrone teste une Promise, toujours vraie, et non sa réponse. En C#, le compilateur avertit (CS4014) ; en JS, rien ne prévient. Le symptôme : un test qui passe toujours.

Schéma 2 · Erreurs et délais

Toute attente doit pouvoir finir

Une erreur pendant l'attente ressort à l'endroit du await : try, catch et finally marchent comme d'habitude. Un serveur qui ne répond jamais, en revanche, ne lève rien. Il faut un minuteur qui annule la requête.

Exemple autonome · JavaScript et C#const ctrl = new AbortController(); const minuteur = setTimeout(() => ctrl.abort(), 5000); try { const r = await fetch(url, { signal: ctrl.signal }); } catch (err) { if (err.name === "AbortError") { /* trop long */ } } finally { clearTimeout(minuteur); } using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5)); // C# : même idée var reponse = await client.GetAsync(url, cts.Token);

Distinguer les échecs

Délai dépassé, serveur injoignable, réponse illisible, refus métier : quatre causes, quatre messages. L'utilisateur sait alors s'il doit réessayer, attendre ou corriger sa saisie.

Le jeton d'annulation

En C#, on passe un CancellationToken à chaque méthode qui attend. Le même jeton peut venir d'un minuteur ou d'un bouton « Annuler » : l'appelé n'a pas à savoir pourquoi on arrête.

Piège courant Bloquer sur une tâche avec .Result ou .Wait() depuis le thread WinForms. La suite de la tâche attend ce thread pour reprendre ; le thread attend la tâche : interblocage, Rhino gelé. On attend avec await, jusqu'en haut.

Schéma 3 · L'une après l'autre ou ensemble

Lancer d'abord, attendre ensuite

Un appel async démarre dès qu'on l'appelle ; await ne fait qu'attendre sa fin. Deux attentes indépendantes peuvent donc se chevaucher : on lance les deux, puis on attend les deux.

Exemple autonome · JavaScript et C#const a = await lire("a"); const b = await lire("b"); // l'une après l'autre const [x, y] = await Promise.all([lire("a"), lire("b")]); // ensemble const tous = await Promise.allSettled([lire("a"), lire("b")]); // même si l'une échoue string[] r = await Task.WhenAll(LireAsync("a"), LireAsync("b")); // C# double d = await Task.Run(() => CalculLourd()); // C# : un calcul, sur un autre thread

Attendre ou calculer

Une requête réseau ne consomme rien pendant l'attente. Un maillage de cent mille faces, si : await seul ne l'accélère pas. Task.Run l'envoie sur un autre thread, et l'interface reste fluide.

Revenir au thread de l'interface

Un contrôle WinForms ou le canvas Grasshopper ne se touchent que depuis leur thread. Depuis ailleurs, on passe par Invoke (attendre) ou BeginInvoke (mettre en file).

Piège courant Promise.all échoue dès que une promesse échoue, et les autres résultats sont perdus pour l'appelant. Quand chaque réponse compte séparément, Promise.allSettled rend un état par promesse : réussie avec sa valeur, ou échouée avec sa raison.

Glossaire

Asynchrone
Qui rend la main pendant une attente et reprend quand le résultat est là.
Promise / Task
Un objet qui représente un résultat à venir, ou l'erreur qui l'a empêché.
Boucle d'événements
Le thread unique qui prend les travaux de la file un par un.
Interblocage
Deux attentes qui dépendent l'une de l'autre : aucune ne finit jamais.
Anti-rebond
Attendre un temps de calme avant d'agir, en annulant les déclenchements rapprochés.
