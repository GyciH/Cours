Le concept

La couverture

Pendant que les tests tournent, l'outil note chaque ligne et chaque branche du programme qui s'exécute. Le pourcentage obtenu, la couverture, est le chiffre le plus cité sur les tests et l'un des plus mal lus. Ce cours le mesure sur Magpie, puis regarde ce qu'il cache.

45 min de lecture et de QCM Prérequis · 109 Exemples · Magpie web, SnapSet

L'idée en une phrase

La couverture montre le code que les tests n'ont jamais traversé ; elle ne prouve pas que le code traversé a été vérifié.

L'analogie

Le relevé GPS d'un gardien de nuit. Il dit quelles allées ont été parcourues, pas si les portes ont été essayées. Une allée jamais parcourue est sûrement mal gardée ; une allée parcourue ne l'est pas forcément bien.

À la fin, tu sais

  1. lire un rapport de couverture ;
  2. distinguer lignes et branches ;
  3. vérifier le dénominateur ;
  4. rendre la logique testable.
À retenir Une couverture basse est une information sûre : ce code n'est pas testé. Une couverture haute n'est qu'un indice. On s'en sert pour trouver les trous, jamais comme objectif à atteindre.

Schéma 1 · Le dénominateur

88 % de quoi ?

Le rapport de Node ne connaît que les fichiers que les tests ont chargés. Un fichier jamais importé n'y figure pas du tout, ni à 0 %, ni ailleurs. Et par défaut, il compte aussi les fichiers de test, qui s'exécutent évidemment à 100 %.

Exemple autonome · Node 22, un rapport utilisablenode --test --experimental-test-coverage \ --test-coverage-exclude="test/**" \ --test-reporter=lcov --test-reporter-destination=lcov.info "test/*.test.mjs" # puis comparer la liste des fichiers du rapport à celle du dépôt

Le format lcov

Une ligne SF: par fichier, LF: lignes trouvées, LH: lignes passées. C'est le format que lisent les éditeurs pour colorer les lignes, et celui qui a servi aux comptes de cette page.

Inclure les absents

c8 ou nyc avec --all, Coverlet en .NET : ces outils listent aussi les fichiers jamais chargés, à 0 %. Sans cette option, le chiffre ne parle que du code que les tests connaissent déjà.

Piège courant Annoncer le chiffre « all files » du rapport. Ici, 88,7 % décrit 14 fichiers sur plus de 50, dont 6 sont les tests eux-mêmes. Rapporté à tout le code web, la même mesure donne 14,4 %.

Schéma 2 · Lignes, branches, mutants

Exécuté n'est pas vérifié

Trois mesures du même fichier, de la plus indulgente à la plus exigeante. La couverture de lignes compte les lignes traversées ; celle des branches, les chemins pris à chaque décision ; le score de mutation, les défauts que les tests remarquent (cours 109).

Exemple autonome · JavaScript, une ligne couverte, deux branches, un seul chemin prisfunction verdict(x, tol) { return Math.abs(x) > tol ? "refusé" : "accepté"; // ligne couverte à 100 % } test("refuse", () => assert.equal(verdict(5, 1), "refusé")); // « accepté » jamais essayé

Le ternaire et le &&

Une ligne peut contenir plusieurs branches (un ? :, un &&, un ??). La couverture de lignes la voit entière dès qu'elle commence ; celle des branches voit le chemin oublié.

Un tableau de bord, pas une note

Les lignes non couvertes du rapport (49–50, 67–68, 89–90…) sont une liste de travail : chaque plage est un cas qu'aucun test ne pose. C'est leur usage le plus utile.

Piège courant Imposer un seuil (« 80 % minimum ») comme règle de fusion. Le plus rapide pour l'atteindre est d'exécuter du code sans rien vérifier : la couverture monte, la protection non. Le seuil se surveille, il ne se vise pas.

Schéma 3 · L'objet humble

Rendre la logique testable

Le code qui touche à une interface ou à un logiciel hôte (Grasshopper, le navigateur) est difficile à exécuter dans un test. La parade est d'en sortir la logique dans une classe pure, et de laisser une enveloppe si mince qu'elle ne peut presque pas se tromper : l'objet humble.

Exemple autonome · C#, l'enveloppe humble et le modèle pursealed class Voyant { void Peindre(Graphics g) => Peintre.Dessiner(g, _modele.Etat()); } sealed class ModeleVoyant { public EtatVoyant Etat() { /* toute la logique */ } } [Fact] public void EteintSansValeur() => Assert.Equal(EtatVoyant.Eteint, new ModeleVoyant().Etat());

Lier plutôt que copier

Le projet de test de SnapSet compile les fichiers purs par lien (chemins relatifs), jamais par copie : le test lit exactement le code livré. Les 30 liens sont listés dans ResolutionTests.csproj.

Et l'enveloppe ?

Le code émis qui la nomme est compilé contre les vrais Grasshopper.dll par CoupleCompileTests (15 tests). On vérifie qu'elle compile ; son comportement se voit dans Rhino.

Piège courant Laisser la logique grossir dans l'enveloppe « parce que c'est plus simple ». Chaque règle ajoutée là échappe aux tests ; au bout de quelques mois, la classe pure ne contient plus que des accesseurs.

Glossaire

Couverture
La part du code exécutée pendant les tests.
Branche
Un des chemins possibles à une décision (if, ? :, &&, ??).
Dénominateur
L'ensemble de code auquel on rapporte les lignes passées.
Objet humble
Une enveloppe minimale autour d'une logique sortie pour être testée.
lcov
Un format texte de rapport de couverture, ligne par ligne.
