Le concept

Allocations et ramasse-miettes

En .NET, créer un objet ne coûte presque rien ; c'est le ménage qui coûte. Chaque objet abandonné devra être repéré par le ramasse-miettes, qui interrompt le programme pour le faire. Dans une boucle chaude, une peinture de canvas ou un calcul répété, réduire les allocations réduit ces pauses. Le cours 58 a posé la pile et le tas ; celui-ci mesure ce qu'ils coûtent.

45 min de lecture et de QCM Prérequis · 58 et 91 Exemples · Metrique.cs, ModeleFeuilles.cs, CapsuleExecution.cs (SnapSet)

L'idée en une phrase

Moins d'objets jetables dans les chemins chauds, c'est moins de ramassages, donc moins de saccades.

L'analogie

Des gobelets jetables au bureau : en prendre un est instantané, mais quelqu'un doit vider la poubelle, et pendant ce temps la machine à café est fermée.

À la fin, tu sais

  1. mesurer les octets alloués ;
  2. choisir entre struct et classe ;
  3. construire une chaîne sans gaspiller ;
  4. repérer les allocations cachées.
À retenir GC.GetAllocatedBytesForCurrentThread() donne le total des octets alloués par le fil courant. Lu avant et après un bloc, il en mesure exactement les allocations. Toutes les valeurs en octets de ce cours viennent de là.

Schéma 1 · Valeur ou référence

Struct ou classe

Une classe vit sur le tas, avec un en-tête, et on la manipule par référence. Une struct est une valeur : rangée dans un tableau, elle s'y trouve directement, sans en-tête et sans objet séparé. Pour de petites données nombreuses, l'écart est net.

SnapSet/schema/Metrique.cs · lignes 1168 à 1172 et 1182 à 1185 (extrait)/// UNE STRUCTURE, ET SANS AUCUN CHAMP OBLIGATOIRE : la valeur par défaut du type — /// quatre zéros — est exactement ce que le schéma dit d'un espacement dont un côté /// manque. Aucun test de nullité à faire nulle part, donc aucun oubli possible. public readonly struct Espacement … public float Haut { get; } public float Droite { get; } public float Bas { get; } public float Gauche { get; }

Quand choisir une struct

Petite (Espacement : quatre float, 16 octets), immuable, sans identité propre : deux espacements égaux sont interchangeables. Au-delà de quelques dizaines d'octets, chaque copie coûte plus que la référence qu'on évite.

Pourquoi readonly

Une struct modifiable surprend : liste[i].X = 3 ne compile pas, parce que liste[i] rend une copie. readonly struct interdit toute modification après construction et permet au compilateur d'éviter des copies de précaution.

Piège courant Ranger des valeurs dans un object, une List<object> ou un ArrayList. Chaque entier y est emballé dans un objet (boxing) : 32 Mo au lieu de 4 pour un million d'entiers, dans la mesure ci-dessus.

Schéma 2 · Les chaînes

Une chaîne ne se modifie pas

Une string .NET est immuable : s += "x" crée une nouvelle chaîne et recopie l'ancienne. Dans une boucle, le coût devient quadratique. Le StringBuilder écrit dans un tampon modifiable et ne crée la chaîne qu'à la fin.

La capacité connue

UneLigne remplace les sauts de ligne par des espaces : le résultat a au plus la longueur de l'entrée. Annoncer texte.Length évite au tampon de grandir par doublements. Le même réflexe se retrouve aux lignes 683 et 705.

Le chemin court

La ligne 97 rend string.Empty sans rien allouer quand il n'y a rien à faire. Traiter d'abord le cas trivial, sans objet, est l'optimisation la plus simple et la plus fréquente des fonctions de texte.

Piège courant Remplacer chaque concaténation par un StringBuilder. Pour assembler trois morceaux une fois, a + b + c est compilé en un seul appel et reste le plus simple. Le StringBuilder ne sert que dans une boucle.

Schéma 3 · Les allocations cachées

Allouer sans écrire new

Beaucoup d'allocations ne se voient pas dans le code : une collection parcourue à travers une interface, une requête LINQ, une chaîne interpolée. Chacune est minuscule ; répétée à chaque image ou pour chaque élément, elle remplit la génération 0.

SnapSet/src/SnapSet.Constituants/Execution/CapsuleExecution.cs · lignes 108 et 222private IReadOnlyDictionary<object, RectangleF> _boites = new Dictionary<object, RectangleF>(); … foreach (var paire in _boites)

L'énumérateur emballé

Le Dictionary fournit un énumérateur qui est une struct : parcouru directement, il ne coûte rien. Parcouru à travers IReadOnlyDictionary, il doit devenir un IEnumerator, donc un objet : 64 octets mesurés, à chaque foreach.

Sur la pile

stackalloc réserve un petit tableau sur la pile, rendu automatiquement à la sortie de la méthode ; Span<T> le manipule sans copie. ArrayPool<T>.Shared prête de grands tableaux et les reprend. Les trois évitent le tas.

Piège courant Chasser les allocations partout. Une requête LINQ de 104 octets dans une méthode appelée une fois par clic est sans effet ; elle se paie seulement dans une boucle chaude. Le cours 91 s'applique : mesurer avant de réécrire.

Glossaire

Allocation
La réservation de mémoire sur le tas pour un nouvel objet.
Génération
Une classe d'âge des objets, ramassée plus ou moins souvent.
Boxing
L'emballage d'une valeur dans un objet du tas.
Struct
Un type valeur, copié et rangé sans en-tête.
Span<T>
Une vue sur une zone de mémoire contiguë, sans copie.
