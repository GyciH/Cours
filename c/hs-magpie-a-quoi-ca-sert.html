Le concept

Magpie, la formation
qui se corrige seule

Un formateur écrit des exercices Grasshopper et les range en parcours. L'apprenant répond en construisant un graphe. Magpie calcule ce graphe, compare le résultat à l'attendu et délivre un certificat en fin de parcours, sans correcteur humain.

45 min de lecture et de QCM Prérequis · aucun, le cours 07 aide Sources · README, feuille de route, 26 issues, état au 23/10/2026

L'idée en une phrase

Magpie automatise ce que fait un formateur Grasshopper penché sur l'écran d'un élève : regarder ce que produit le graphe, pas la façon dont il est câblé, et dire si c'est juste.

L'analogie

Un examen de code de la route sur tablette. Les questions sont fixées à l'avance, la correction est automatique, le résultat n'apparaît qu'à la fin, et le certificat porte un numéro que n'importe qui peut vérifier.

À la fin, tu sais

  1. dire à quoi sert Magpie et pour qui : auteur, apprenant, serveur ;
  2. distinguer ses deux volets, le plugin .gha et l'application web, et ce qu'ils partagent ;
  3. situer le projet sur sa feuille de route : ce qui est fait, ce qui reste avant la V1.0 de mai 2027.
À retenir Magpie ne juge jamais la méthode, seulement le résultat câblé sur le marqueur Réponse. Deux graphes différents qui donnent la même valeur sont tous les deux justes.

Schéma 1 · L'architecture

Un format d'exercice, deux volets

Le dépôt contient deux façons de vivre la même expérience. Elles partagent le même fichier d'exercice : un exercice créé d'un côté s'importe tel quel de l'autre. Le web n'est pas un portage du plugin, c'est une reconstruction qui confie le calcul à Rhino Compute.

Schéma 2 · Le trajet d'une réponse

Le corrigé ne quitte jamais le serveur

C'est le principe de conception du volet web. Le navigateur n'envoie qu'une description abstraite du graphe ; tout le reste se passe côté serveur, et seul un « réussi » ou « refusé » revient, rangé pour le bilan.

Les modes de validation

ModeCe qu'il accepte
ExactOrderedListnombres, dans cet ordre
SetEqualitymêmes valeurs, ordre libre
SingleValueune seule valeur
NumericTolerancenombres, à une marge près
GeometryTolerancegéométrie, écart max ≤ tolérance
…Text (×2)textes, ordonnés ou non
Piège courant Le mode choisi par l'auteur décide de tout. SingleValue ignore la tolérance ; SetEquality ne compte pas les doublons ; un attendu non entier impose NumericTolerance. La règle qui a coûté le plus cher au corpus : la valeur rendue doit bouger quand la compétence manque.
Et dans le plugin ? Même logique, calculée en local par le GenericChecker. Le web l'a rejoint le 21/10 : aucun verdict montré en cours de parcours.

Schéma 3 · Où va le développement

Trois jalons, et de l'avance sur le deuxième

La feuille de route (docs/magpie_chantiers.md) répartit les chantiers en trois jalons datés, chacun suivi par ses issues GitHub. Pastille verte : issue fermée ; orange : ouverte, au 23/10/2026.

Décidé, pas encore codé

Le modèle de diffusion du 22/09/2026 : un parcours de base embarqué dans le .gha, les suivants téléchargés depuis le site en paquet .mgp et importés par un composant. Grasshopper ne parle jamais au réseau : le navigateur est le seul pont. Le certificat est émis par le site, avec un numéro vérifiable.

Point de vigilance La feuille de route place le déploiement (#26) après l'authentification (#18) : publier avant exposerait le Rhino Compute de la machine de dev. Les 21-22/10, des verrous ont été posés (admin en HTTP Basic, clé d'API sur Compute, relais coupé), mais #18 reste ouverte.

Corrigé expliqué

Les réponses, et pourquoi

01 · B. Seul le résultat compte ; deux montages différents qui rendent la même valeur sont justes.
02 · C. Plugin et web s'alignent : le verdict ne sert qu'au bilan de fin de parcours.
03 · B. Le JSON est le contrat. Le code, lui, est en C# d'un côté et en JS de l'autre.
04 · A et C. Apprenant, Auteur, Serveur, Dev ; chacun autonome. Dev n'est pas diffusé.
05 · B. Le web ne réimplémente pas Grasshopper : il confie le calcul à Compute.
06 · C. Le .ghx est écrit côté serveur, ce qui garde le contrôle du contenu.
07 · B. Un ancien fichier « Mode: 0 » lit la position ; insérer au milieu la décale.
08 · C. MagpieServeur.gha est installé sur Compute, d'où le pont entre les volets.
09 · B. V0.1 est bouclée ; V0.2 a même de l'avance (#10, #22, #4, #5 fermées).
10 · A, B et C. La séparation apprenant / auteur (#7) est faite depuis le 20/10.
11 · B. Le navigateur est le seul pont : pas de jeton ni d'API dans Rhino.
12 · B. Le backend relayait vers Compute ; sans authentification, n'importe qui l'utiliserait.
