Le concept

JavaScript pour un
développeur C#

Le volet web de Magpie est écrit en JavaScript. La syntaxe te semblera familière : accolades, if, for, return. La grande différence est ailleurs : en JavaScript, ce sont les valeurs qui ont un type, pas les variables.

55 min de lecture et de QCM Prérequis · 01 C# moderne · 03 collections Exemples · web/validation.mjs (Magpie)

L'idée en une phrase

JavaScript est un langage à typage dynamique : une variable peut recevoir n'importe quelle valeur, et rien n'est vérifié avant l'exécution. Il tourne dans le navigateur, et sur un serveur grâce à Node.js.

L'analogie

En C#, chaque boîte porte une étiquette (« chaussures ») et le compilateur refuse d'y ranger autre chose. En JavaScript, les boîtes n'ont pas d'étiquette : c'est l'objet rangé dedans qui dit ce qu'il est. Plus souple, mais personne ne vérifie à ta place.

À la fin, tu sais

  1. traduire les types de C# en valeurs JavaScript ;
  2. lire objets et tableaux littéraux ;
  3. écrire une fonction fléchée et la passer en argument ;
  4. éviter les trois pièges : ==, undefined, for…in.
À retenir Sans compilateur pour attraper les fautes de frappe, une erreur de JavaScript se révèle à l'exécution, souvent loin de sa cause. D'où, dans Magpie, des tests (web/test/, cours 26) et des contrôles explicites en tête de chaque fonction.

Schéma 1 · Les valeurs et leurs types

Moins de types, et deux façons de dire « rien »

JavaScript n'a qu'un type de nombre (un double), des chaînes, des booléens, des objets. Et il distingue null (« vide, exprès ») de undefined (« jamais renseigné »).

"" : String(v))); }

Vérifier soi-même

Rien ne garantit que value soit un tableau : Array.isArray le teste. Number("abc") ne lève pas d'erreur, il rend NaN (« pas un nombre ») ; Number.isNaN le repère.

Comme LINQ, en d'autres mots

map est le Select de LINQ (cours 03), some son Any, filter son Where. value.map(Number) passe la fonction Number elle-même, sans parenthèses.

Piège courant == convertit avant de comparer : "1" == 1 est vrai, 0 == "" aussi. === compare sans conversion, comme le == de C#. Règle simple : toujours === et !==, comme partout dans validation.mjs.

Schéma 2 · Objets et tableaux littéraux

Un objet sans classe

En C#, il faut une classe pour créer un objet. En JavaScript, on l'écrit directement entre accolades : { pass: false, reason: "…" }. C'est la forme même du JSON (cours 24).

Un dictionnaire de fonctions

VALIDATORS associe un nom de mode à une fonction, comme un Dictionary<string, Func<…>>. VALIDATORS[config.Mode] lit la clé dont le nom est dans config.Mode. Deux noms peuvent pointer la même fonction.

Les mêmes raccourcis qu'en C#

config.Tolerance ?? 0 : 0 si la clé manque. config.ExpectedNumbers?.[0] : undefined au lieu d'une erreur si la liste manque. [...expected] copie un tableau (la décomposition).

Piège courant La faute de frappe silencieuse. config.mode au lieu de config.Mode ne provoque aucune erreur : la clé n'existe pas, la valeur est undefined. D'où le test if (!validator), qui transforme ce silence en un message clair.

Schéma 3 · Fonctions et variables

Des fonctions qui sont des valeurs

Une fonction se range dans une variable, se passe en argument, se renvoie. La forme fléchée (e) => Number(e) === value est l'équivalent exact d'une lambda C#.

web/validation.mjs · 62–79, condenséfunction validateSetEqualityText(submitted, config) { const expected = config.ExpectedTexts ?? []; const values = toTextArray(submitted); const remaining = [...expected]; for (const value of values) { const idx = remaining.indexOf(value); if (idx === -1) return { pass: false, reason: "Au moins un élément ne correspond à aucune valeur attendue." }; remaining.splice(idx, 1); // retire 1 élément à la position idx } return { pass: true, reason: "L'ensemble des valeurs correspond." }; }

const, let, et plus jamais var

const : la variable ne sera pas réaffectée (le tableau, lui, peut changer). let : elle le sera, comme le i d'une boucle. var est l'ancienne forme, à la portée surprenante ; Magpie ne l'emploie pas.

Les gabarits de texte

Entre accents graves, `${a} au lieu de ${b}` insère des valeurs, comme $"{a} au lieu de {b}" en C#. Les guillemets simples ou doubles, eux, n'insèrent rien.

Piège courant for…in au lieu de for…of. Sur un tableau, for (const v in ["a","b"]) parcourt les indices, sous forme de chaînes (« 0 », « 1 »). C'est for…of qui parcourt les valeurs, comme le foreach de C#.
