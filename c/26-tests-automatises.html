Le concept

Tests automatisés

Ouvrir Rhino, poser un composant, cliquer : c'est lent, et on oublie toujours un cas. Un test automatisé refait la vérification en quelques millisecondes, à chaque modification. Encore faut-il que le code à tester puisse vivre hors de Rhino.

50 min de lecture et de QCM Prérequis · 25 génération de code Exemples · ResolutionTests (SnapSet), web/test (Magpie)

L'idée en une phrase

Un test est une petite méthode qui prépare une situation, appelle le code, puis affirme ce qu'elle doit obtenir. Si l'affirmation est fausse, le test échoue et dit pourquoi.

L'analogie

Le banc d'essai d'un moteur. On ne monte pas le moteur dans la voiture pour savoir s'il tourne : on le pose sur un banc, on branche des capteurs, on lit les valeurs. Pour cela, le moteur doit pouvoir se démonter de la voiture.

À la fin, tu sais

  1. lire et écrire un test xUnit avec [Fact] et [Theory] ;
  2. expliquer comment SnapSet teste sa logique sans Grasshopper ;
  3. vérifier qu'un code émis compile, avec Roslyn ;
  4. lancer les tests du web de Magpie avec node --test.
À retenir Ce qui se teste facilement, c'est ce qui ne dépend de rien : une fonction qui reçoit des valeurs et rend un résultat. L'architecture de SnapSet (Metrique.cs, les fichiers Pur/, le générateur) est pensée pour ça.

Schéma 1 · L'anatomie d'un test xUnit

Préparer, agir, affirmer

xUnit (paquet xunit 2.9.2 dans ResolutionTests.csproj) trouve les méthodes marquées [Fact] ou [Theory] et les exécute une par une. Chaque test reçoit une instance neuve de sa classe.

EcrivainGenerationTests.cs · 45–60, condensé[Fact] public void LaPremiereGenerationCreeLesDeuxFichiers() { var d = ExemplesDessin.Correction(); // préparer var compte = EcrivainGeneration.Ecrire(d, _dossier, GuidFixe); // agir Assert.False(compte.Refuse); // affirmer Assert.Equal(SortFichier.Cree, compte.Dessin); Assert.Equal(SortFichier.Cree, compte.Code); Assert.Equal(Chemin("Correction.Dessin.g.cs"), compte.CheminDessin); }

Des entrées fixes

GuidFixe remplace Guid.NewGuid(), et ExemplesDessin fournit des dessins tout faits. Un test qui tirerait une valeur au hasard ne pourrait pas affirmer le texte exact attendu.

Assert.Equal(attendu, obtenu)

L'ordre compte pour le message : en cas d'échec, xUnit affiche « Expected » puis « Actual ». Inversés, les deux valeurs s'affichent à la mauvaise place et le diagnostic égare.

Piège courant Un test qui passe pour de mauvaises raisons. MetriqueTests choisit un bandeau non nul : avec un bandeau à 0, le calcul juste et le calcul faux donnent le même nombre (commentaire des lignes 23–26). Une valeur d'essai doit faire diverger le juste du faux.

Schéma 2 · Tester sans Rhino

Compiler la logique pure, fichier par fichier

Grasshopper.dll ne fonctionne qu'à l'intérieur de Rhino. Le projet de test ne référence donc pas les .gha : il recompile lui-même, par lien, les seuls fichiers qui n'utilisent pas Grasshopper.

ResolutionTests.csproj · 22, 80 et 116<EnableDefaultCompileItems>false</EnableDefaultCompileItems> <Compile Include="..\..\src\SnapSet.Constituants\Pur\ModeleFeuilles.cs" Link="Constituants\ModeleFeuilles.cs" /> <Compile Include="..\..\src\SnapSet.Conception\Generation\GenerateurDessin.cs" Link="Conception\GenerateurDessin.cs" />

Un lien, pas une copie

Link compile le fichier d'origine : une seule source, aucune copie à tenir à jour. EnableDefaultCompileItems=false empêche le projet d'avaler tous les .cs de son dossier : chaque fichier est choisi.

Couper les fichiers en deux

Une classe peut avoir une moitié pure et une moitié Grasshopper, en deux fichiers partial (cours 25). Seule la moitié pure est liée : c'est le cas de ConstituantExecution et de sa palette.

Piège courant Lier un fichier ET référencer la DLL qui le contient. Le même type existerait deux fois : erreur CS0433. Le .csproj construit SnapSet.Constituants par une ProjectReference avec ReferenceOutputAssembly="false" : la DLL existe, mais seul Roslyn la lit.

Schéma 3 · Les tests du web de Magpie

node --test, sans aucun paquet

Le volet web de Magpie n'installe pas de bibliothèque de test : Node fournit node:test et node:assert. npm test lance node --test "test/*.test.mjs" (web/package.json, ligne 10).

web/test/validation.test.mjs · 3–18, condenséimport { test } from "node:test"; import assert from "node:assert/strict"; import { validateSubmission } from "../validation.mjs"; const verdict = (submitted, config) => validateSubmission(submitted, config).pass; test("ExactOrderedList : ordre et tolérance", () => { const config = { Mode: "ExactOrderedList", ExpectedNumbers: [1, 3, 5], Tolerance: 0.01 }; assert.equal(verdict([1.005, 3, 5], config), true, "dans la tolérance"); assert.equal(verdict([3, 1, 5], config), false, "ordre faux"); });

Le troisième argument

« dans la tolérance », « ordre faux » : le message s'affiche quand l'affirmation échoue. Plusieurs affirmations dans un même test restent ainsi lisibles.

Tester ce qui ne doit pas arriver

Lignes 20–25 : le message renvoyé pour une mauvaise réponse ne doit jamais contenir la valeur attendue. Un test peut garder une règle pédagogique, pas seulement un calcul.

Piège courant Lire un échec sans lire l'erreur. Ici, trois tests de apercu.test.mjs échouent avec ERR_MODULE_NOT_FOUND : le paquet rhino3dm n'est pas installé. Ce n'est pas un défaut du code ; npm install d'abord, puis npm test.

Glossaire

Assertion
L'affirmation qu'un test vérifie ; fausse, elle fait échouer le test.
Logique pure
Du code qui ne dépend que de ses entrées, sans Rhino ni disque.
Roslyn
Le compilateur C#, utilisable comme une bibliothèque.
Diagnostic
Une erreur ou un avertissement du compilateur, avec son code CS.
Métadonnées
La description des types d'une DLL, lue sans exécuter son code.
