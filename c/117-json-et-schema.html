Le concept

JSON et son schéma

JSON écrit des objets, des tableaux et des valeurs simples, avec une syntaxe minuscule. Les exercices de Magpie en sont faits, lus par le plugin en C# et par le volet web en JavaScript. Le format ne dit pas ce qu'une valeur veut dire : c'est l'affaire de chaque lecteur, ou d'un schéma écrit une fois pour tous.

45 min de lecture et de QCM Prérequis · 24, 116 Exemples · Magpie plugin et web, SnapSet

L'idée en une phrase

Un fichier JSON n'a de sens que par le contrat entre ses lecteurs ; tant que ce contrat n'est écrit nulle part, chaque lecteur l'interprète à sa façon, et ils finissent par diverger.

L'analogie

Une feuille de cotes sans cartouche : les chiffres sont lisibles, mais millimètres ou pouces, cote nominale ou tolérancée, chacun le devine. Le schéma est le cartouche.

À la fin, tu sais

  1. dire ce que JSON permet, et ce qu'il interdit ;
  2. prévoir les écarts entre deux lecteurs ;
  3. repérer ce qu'un champ absent devient ;
  4. écrire et passer un schéma JSON.
À retenir JSON fixe la syntaxe, pas le sens. « "Mode": 3 » est du JSON parfait ; que ce soit un mode, et lequel, dépend du programme qui lit. Deux programmes, deux réponses possibles.

Schéma 1 · Trois lecteurs, un texte

Strict ou tolérant

La norme JSON est courte et stricte. Les bibliothèques, elles, s'en écartent plus ou moins. On a passé seize textes à trois lecteurs ; voici ceux où ils ne sont pas d'accord, ou pas d'accord avec la norme.

Exemple autonome · Node, lire un JSON écrit sous Windowsimport { readFileSync } from "node:fs"; const texte = readFileSync(chemin, "utf-8").replace(/^\uFEFF/, ""); // retirer un BOM éventuel const config = JSON.parse(texte);

Le BOM

readFileSync(…, "utf-8") garde le BOM, et JSON.parse le refuse. Côté plugin, File.ReadAllText le retire avant Newtonsoft. Les 144 JSON de Magpie n'en ont aucun (mesuré) : le plugin écrit par File.WriteAllText, sans BOM.

Les fichiers de VS Code

.vscode/launch.json a une virgule finale (ligne 44) : Python et JSON.parse le refusent. VS Code lit du JSONC, du JSON avec commentaires et virgules. Même extension, autre format.

Piège courant Tester un fichier écrit à la main avec le lecteur le plus tolérant. Il passe dans le plugin, qui accepte commentaires et virgules finales ; importé côté web, il est refusé. On valide avec le lecteur le plus strict.

Schéma 2 · Ce que la syntaxe ne dit pas

Un mode, deux interprétations

Le champ Mode est une chaîne pour JSON, une énumération pour C#, une clé de table pour JavaScript. Tant que le fichier dit « NumericTolerance », les trois s'accordent ; dès qu'il dit autre chose, chacun suit sa règle.

Exemple autonome · JavaScript, lire le mode comme le plugin le litconst MODES = ["ExactOrderedList", "SetEquality", "SingleValue", "NumericTolerance", "GeometryTolerance", "ExactOrderedListText", "SetEqualityText"]; const mode = Number.isInteger(config.Mode) ? MODES[config.Mode] : config.Mode; if (config.Mode === undefined || !(mode in VALIDATORS)) throw new Error("Mode illisible");

Le champ absent

Newtonsoft ne touche pas une propriété absente : elle garde son initialiseur. ExpectedTexts vaut donc une liste vide (ExerciseDefinition.cs:19), ExpectedBranchSizes null (ligne 31), Mode son premier membre. En JavaScript, tout champ absent vaut undefined.

Quatre générations

Les 58 exercices ont quatre jeux de clés : 32 sans ExpectedTexts, 18 avec, 5 sans graphe de départ, 3 avec ExpectedBranchSizes (mesuré). Chaque fichier garde la forme de son époque ; les lecteurs doivent toutes les accepter.

Piège courant Tester une valeur avec !config.Mode. Le zéro, la chaîne vide et false sont « faux » en JavaScript : un mode écrit 0, parfaitement valide pour le plugin, passe pour absent. On teste === undefined.

Schéma 3 · Écrire le contrat

Un schéma JSON

JSON Schema décrit, en JSON, ce qu'un document doit contenir : types, valeurs permises, champs requis ou interdits. Un validateur le passe sur un fichier avant toute lecture. On en a écrit un pour les exercices de Magpie, d'après le modèle C#.

Exemple autonome · un extrait du schéma des exercices, et sa vérification"required": ["Id", "Titre", "Mode"], "additionalProperties": false, "Mode": { "enum": ["ExactOrderedList", "SetEquality", … "SetEqualityText"] }, "Tolerance": { "type": "number", "minimum": 0 }, # Python : jsonschema.Draft202012Validator(schema).iter_errors(exercice)

Ce que le schéma apprend

Écrit d'après le code, il a d'abord refusé 23 fichiers : le motif « lettres, tiret, chiffres » ne couvrait pas les Id réels. Le schéma oblige à écrire une règle que tout le monde suivait sans l'avoir dite, ou à découvrir qu'il y en a cinq.

Un schéma comme source

SnapSet va plus loin : son schéma porte des clés à lui (parEtat, 58 fois ; rubrique, 192 fois), que la norme ignore, et generer-modele.js en tire le code C#. Le contrat et le code ne peuvent plus diverger.

Piège courant Écrire le schéma une fois, puis le laisser à côté. Un schéma que rien n'exécute (aucun test, aucun import) se périme au premier champ ajouté. Il vaut par le validateur qui le passe, à chaque import ou à chaque commit.

JSONC
