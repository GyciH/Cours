Le concept

SQLite dans Node

Le catalogue des composants, les parcours et les exercices de Magpie tiennent dans un seul fichier, magpie.db. SQLite est une base de données complète, sans serveur à installer : une bibliothèque lit et écrit ce fichier. Node l'embarque depuis la version 22, sous le nom node:sqlite.

55 min de lecture et de QCM Prérequis · 30 et 33 Exemples · db.mjs, exercises.mjs, compute-proxy.mjs (Magpie)

L'idée en une phrase

Une base relationnelle range les données en tables de lignes et de colonnes, et on l'interroge en SQL : on décrit les lignes voulues, la base trouve comment les obtenir.

L'analogie

Un classeur Excel bien tenu : une feuille par sorte de chose, une ligne par élément, une colonne par propriété, et une colonne d'identifiants qui permet à une feuille de renvoyer à une autre.

À la fin, tu sais

  1. lire le schéma de magpie.db et ses liens ;
  2. écrire une requête paramétrée avec prepare et ? ;
  3. dire pourquoi on ne colle jamais une valeur dans du SQL ;
  4. suivre une migration de schéma sans perte de données.
À retenir DatabaseSync est synchrone : chaque requête bloque le fil de Node le temps de s'exécuter. C'est acceptable ici, car la base est locale et les requêtes durent quelques microsecondes ; l'attente longue, celle de Compute, reste asynchrone (cours 30).

Schéma 1 · Les tables

Trois tables, un lien

openDb crée les tables au premier lancement. Chaque colonne a un type, une ligne est repérée par sa clé primaire, et une clé étrangère pointe vers la ligne d'une autre table.

db.mjs · 47–55CREATE TABLE IF NOT EXISTS exercises ( id TEXT PRIMARY KEY, parcoursId TEXT REFERENCES parcours(id), sortOrder INTEGER NOT NULL DEFAULT 0, title TEXT NOT NULL, instructions TEXT, starterGraph TEXT, -- JSON, optionnel (graphe de départ pré-câblé, propre au web) validationConfig TEXT NOT NULL -- JSON natif complet, JAMAIS renvoyé au client ) STRICT;

STRICT, comme C#

Par défaut, SQLite accepte du texte dans une colonne INTEGER. STRICT l'interdit : une valeur du mauvais type est refusée à l'écriture, comme le ferait le compilateur C#.

Du JSON dans une colonne TEXT

validationConfig garde le JSON de l'exercice tel que le plugin l'écrit, sans le découper en colonnes. On ne le cherche jamais par son contenu : on le relit en entier, puis JSON.parse.

Piège courant Croire qu'une colonne se protège seule. validationConfig contient la réponse attendue : rien dans la base ne l'empêche de sortir. C'est le code qui ne la sélectionne jamais dans les routes de l'apprenant ; la liste publique ne lit que id, title, instructions (compute-proxy.mjs, ligne 230).

Schéma 2 · Requêtes paramétrées

Le SQL d'un côté, les valeurs de l'autre

db.prepare(sql) compile une requête une fois. Chaque ? marque une place ; les valeurs arrivent ensuite, à part, par get (une ligne), all (toutes) ou run (une écriture).

exercises.mjs · 11–18db.prepare( `INSERT INTO exercises (id, parcoursId, sortOrder, title, instructions, starterGraph, validationConfig) VALUES (?, NULL, 0, ?, ?, NULL, ?) ON CONFLICT(id) DO UPDATE SET title = excluded.title, instructions = excluded.instructions, validationConfig = excluded.validationConfig` ).run(config.Id, config.Titre, config.Consigne || null, JSON.stringify(config));

Insérer ou mettre à jour

ON CONFLICT(id) DO UPDATE : si l'id existe déjà, la ligne est mise à jour au lieu d'échouer. excluded désigne la ligne qu'on tentait d'insérer. Réimporter un exercice corrigé ne change donc jamais sa référence.

Préparer une fois, exécuter souvent

upsertParcours prépare setPosition avant la boucle, puis l'exécute pour chaque exercice. La requête est analysée une seule fois ; seules les valeurs changent.

Piège courant Coller une valeur dans le texte SQL : `… WHERE id = '${id}'`. Un id comme x' OR '1'='1 réécrit alors la requête : c'est l'injection SQL. Avec ?, la valeur n'est jamais lue comme du SQL. Toutes les requêtes de Magpie qui reçoivent une valeur passent par ?.

Schéma 3 · Les migrations

Faire évoluer une base déjà remplie

Le fichier magpie.db d'un poste peut dater d'une ancienne version du code. CREATE TABLE IF NOT EXISTS ne touche jamais une table existante : chaque changement de schéma est donc rattrapé à part, au démarrage, par une migration.

db.mjs · 125–138// Migration 3 : le parcours garde la liste ExerciseIds de son JSON natif, … const hasExerciseIds = db.prepare("PRAGMA table_info(parcours)").all() .some((c) => c.name === "exerciseIds"); if (!hasExerciseIds) { db.exec("ALTER TABLE parcours ADD COLUMN exerciseIds TEXT;"); } // Migration 4 : objets du graphe de départ que le canvas ne sait pas représenter … const hasOpaque = db.prepare("PRAGMA table_info(exercises)").all() .some((c) => c.name === "opaqueObjects"); if (!hasOpaque) { db.exec("ALTER TABLE exercises ADD COLUMN opaqueObjects TEXT;"); }

Regarder avant d'agir

PRAGMA table_info liste les colonnes réelles d'une table. Chaque migration teste d'abord l'état de la base, et ne fait rien s'il est déjà bon : on peut relancer le serveur autant de fois qu'on veut.

Ajouter, ou reconstruire

Ajouter une colonne se fait en place (ALTER TABLE … ADD COLUMN). Changer le type d'une colonne, non : la migration 2 relit les exercices, recrée les tables, puis les réinsère (lignes 87–123).

Piège courant Modifier seulement le CREATE TABLE. Une base neuve aurait la nouvelle colonne, mais celle d'un poste existant resterait à l'ancien schéma, et la première requête qui lit la colonne échouerait. D'où les migrations, à côté du schéma.

Glossaire

Clé primaire
La colonne dont la valeur identifie une ligne, sans doublon.
Clé étrangère
Une colonne qui contient la clé primaire d'une ligne d'une autre table.
Requête paramétrée
Du SQL avec des ? ; les valeurs voyagent à part.
Injection SQL
Une valeur collée dans le SQL qui en change le sens.
Migration
Un changement de schéma appliqué à une base déjà remplie.
