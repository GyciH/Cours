Le concept

IP, ports, DNS et TCP

Sous chaque requête HTTP (cours 61) se cachent trois étages plus anciens. Le DNS traduit un nom en adresse IP ; l'adresse désigne une machine, le port un programme sur cette machine ; TCP ouvre entre les deux une connexion fiable, dans laquelle HTTP circule. Quand « ça ne se connecte pas », c'est presque toujours à l'un de ces étages.

50 min de lecture et de QCM Prérequis · 61 et 66 Exemples · compute-proxy.mjs, vite.config.js (Magpie)

L'idée en une phrase

Pour joindre un programme sur le réseau, il faut son adresse (trouvée par DNS) et son port, puis une connexion TCP ; chaque étape a son message d'erreur, qui dit où chercher.

L'analogie

Appeler un service dans une entreprise : l'annuaire donne le numéro du standard (DNS → IP), le poste désigne la personne (port), et la communication s'établit quand elle décroche (TCP).

À la fin, tu sais

  1. lire une adresse et son port ;
  2. dire ce que fait le DNS ;
  3. suivre l'ouverture d'une connexion TCP ;
  4. diagnostiquer un échec de connexion.
À retenir localhost n'est pas une adresse mais un nom, qui désigne la machine elle-même. Un serveur lancé sur ton PC et joint par localhost ne quitte jamais le PC : c'est pourquoi le développement local marche sans Internet.

Schéma 1 · Adresses et ports

Une machine, des dizaines de programmes

Une adresse IPv4 s'écrit en quatre nombres de 0 à 255 ; IPv6, plus longue, s'écrit en hexadécimal (::1 est l'équivalent de 127.0.0.1). Sur une même machine, chaque programme qui attend des connexions écoute sur un port, de 1 à 65 535. En local, Magpie en occupe trois.

Exemple autonome · Windowsnetstat -ano | findstr :5175 # qui écoute sur 5175 ? (dernier nombre : le PID) tasklist /fi "PID eq 12345" # quel programme porte ce PID ipconfig # les adresses IP de ce PC Test-NetConnection localhost -Port 6500 # PowerShell : le port répond-il ?

Écouter où ?

Un serveur choisit aussi sur quelle adresse écouter. 127.0.0.1 : seulement la machine elle-même. 0.0.0.0 (ou ::) : toutes ses adresses, donc aussi les autres machines du réseau, si le pare-feu les laisse passer.

Le pare-feu

Windows demande, la première fois qu'un programme écoute, s'il doit être joignable du réseau. Refuser bloque les autres machines, jamais localhost. C'est souvent la cause d'un « ça marche chez moi, pas depuis la tablette ».

Piège courant Lancer deux fois le même serveur. Le second échoue avec EADDRINUSE : le port est déjà pris, souvent par une fenêtre oubliée de la veille. netstat trouve le coupable ; le fermer libère le port.

Schéma 2 · Le DNS

L'annuaire d'Internet

Le DNS est une base répartie : aucun serveur ne connaît tous les noms. Ton PC interroge un résolveur, qui remonte la hiérarchie (racine, puis .fr, puis le serveur du domaine) et garde la réponse en cache le temps indiqué (TTL). La plupart des requêtes s'arrêtent à un cache.

Exemple autonome · terminal et Nodenslookup www.cj-developpement.fr # Windows, Linux, macOS ipconfig /flushdns # Windows : vider le cache local dns.lookup("localhost", { all: true }, (e, a) => console.log(a)); // sur la machine de rédaction : [ { address: '127.0.0.1', family: 4 } ]

Le fichier hosts

Avant le DNS, le système lit C:\Windows\System32\drivers\etc\hosts : une liste « adresse nom » écrite à la main. C'est là que localhost est défini, et l'endroit où l'on simule un nom pendant un test.

Changer d'hébergeur

Modifier l'enregistrement A d'un domaine ne prend effet partout qu'une fois les caches expirés. On baisse le TTL quelques jours avant une migration, pour que le basculement soit rapide.

Piège courant localhost peut désigner ::1 (IPv6) avant 127.0.0.1. Un serveur qui n'écoute que sur 127.0.0.1 devient alors injoignable par son nom. En cas de doute, on essaie l'adresse numérique : si elle marche et le nom non, c'est la résolution.

Schéma 3 · TCP et ses échecs

Ouvrir une connexion, comprendre un refus

TCP ouvre une connexion par un échange de trois messages, puis garantit que les octets arrivent tous, dans l'ordre, en renvoyant ceux qui se perdent. Les deux premières erreurs ci-dessous ont été provoquées pour ce cours ; leur code dit à quel étage chercher.

Exemple autonome · Node (mesuré)try { await fetch("http://localhost:6500/grasshopper"); } catch (e) { console.log(e.message, e.cause?.code); } // fetch failed ECONNREFUSED (rien sur le port 6500) // fetch failed ENOTFOUND (avec un nom inexistant)

Refus ou silence

Un refus arrive vite : la machine est là, mais rien n'écoute. Le silence, lui, dure : la machine est éteinte, ou un pare-feu jette les paquets. D'où l'utilité d'un délai maximal, sans lequel on attendrait longtemps.

Et UDP ?

L'autre transport d'Internet n'ouvre pas de connexion et ne garantit rien : plus rapide, il sert au DNS, à la vidéo, aux jeux. HTTP/3 s'appuie sur lui (QUIC), en recréant la fiabilité par-dessus.

Piège courant Ne lire que e.message. Avec fetch en Node, il vaut « fetch failed » dans tous les cas ; la vraie raison est dans e.cause.code. Un message d'erreur qui omet la cause renvoie le développeur chercher au mauvais étage.

Glossaire

Adresse IP
Le numéro qui désigne une machine sur un réseau.
Port
Le numéro qui désigne un programme à l'écoute sur une machine.
DNS
L'annuaire réparti qui traduit les noms en adresses IP.
TCP
Le transport qui ouvre une connexion fiable et ordonnée entre deux programmes.
Boucle locale
L'adresse 127.0.0.1 (ou ::1), qui désigne la machine elle-même.
