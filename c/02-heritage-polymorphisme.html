Le concept

Héritage et
polymorphisme, appliqués

Hériter, c'est dire « est un ». Une classe enfant reçoit tout ce que son parent sait faire, et n'écrit que ce qui change. Le polymorphisme, c'est l'autre moitié : le code qui manipule le parent exécute, sans le savoir, la version de l'enfant.

55 min de lecture et de QCM Prérequis · 01 C# moderne Exemple · SnapSet, les constituants

L'idée en une phrase

On écrit une fois, dans le parent, ce que plusieurs classes ont en commun ; chaque enfant complète les cases laissées vides et corrige celles qui le concernent.

L'analogie

Un formulaire pré-rempli. Le parent remplit tout ce qu'il peut. Certaines cases sont obligatoires et vides (abstract), d'autres ont une valeur proposée qu'on peut changer (virtual).

À la fin, tu sais

  1. employer les six mots du contrat parent-enfant : abstract, virtual, override, sealed, base, protected ;
  2. lire la hiérarchie des constituants de SnapSet et dire qui définit quoi ;
  3. suivre un appel polymorphe : Grasshopper demande l'icône d'un GH_Component, et c'est le code de Colonne qui répond.
À retenir Ligne et Colonne sont deux classes de 19 lignes. Tout le reste, plus de 500 lignes, est écrit une seule fois dans leurs parents. C'est le bénéfice de l'héritage : une correction dans Conteneur profite aux deux.

Schéma 1 · L'arbre généalogique

Les constituants de SnapSet, trois étages

Cadre pointillé : classe abstraite, qu'on ne peut pas créer seule. Cadre plein foncé : classe scellée (sealed), dont personne ne peut hériter. Ce sont les seules qui apparaissent dans le ruban.

La flèche d'héritage Par convention, la flèche à pointe creuse va de l'enfant vers le parent : « Colonne est un Conteneur ». Dans le code, c'est le : de class Colonne : Conteneur. Une classe C# n'a qu'un seul parent ; elle peut en revanche implémenter plusieurs interfaces (Conteneur implémente IGH_InstanceGuidDependent).

Schéma 3 · Deux trajets à suivre

Les constructeurs montent, les appels descendent

A · new Colonne()

Chaque constructeur passe la main à son parent par base(…). Les arguments montent, puis les corps s'exécutent en redescendant, du parent le plus haut vers l'enfant.

B · Grasshopper demande l'icône

Grasshopper ne connaît que GH_Component. Il lit Icon ; le langage cherche la version la plus basse dans la famille de l'objet réel. C'est le polymorphisme.

À retenir Constituant écrit une propriété Icon pour 17 constituants. Elle fonctionne parce qu'elle appelle Type, que chaque enfant remplit. Le parent pose la question, l'enfant donne la réponse.

Corrigé expliqué

Les réponses, et pourquoi

01 · B. Le : se lit « est un ». Contenir un objet, c'est la composition, autre chose.
02 · B. Une classe abstract ne s'instancie pas. On crée une Colonne, une Ligne, une feuille.
03 · B. Un enfant qui ne l'écrit pas doit lui-même être abstract, comme Conteneur.
04 · B. virtual propose une version ; override la remplace si besoin.
05 · B. Seule ConceptionPrise : une Prise mal placée a un motif à signaler.
06 · B. sealed ferme la famille. Colonne reste modifiable et visible.
07 · A et B. override remplace, sealed verrouille. protected la limite à la famille.
08 · B. Les arguments montent par base(…), les corps s'exécutent du haut vers le bas.
09 · B. Constituant passe Categorie et SousCategorie à GH_Component.
10 · A et B. Constituant.Icon remplace celle de GH_Component et appelle Type, que Colonne fournit.
11 · B. Les composants de Cuttlefish partagent des calculs (Outils.Groupes, Milieu), pas un comportement.
12 · B. C'est la méthode modèle : l'ordre ne peut être ni oublié ni changé par une feuille.

Glossaire

Héritage
Relation « est un » : l'enfant reçoit les membres du parent.
Polymorphisme
Un appel fait par le parent exécute la version de l'objet réel.
Méthode modèle
Le parent fixe les étapes, l'enfant fournit certaines d'entre elles.
Interface
Un contrat sans code ; une classe peut en implémenter plusieurs.
