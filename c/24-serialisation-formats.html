Le concept

Sérialisation et
formats de fichiers

Un exercice Magpie vit en mémoire le temps d'une session. Pour le livrer, le copier ou le rouvrir demain, il faut le mettre à plat dans un fichier, puis savoir le reconstruire à l'identique.

50 min de lecture et de QCM Prérequis · 03 collections · 12 persistance Exemples · MagpieRepository, GeometrySerializer, GrapheDeDepart (Magpie)

L'idée en une phrase

Sérialiser, c'est transformer un objet en une suite de caractères ou d'octets qu'on peut écrire ; désérialiser, c'est reconstruire l'objet à partir d'elle. Le format (JSON, XML, binaire) est le contrat entre les deux.

L'analogie

Un meuble en kit. On le démonte en pièces numérotées et on écrit la notice ; le carton voyage ; à l'arrivée, la notice permet de remonter le même meuble. Sans notice commune, les pièces ne servent à rien.

À la fin, tu sais

  1. relier un fichier JSON à sa classe C#, avec Newtonsoft ;
  2. mettre des octets dans du texte grâce au base64 ;
  3. écrire et relire un graphe Grasshopper en XML ;
  4. embarquer un fichier dans une DLL et le relire.
À retenir Un format écrit dure plus longtemps que le code qui l'a produit. Chaque choix (un nom de clé, une énumération en toutes lettres, le nom d'un nœud racine) devient une promesse : les fichiers déjà distribués doivent encore se relire.

Schéma 1 · JSON et Newtonsoft

Une classe, un fichier texte

JSON écrit des objets avec des accolades, des listes avec des crochets, et des valeurs simples : texte, nombre, booléen, null. Newtonsoft.Json fait correspondre chaque propriété publique à une clé du même nom.

MagpieRepository.cs · 31–35 et 90–95private static readonly JsonSerializerSettings Reglages = new JsonSerializerSettings { Formatting = Formatting.Indented, Converters = { new StringEnumConverter() } }; public static void SaveExercise(ExerciseDefinition ex) { Directory.CreateDirectory(ExercisesFolder); string path = Path.Combine(ExercisesFolder, $"{ex.Id}.json"); File.WriteAllText(path, JsonConvert.SerializeObject(ex, Reglages)); }

Relire, c'est l'appel inverse

JsonConvert.DeserializeObject<ExerciseDefinition>(texte) crée l'objet avec son constructeur sans argument, puis remplit chaque propriété dont il trouve la clé. Une clé absente laisse la valeur par défaut : Tolerance = 0.0, une liste vide.

Ce qui n'est pas écrit

AttendUnArbre se calcule à partir d'ExpectedBranchSizes. L'écrire serait stocker deux fois la même information, avec le risque qu'elles divergent : [JsonIgnore] l'exclut.

Piège courant Une énumération écrite en entier. Sans StringEnumConverter, Newtonsoft écrit "Mode": 0 : le fichier dépend de la position du membre dans l'enum, et le volet web, qui cherche ses validateurs par nom, ne reconnaît pas le mode (commentaire des lignes 25–30). La lecture accepte les deux formes.

Schéma 2 · Binaire et base64

Une courbe dans un fichier texte

Une géométrie de référence ne se décrit pas en quelques clés. Magpie la confie à Grasshopper, qui sait déjà l'écrire (cours 12), puis range le résultat binaire dans une chaîne.

GeometrySerializer.cs · 15–22public static string Serialize(GH_ISerializable goo) { var chunk = new GH_LooseChunk(ChunkName); goo.Write(chunk); // objet -> GH_Chunk byte[] bytes = chunk.Serialize_Binary(); // GH_Chunk -> byte[] return Convert.ToBase64String(bytes); // byte[] -> string }

Le mécanisme natif, réutilisé

Write et Read de GH_ISerializable sont ceux qu'emploie Grasshopper pour « Internaliser les données » et pour le copier-coller. Magpie n'écrit aucun format de courbe : il marche pour tout type qui sait déjà s'écrire.

Le type voyage à côté

Les octets ne disent pas s'il faut reconstruire un GH_Point ou un GH_Curve. D'où la clé ExpectedGeometryTypeName (« curve »…) et GeometryTypeRegistry, une table nom → type, qui choisit le bon Deserialize<T>.

Piège courant Mettre les octets « tels quels » dans une chaîne. Un octet quelconque n'est pas forcément un caractère valide : des guillemets ou un code de contrôle casseraient le JSON. Le base64 n'emploie que 64 caractères sûrs, au prix d'un tiers de taille en plus.

Schéma 3 · Ressources embarquées

Livrer des fichiers sans dossier à installer

L'apprenant installe un .gha, rien d'autre. Les exercices du parcours, les icônes et le gabarit de certificat sont donc dans la DLL, copiés à la compilation.

MagpieSources.cs · 164–178private string Lire(string nom) { using (var flux = _assembly.GetManifestResourceStream(nom)) { if (flux == null) throw new InvalidOperationException($"Ressource « {nom} » annoncée par l'assembly mais introuvable."); using (var lecteur = new StreamReader(flux, Encoding.UTF8, detectEncodingFromByteOrderMarks: true)) return lecteur.ReadToEnd(); } }

Le gabarit .3dm du certificat

Rhino ne sait ouvrir un .3dm que depuis un chemin. MagpieCertificateGenerator copie donc la ressource dans un fichier temporaire, l'ouvre par RhinoDoc.CreateHeadless (sans toucher au document de l'utilisateur), remplace le texte des objets nommés Magpie_Nom, Magpie_Date… puis imprime la mise en plan en PDF.

Un glob, pas une liste

Le .csproj embarque Resources\**\*. Ajouter un exercice ne demande aucune édition du projet ; en contrepartie, tout fichier déposé là part dans le binaire livré. Les JSON de parcours y arrivent par outils/publier-parcours.mjs.

Piège courant Le BOM. Un fichier réenregistré à la main peut commencer par trois octets invisibles qui marquent l'UTF-8. Lus comme un caractère, ils rendent le JSON invalide. detectEncodingFromByteOrderMarks: true les reconnaît et les retire.
