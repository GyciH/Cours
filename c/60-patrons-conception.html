Le concept

Les patrons de conception

Certains problèmes reviennent dans tous les logiciels : un arbre d'objets à traiter d'un bloc, un objet qui doit prévenir d'autres sans les connaître, un geste qu'on veut pouvoir annuler. Un patron de conception donne un nom et une forme éprouvée à chacune de ces solutions.

55 min de lecture et de QCM Prérequis · 01 et 58 Exemples · Conteneur, Bouton, Constituant, Metrique, GenerateurDessin

L'idée en une phrase

Un patron n'est pas une bibliothèque qu'on importe mais un plan : quelles classes, qui connaît qui, qui appelle qui. Le connaître permet de reconnaître le problème plus tôt et d'en parler en un mot.

L'analogie

Les assemblages en menuiserie. Tenon et mortaise, queue d'aronde, mi-bois : personne ne les réinvente, chacun répond à un effort particulier, et le nom suffit entre artisans. Le bois, lui, change à chaque meuble.

À la fin, tu sais

  1. reconnaître cinq patrons dans SnapSet ;
  2. dire quel problème chacun règle ;
  3. savoir pourquoi l'annulation s'enregistre avant ;
  4. éviter le patron plaqué sans problème.
À retenir On part du problème, jamais du patron. Un code qui n'a qu'une façon de mesurer n'a pas besoin d'une stratégie ; un code qui en a deux (Rhino et les tests) en a besoin. Les noms viennent du livre de Gamma, Helm, Johnson et Vlissides (1994).

Schéma 1 · Composite

Un arbre qui parle d'une seule voix

Feuilles et conteneurs partagent un même type de base. Un conteneur range des membres qui peuvent être eux-mêmes des conteneurs ; le code qui parcourt l'arbre n'a pas besoin de distinguer les deux pour la plupart des opérations.

Exemple autonome · C#abstract class Forme { public abstract double Aire(); } class Disque : Forme { public double R; public override double Aire() => Math.PI * R * R; } class Groupe : Forme { public List<Forme> Membres = new List<Forme>(); public override double Aire() => Membres.Sum(m => m.Aire()); // récursif, sans test de type }

La récursion vient gratuitement

Mesurer une colonne, c'est mesurer ses membres puis les additionner ; si un membre est une ligne, il fait de même avec les siens. Le cas de base, ce sont les feuilles.

Rhino en est plein

Un bloc Rhino contient des objets ou d'autres blocs ; un cluster Grasshopper contient des composants ou d'autres clusters ; un groupe SVG contient des formes ou d'autres groupes.

Piège courant Remplir le parcours de if (x is Ligne) … else if (x is Colonne) …. Chaque nouveau type oblige alors à retrouver tous ces tests. Ce qui varie selon le type va dans une méthode du type ; le parcours, lui, reste aveugle.

Schéma 2 · Observateur

Prévenir sans connaître

Le sujet annonce « il s'est passé quelque chose » ; les observateurs qui se sont inscrits réagissent. Le sujet ne dépend d'aucun d'eux : on peut en ajouter un sans toucher au bouton. En C#, l'event est ce patron intégré au langage.

Exemple autonome · C#class Thermostat { public event EventHandler<double> Mesure; // le sujet public void Lire(double t) => Mesure?.Invoke(this, t); // ?. : personne n'écoute ? rien } thermo.Mesure += (s, t) => ecran.Afficher(t); // un observateur thermo.Mesure += (s, t) => { if (t > 30) alarme.Sonner(); }; // un autre, indépendant

Côté React

Un composant qui reçoit onChange en propriété fait la même chose : il annonce, le parent décide. L'état remonte, les données descendent.

Le prix à payer

Le chemin d'exécution ne se lit plus d'un bloc : qui réagit à Clic ? Il faut chercher les +=. Et chaque inscription retient l'observateur en mémoire (cours 58).

Piège courant Un observateur qui modifie le sujet dans sa réaction. Le sujet annonce de nouveau, l'observateur réagit de nouveau : boucle infinie ou pile qui déborde. On compare l'ancienne et la nouvelle valeur, et on n'annonce que si elle a vraiment changé.

Schéma 3 · Commande et annulation

Un geste qu'on peut défaire

Chaque modification devient un objet rangé dans une pile. Annuler, c'est dépiler et défaire ; rétablir, c'est refaire. Deux manières de défaire : jouer l'opération inverse, ou garder une copie de l'état d'avant (un mémento). Grasshopper prend la seconde.

Exemple autonome · C#interface ICommande { void Faire(); void Defaire(); } var annuler = new Stack<ICommande>(); var retablir = new Stack<ICommande>(); void Executer(ICommande c) { c.Faire(); annuler.Push(c); retablir.Clear(); } void Annuler() { var c = annuler.Pop(); c.Defaire(); retablir.Push(c); } void Retablir() { var c = retablir.Pop(); c.Faire(); annuler.Push(c); }

Le libellé compte

Le menu Edit de Grasshopper affiche « Undo Toggle », « Undo Resize… ». SnapSet reprend les noms des objets natifs (Toggle, Select: …) pour qu'un utilisateur ne voie pas la différence.

Pourquoi un nouveau geste vide la pile

Après avoir annulé trois gestes puis fait autre chose, les gestes annulés n'ont plus de sens : ils partaient d'un état qui n'existe plus. La branche est abandonnée.

Piège courant Enregistrer l'annulation après le changement. Le mémento capture alors l'état déjà modifié : Ctrl+Z « réussit » mais ne change rien. L'ordre est toujours : enregistrer, modifier, prévenir.

Glossaire

Patron
Une forme de solution, nommée, à un problème de conception qui revient.
Sujet
Dans l'observateur, l'objet qui annonce ; ses abonnés sont les observateurs.
Mémento
Une copie de l'état d'avant, gardée pour pouvoir y revenir.
Stratégie
Un comportement passé de l'extérieur, interchangeable sans toucher à l'appelant.
Méthode partielle
Une déclaration C# qu'un autre fichier peut implémenter, sinon effacée.
