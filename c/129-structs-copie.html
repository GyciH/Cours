Le concept

Les structs et la copie

Une class se manipule par son adresse ; une struct se manipule par sa valeur. Affecter, passer en paramètre, lire dans une liste : avec une struct, chaque fois, on obtient une copie. C'est ce qui rend Point3d sûr et rapide, et ce qui fait qu'on modifie parfois une copie sans le savoir.

45 min de lecture et de QCM Prérequis · 58, 128 Exemples · SnapSet schema, Magpie plugin

L'idée en une phrase

Une petite donnée sans identité, un point, une marge, un verdict, fait une bonne struct, de préférence immuable ; tout ce qu'on partage et modifie reste une class.

L'analogie

Une cote sur un plan contre la pièce elle-même. Recopier une cote ne change pas l'autre exemplaire ; prêter la pièce, c'est la retrouver modifiée.

À la fin, tu sais

  1. prévoir quand on copie ;
  2. modifier un élément pour de bon ;
  3. choisir struct ou class ;
  4. savoir ce que readonly fige.
À retenir Une struct qu'on ne peut pas modifier ne peut pas surprendre. readonly struct et des propriétés sans set évitent toute la famille des copies modifiées en vain.

Schéma 1 · Modifier une copie

Cinq façons d'ajouter 1

Même struct, même intention : décaler X. Selon l'endroit où vit la valeur, on modifie l'original, on modifie une copie, ou le compilateur refuse. On a essayé les cinq.

Exemple autonome · C#, modifier un élément d'une List de structsfor (int i = 0; i < points.Count; i++) { var p = points[i]; // une copie p.Z += hauteur; points[i] = p; // on la remet à sa place }

Tableau ou liste

Un tableau donne l'élément lui-même : pts[i].Z += h le modifie. L'indexeur d'une List est une méthode qui rend une valeur : une copie.

La copie défensive

Sur un champ readonly, appeler une méthode qui modifie la struct est permis : C# la fait sur une copie, pour protéger le champ. L'appel ne sert à rien, sans avertissement.

Piège courant pt.Transform(xform); sur un Point3d lu dans une liste ou rangé dans un champ readonly. La méthode modifie la copie ; le point d'origine n'a pas bougé, et aucun message ne le dit.

Schéma 2 · En mémoire

Côte à côte ou éparpillés

Un tableau de structs range les valeurs les unes après les autres. Un tableau d'objets range des adresses, et les objets vivent ailleurs. On a mesuré la place et le temps de lecture.

Exemple autonome · C#, mesurer la place d'une structunsafe { Console.WriteLine(sizeof(Pt)); } // 24 : trois double, sans en-tête Console.WriteLine(GC.GetAllocatedBytesForCurrentThread()); // avant et après : ce qu'on a alloué

Pas d'en-tête

Un objet porte 16 octets d'en-tête et se lit par une adresse. Une struct n'a ni l'un ni l'autre : dans un tableau, ses champs suivent ceux de la précédente.

Le comparateur de Magpie

La distance de Hausdorff parcourt deux nuages de Point3d[] l'un contre l'autre (GeometrySampler.cs:268). Recopiée telle quelle, 2 500 × 2 500 points : 14 à 31 ms mesurés.

Piège courant Faire une struct d'un gros objet qu'on passe partout. Chaque appel le recopie en entier ; au-delà de quelques double, une class, ou un passage par in, coûte moins.

Schéma 3 · Ce que readonly fige

Immuable, en surface

readonly struct interdit de modifier les champs. Mais un champ qui est une adresse, un tableau, une liste, reste une adresse : on ne peut pas la changer, on peut changer ce qu'elle désigne.

Exemple autonome · C#, une struct immuablepublic readonly struct Marge { public Marge(float haut, float bas) { Haut = haut; Bas = bas; } public float Haut { get; } public float Bas { get; } public Marge AvecHaut(float h) => new Marge(h, Bas); // on rend une autre valeur }

La valeur par défaut

Une struct existe toujours : default remplit tout de zéros. Metrique.cs en fait une règle, une marge absente vaut zéro, sans test de null (ligne 1167).

Égalité de valeur

Deux structs sont égales si leurs champs le sont, par défaut. C'est juste, mais lent ; le cours 131 montre comment écrire Equals pour aller vite.

Piège courant Croire qu'une readonly struct qui contient un tableau est figée. Le tableau reste modifiable par quiconque reçoit la struct : on a écrit dans Points[0] sans la moindre erreur.

Glossaire

Type valeur
Un type dont la variable contient la donnée elle-même : struct, enum, int.
Type référence
Un type dont la variable contient une adresse : class, tableau, string.
Copie défensive
La copie que fait C# pour protéger une struct readonly d'une méthode qui la modifierait.
Immuable
Qu'on ne peut plus modifier une fois construit.
Localité
Le fait que des données lues ensemble soient rangées côte à côte.
