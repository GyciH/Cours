Le concept

Génération de code

SnapSet n'écrit pas à la main ce qu'il peut déduire d'une description. Un schéma JSON devient des classes C#, et un dessin posé sur le canvas devient un composant Grasshopper. Le tout est de séparer ce que la machine réécrit de ce que le développeur garde.

50 min de lecture et de QCM Prérequis · 24 sérialisation Exemples · generer-modele.js, GenerateurDessin, EcrivainGeneration (SnapSet)

L'idée en une phrase

Un générateur est un programme qui écrit du code à partir d'une description. Il est utile s'il est déterministe : la même entrée donne toujours les mêmes octets, et le fichier produit n'est jamais retouché à la main.

L'analogie

Un tampon encreur. On grave le motif une fois (le générateur), on l'encre avec la description, et chaque coup donne la même empreinte. Si l'empreinte ne plaît pas, on change le tampon ou l'encre, pas l'empreinte au crayon.

À la fin, tu sais

  1. lire comment une entrée du schéma devient une propriété C# ;
  2. repérer ce qui rend une sortie non déterministe ;
  3. faire coopérer un fichier généré et un fichier écrit à la main par une classe partielle ;
  4. expliquer pourquoi « Générer » n'écrase jamais Xxx.cs.
À retenir Un fichier .g.cs est une sortie, comme un PDF qu'on imprime. On le corrige en changeant son entrée (le schéma, le dessin) ou son générateur, puis on régénère. Une retouche à la main disparaît au coup suivant.

Ce que le schéma ne dit pas

« gripsPresents » ne fait pas un bon nom de type. Cette petite table vit dans le générateur, jamais dans le fichier émis. Les rubriques, elles, viennent du schéma : une table de plus serait un second vocabulaire.

S'arrêter plutôt que deviner

Un réglage composé nouveau sans entrée dans la table arrête le script avec un message qui dit quoi faire. Un nom inventé au hasard compilerait, puis resterait dans tous les plugins publiés.

Piège courant Corriger ModeleGHStyle.g.cs directement. Son en-tête le dit : « NE MODIFIE PAS CE FICHIER À LA MAIN ». La correction compile, puis disparaît à la prochaine exécution de node schema/generer-modele.js. On change le schéma, puis on régénère.

Schéma 2 · Déterminisme

Deux exécutions, les mêmes octets

Un générateur est idempotent quand le relancer sur la même entrée ne change rien. Vérifié pour ce cours : deux exécutions dans une copie du dossier donnent les mêmes empreintes SHA-1 que les fichiers du dépôt.

GenerationDessinTests.cs · 176–192, condenséCultureInfo.CurrentCulture = CultureInfo.InvariantCulture; string invariant = GenerateurDessin.TexteDessin(ExemplesDessin.Atelier()); CultureInfo.CurrentCulture = new CultureInfo("fr-FR"); string francais = GenerateurDessin.TexteDessin(ExemplesDessin.Atelier()); Assert.Equal(invariant, francais); Assert.Contains("LargeurMinimale = 40.5f,", francais);

Pourquoi tenir aux mêmes octets

Si le texte n'a pas changé, EcrivainGeneration ne réécrit pas le fichier : sa date reste la même, Visual Studio ne recompile rien, et git ne montre aucune différence. Un horodatage dans l'en-tête suffirait à tout casser.

Le Guid, passé de l'extérieur

Le squelette Xxx.cs porte un ComponentGuid. TexteSquelette le reçoit en paramètre et n'en tire jamais lui-même : c'est l'écrivain qui appelle Guid.NewGuid(). Le générateur reste une fonction pure de ses entrées.

Piège courant La culture du poste. Sur un Windows français, 40.5f.ToString() donne « 40,5 » : le code émis deviendrait 40,5f, qui ne compile pas. Chaque nombre passe donc par CultureInfo.InvariantCulture, et le test ci-dessus le vérifie.

Schéma 3 · Deux fichiers, une classe

Le généré et le tien, réunis par partial

Le mot-clé partial permet d'écrire une classe dans plusieurs fichiers ; le compilateur les réunit. Le fichier généré déclare des méthodes partielles et les appelle. Ton fichier les implémente, s'il le souhaite.

Code émis par GenerateurDessin.Gestionnaire (850–872) pour une Liste taguée « mode »private void QuandModeChange(object sender, global::System.EventArgs e) { int v = this.mode.Index; this.RecordUndoEvent("Select: " + this.mode.LibelleChoisi); this._dejaRejoue = true; this._vuMode = v; this.SetValue("mode_Index", v); this.SurChangementMode(); // la méthode partielle this.OnObjectChanged("mode", v); this.ExpireSolution(true); }

Une partielle sans corps disparaît

Si Xxx.cs n'implémente pas SurChangementMode(), le compilateur efface la déclaration et l'appel. Ne rien écrire est permis, et ne coûte rien à l'exécution.

La base est déclarée chez toi

Le fichier généré écrit partial class Xxx, sans base ni public. Xxx.cs écrit public partial class Xxx : GH_Component. Tu peux passer la classe en internal sans conflit (CS0262).

Piège courant Renommer un tag au dessin. Xxx.cs implémente encore SurChangementMode(), que le fichier régénéré ne déclare plus : erreur CS0759. « Générer » le signale dans son compte rendu, mais ne touche pas à ton fichier. C'est à toi de renommer la méthode.

Glossaire

Générateur
Un programme qui écrit du code à partir d'une description.
Idempotent
Qu'on peut relancer sans rien changer de plus.
Déterministe
Même entrée, même sortie, au bit près.
Méthode partielle
Déclarée dans un fichier, implémentée (ou non) dans un autre.
Écriture atomique
Le fichier passe d'un état complet à l'autre, sans état intermédiaire visible.
