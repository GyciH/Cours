Le concept

Formuler un problème d'optimisation

Galapagos, Octopus ou un script maison : tous les optimiseurs attendent la même chose. Des variables qu'ils ont le droit de bouger, un nombre à rendre le plus petit ou le plus grand possible, et des limites à respecter. Bien poser ces trois choses compte plus que le choix de l'algorithme.

45 min de lecture et de QCM Prérequis · 55, 145, 150 Exemples · Magpie

L'idée en une phrase

Optimiser, c'est chercher dans l'espace des variables le point où l'objectif est le meilleur, sans pouvoir tout essayer.

L'analogie

Chercher le point le plus bas d'une région dans le brouillard : on ne voit que le sol sous ses pieds, et chaque mesure coûte un pas.

À la fin, tu sais

  1. nommer variables, objectif et contraintes ;
  2. préférer le hasard à la grille ;
  3. reconnaître un minimum local ;
  4. chiffrer le coût d'une recherche.
À retenir Un optimiseur ne comprend rien à ton projet : il ne voit qu'un nombre. Tout ce que tu veux obtenir doit se lire dans ce nombre, sinon il ne le cherchera pas.

Schéma 1 · Grille ou hasard

Essayer au hasard plutôt qu'en quadrillage

La recherche la plus simple essaie des points et garde le meilleur. Le quadrillage semble plus rigoureux ; il gaspille pourtant ses essais dès qu'une variable compte peu.

Exemple autonome · C#, la recherche au hasarddouble meilleur = double.MaxValue; double[] xBest = null; for (int k = 0; k < budget; k++) { var x = Tirer(r); // un point au hasard dans les bornes de chaque variable double v = Objectif(x); if (v < meilleur) { meilleur = v; xBest = x; } }

Les trois ingrédients

Les variables (les « gènes » de Galapagos) avec leurs bornes ; l'objectif (la « fitness »), un seul nombre ; les contraintes, ce qui rend une solution inacceptable.

Un repère, pas une fin

La recherche au hasard est le témoin à battre. Un algorithme plus savant qui ne fait pas mieux qu'elle, à budget égal, est mal réglé ou mal choisi.

Piège courant Quadriller cinq curseurs à trois positions. Les 243 essais ne testent que trois valeurs de chaque curseur : l'erreur restait 0,096 contre 0,0015 au hasard (mesuré).

Schéma 2 · Le paysage

Un creux n'est pas forcément le plus bas

Une méthode locale descend tant qu'un petit pas améliore, puis s'arrête. Sur un paysage à plusieurs creux, l'endroit où elle finit dépend surtout de l'endroit où elle part.

Exemple autonome · C#, plusieurs départsfor (int k = 0; k < departs; k++) { var x = Descente(Tirer(r)); // une descente locale depuis un départ au hasard if (Objectif(x) < Objectif(xBest)) xBest = x; } // on garde le meilleur creux trouvé

Lisse ou accidenté

Un paysage à un seul creux, comme une somme de carrés, se règle en une descente. Un paysage accidenté demande de l'exploration : départs multiples, recuit ou génétique (cours 154 et 155).

Changer le paysage

Le paysage dépend de l'objectif choisi. Remplacer un « nombre de pièces » entier par une mesure continue qui l'approche lisse souvent les marches.

Piège courant Conclure après un seul lancement. Une descente unique finissait au minimum global dans 1,35 % des cas sur Rastrigin (mesuré) : un bon résultat de départ ne dit pas qu'il n'y a pas mieux.

Schéma 3 · Le prix d'une évaluation

Chaque variable multiplie le travail

Dans Grasshopper, évaluer l'objectif veut dire recalculer toute la définition. C'est ce coût, multiplié par le nombre d'essais, qui décide de ce qui est faisable.

Exemple autonome · C#, ramener chaque variable entre 0 et 1double Reel(double u, double min, double max) => min + u * (max - min); // u entre 0 et 1 // l'optimiseur ne manipule que des u : un pas de 0,01 vaut 1 % de chaque plage, mm comme degrés

Moins de variables

Avant d'optimiser, fixer ce qui ne bouge presque pas le résultat. Deux curseurs utiles valent mieux que dix dont huit ne servent qu'à agrandir l'espace.

Des bornes honnêtes

Des bornes trop larges diluent les essais dans des formes absurdes ; trop étroites, elles excluent la bonne réponse. Elles font partie du problème.

Piège courant Mélanger des variables en millimètres et en degrés sous un même pas. Un pas de 1 déplace à peine une longueur de 5 000 mm mais fait tourner l'angle d'un degré entier (déduit).

Glossaire

Fonction objectif
Le nombre que l'optimiseur cherche à rendre minimal ou maximal.
Variable de décision
Une valeur que l'optimiseur a le droit de changer, entre deux bornes.
Contrainte
Une condition qu'une solution doit respecter pour être acceptable.
Minimum local
Un point qu'aucun petit pas ne peut améliorer, sans être forcément le meilleur.
Recherche au hasard
Essayer des points tirés dans les bornes et garder le meilleur.
