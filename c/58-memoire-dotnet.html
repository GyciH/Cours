Le concept

La mémoire en .NET

En C#, on ne libère presque jamais la mémoire à la main : le ramasse-miettes (GC) s'en charge. Mais il ne s'occupe que de la mémoire. Les pinceaux GDI, les polices, les fichiers ouverts se rendent avec Dispose, et un objet qu'on désigne encore par erreur ne part jamais.

55 min de lecture et de QCM Prérequis · 01 et 19 Exemples · PeintreFeuilles, MesureurGdi, SaisieMultiligne, ServiceGeste

L'idée en une phrase

Une variable contient soit une valeur (un int, une struct), soit une référence vers un objet du tas ; le GC récupère les objets que plus aucune référence vivante ne désigne, et Dispose rend tout de suite ce que le GC ne gère pas.

L'analogie

Une consigne de gare. Ton ticket (la référence) mène au casier (l'objet). Quand plus personne n'a de ticket, l'agent vide le casier à sa prochaine ronde. Une clé de voiture de location rangée dedans, en revanche, il faut la rendre soi-même au comptoir.

À la fin, tu sais

  1. prévoir ce que copie une affectation ;
  2. dire quand un objet devient récupérable ;
  3. placer un using autour de ce qui est jetable ;
  4. repérer les deux fuites classiques : static et événement.
À retenir Deux questions devant chaque objet : qui le désigne encore ? (sinon le GC le récupère) et qui le possède ? (le propriétaire, et lui seul, appelle Dispose). Les fuites viennent d'une réponse floue à l'une des deux.

Schéma 1 · Valeur ou référence

Ce que copie le signe égal

Affecter une struct copie tout son contenu : deux boîtes, deux vies. Affecter une class copie seulement la référence : deux noms pour un même objet. Le choix entre les deux se fait à la déclaration du type, pas à l'usage.

Exemple autonome · C#struct Point2 { public float X; } class Boite { public float X; } var p = new Point2 { X = 1 }; var q = p; q.X = 5; // p.X vaut toujours 1 var a = new Boite { X = 1 }; var b = a; b.X = 5; // a.X vaut 5 object o = p; // « boxing » : une copie de p part sur le tas var liste = new List<Point2> { p }; // liste[0].X = 2; → erreur CS1612

Quand choisir une struct

Pour une petite valeur sans identité, comparée par son contenu : un point, une marge, une couleur. Idéalement readonly, pour qu'aucune copie ne puisse surprendre. Point3d de RhinoCommon est une struct, Curve une classe.

La valeur par défaut

Une struct n'est jamais null : sa valeur par défaut a tous les champs à zéro. Une classe vaut null tant qu'on ne l'a pas créée, d'où les tests de nullité et les NullReferenceException.

Piège courant Modifier une struct obtenue par une propriété ou une liste. liste[0] rend une copie : le compilateur refuse de la modifier (CS1612), et une méthode qui la modifie travaillerait sur la copie. On remplace l'élément entier : liste[0] = nouveauPoint;.

Schéma 2 · Le ramasse-miettes

Est vivant ce qu'on peut atteindre

Le GC part des racines (champs static, variables locales en cours, handles épinglés) et suit toutes les références. Ce qu'il atteint est vivant ; le reste est récupéré, même si ces objets se désignent entre eux. On ne choisit pas le moment du passage.

Exemple autonome · C#static readonly List<Forme> Historique = new List<Forme>(); // racine pour toute la session void Calculer() { var tampon = new double[1_000_000]; // vivant pendant l'appel } // ensuite récupérable bouton.Click += vue.SurClic; // bouton désigne vue tant qu'on ne fait pas -=

Pourquoi des générations

La plupart des objets meurent jeunes (une chaîne temporaire, un tableau de calcul). Le GC visite souvent la génération 0, rapide et petite, et rarement la 2, où vivent les objets anciens. Un objet de plus de 85 000 octets va directement dans un tas à part.

Un événement est une référence

source.Evt += cible.Methode range dans la source un délégué qui désigne la cible. Tant que la source vit, la cible vit. Une source qui dure (le canvas, le document) garde donc en vie tous ses abonnés.

Piège courant Les deux fuites de .NET ne sont pas des oublis de libération mais des références oubliées : une collection static qui ne se vide jamais, et un abonnement à un objet durable sans -= correspondant. Le GC fait bien son travail : l'objet est encore atteignable.

Schéma 3 · Les ressources jetables

Dispose rend ce que le GC ne voit pas

Un SolidBrush occupe quelques octets côté .NET, mais aussi un handle GDI côté Windows, en nombre limité. Le GC ne connaît que les octets. IDisposable signale « appelle-moi Dispose quand tu as fini », et using le fait à coup sûr.

Exemple autonome · C#using (var pinceau = new SolidBrush(couleur)) // forme classique, un bloc { g.FillRectangle(pinceau, boite); } // Dispose ici, exception ou pas using var trait = new Pen(couleur, 1f); // C# 8 : Dispose à la fin de la méthode

Ce qui est jetable

Tout ce qui tient une ressource du système : Pen, Brush, Font, Bitmap, Graphics, flux de fichier, connexion SQLite, contrôle WinForms. Les géométries RhinoCommon aussi : elles tiennent de la mémoire native.

Créer ou emprunter

Un objet qu'on crée avec new nous appartient. Un objet qu'on reçoit d'une API (une police d'un cache, la matrice d'un viewport) est emprunté : le libérer casserait le propriétaire, qui s'en sert encore.

Piège courant Créer un Pen à chaque peinture sans using. Rien ne se voit au début ; après quelques milliers de rafraîchissements, la limite d'objets GDI est atteinte et l'application entière cesse de se dessiner. L'inverse est aussi grave : Dispose sur un objet emprunté.

Glossaire

Tas
La zone où vivent les objets des classes, rangée par le ramasse-miettes.
Racine
Un point de départ du GC : champ static, variable locale en cours, handle épinglé.
Boxing
La copie d'une valeur dans un objet du tas, quand on la range dans un object.
Handle GDI
Le numéro qu'attribue Windows à un pinceau, une police ou une image ; en nombre limité.
IDisposable
L'interface des objets qui tiennent une ressource à rendre par Dispose.
