Le concept

Faire évoluer un format

Un fichier survit au programme qui l'a écrit. Changer un nom de champ, l'ordre d'une énumération ou le sens d'une valeur, c'est changer le contrat de tous les fichiers déjà enregistrés. En une journée de septembre, l'enum ValidationMode de Magpie a cassé ce contrat, puis l'a réparé ; tout le cours tient dans ces deux commits.

45 min de lecture et de QCM Prérequis · 117 Exemples · Magpie plugin et web, SnapSet

L'idée en une phrase

Tout ce qu'un programme écrit sur disque devient une promesse : il faudra savoir le relire tel quel, quoi qu'on change au code ensuite.

L'analogie

La référence d'une pièce dans un catalogue fournisseur. On peut ajouter des références, jamais en réattribuer une : les bons de commande déjà émis la citent, et livreraient la mauvaise pièce.

À la fin, tu sais

  1. reconnaître ce qui fait partie d'un format ;
  2. classer un changement, sûr ou cassant ;
  3. ajouter un champ sans casser ;
  4. écrire une version et migrer.
À retenir Un nom de membre, sa position, un nom de chunk, un GUID de composant : dès qu'ils sont écrits dans un fichier, ce ne sont plus des détails de code. La documentation de Magpie le dit pour deux d'entre eux : on les garde, même mal orthographiés.

Schéma 1 · Rejouer l'histoire

Un numéro décalé, un nom disparu

On a recopié les trois versions de l'enum dans un petit programme et relu, avec chacune, quatre fichiers d'exercice possibles : deux écrits en numéro, deux en nom. Le décalage de 6fbb234 se voit immédiatement.

Exemple autonome · C#, fixer la valeur écrite de chaque membrepublic enum ValidationMode { ExactOrderedList = 0, SetEquality = 1, SingleValue = 2, NumericTolerance = 3, GeometryTolerance = 4, ExactOrderedListText = 5, SetEqualityText = 6, // jamais réattribués }

Le silence, pire que l'erreur

Le nom disparu lève une exception : on la voit, on répare. Le numéro décalé transforme un exercice d'ensemble en exercice de textes, sans un mot : seuls les étudiants le découvrent, à la correction.

Les numéros explicites

Écrire = 0, = 1… rend chaque numéro visible et fixe. Le jour où quelqu'un insère un membre, il doit lui choisir un numéro neuf, et l'erreur saute aux yeux en relecture.

Piège courant Renommer pour faire plus clair. ExactOrderedListNum était plus précis qu'ExactOrderedList ; il rendait aussi illisibles tous les exercices écrits avec l'ancien nom. Un renommage se fait par un alias lu en plus de l'ancien nom, jamais à sa place.

Schéma 2 · Ajouter sans casser

Ce qu'on peut changer, ce qu'on ne peut pas

Un changement se juge dans les deux sens : un nouveau programme doit relire les vieux fichiers (compatibilité ascendante), et il est bon qu'un vieux programme ne se trompe pas sur un fichier neuf (compatibilité descendante).

Exemple autonome · C#, lire un chunk GH_IO en tolérant les champs absentsint n = bloc.ItemExists("Nombre") ? bloc.GetInt32("Nombre") : 0; string libelle = e.ItemExists("Libelle") ? e.GetString("Libelle") : string.Empty; // la forme de SnapSet, ConceptionListe.cs:275 et 285 : un fichier d'avant le champ se relit

La valeur par défaut est un choix

ExpectedTexts arrive vide sur les anciens exercices, ExpectedBranchSizes null : « liste simple, comme avant » (ExerciseDefinition.cs:22–24). Le défaut doit redonner exactement l'ancien comportement, sinon l'ajout n'est pas additif.

Refuser franchement

Le web ne sait pas comparer un arbre. Plutôt que d'ignorer ExpectedBranchSizes et de corriger à plat, il refuse l'exercice. Un vieux lecteur qui ignore un champ dont le sens compte se trompe en silence.

Piège courant Réutiliser un champ existant pour un sens nouveau (« Tolerance vaudra désormais un pourcentage »). Aucun lecteur ne peut deviner de quelle époque date le fichier : les anciens exercices sont corrigés avec la nouvelle règle, sans erreur.

Schéma 3 · Dire la version

Un numéro pour décider

Quand un changement cassant devient inévitable, le fichier doit dire de quelle version il est. Le lecteur sait alors s'il peut lire, s'il doit convertir, ou s'il doit refuser. Presque tous les formats autour de Magpie le font.

Exemple autonome · C#, migrer à la lectureint version = json.Value<int?>("FormatVersion") ?? 1; // absent : la forme d'avant if (version > VersionConnue) throw new FormatException("Exercice écrit par un Magpie plus récent."); if (version < 2) MigrerV1VersV2(json); // une étape par version

Une étape par version

Chaque migration ne connaît que deux versions voisines. Un fichier v1 passe par v1→v2 puis v2→v3. On n'écrit jamais de conversion v1→v3 directe : il en faudrait une par couple.

Le fichier trop récent

C'est le seul cas qu'un lecteur ne peut pas réparer. Avec un numéro, il dit « mettez à jour Magpie » ; sans numéro, il lit de travers. Le .3dm s'en sert : sa version, en tête, dit quel Rhino au minimum peut l'ouvrir (déduit de l'usage de Rhino).

Piège courant Changer la version à chaque livraison du programme. La version du format ne bouge que quand le format change ; plugin_version 1.0.8 et ArchiveVersion 0.2.2 sont deux numéros distincts dans un même .gh.

À surveiller · des exercices sans version Les 58 exercices ont quatre formes, reconnues seulement aux clés présentes (mesuré), et aucun champ ne dit leur version. Les trois évolutions passées étaient additives ; la suivante pourrait ne pas l'être, et ni le plugin ni le web ne sauront reconnaître un fichier trop récent. Glossaire

Compatibilité ascendante
Le nouveau programme relit les anciens fichiers.
Compatibilité descendante
L'ancien programme se comporte bien devant un fichier neuf.
Changement additif
Un ajout facultatif dont le défaut redonne l'ancien comportement.
Ordinal
Le numéro d'un membre d'enum, écrit à la place de son nom.
Migration
La conversion d'un fichier d'une version vers la suivante.
