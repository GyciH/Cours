Le concept

Lire avec SQL

Une requête SQL ne dit pas comment chercher : elle décrit les lignes voulues, et la base trouve le chemin. Quelques mots suffisent pour la plupart des lectures : choisir des colonnes, filtrer, relier deux tables, grouper et compter, trier. Les surprises viennent presque toutes de NULL et des noms de colonnes.

45 min de lecture et de QCM Prérequis · 34 et 97 Exemples · compute-proxy.mjs, authorize-components.mjs (Magpie)

L'idée en une phrase

On filtre les lignes, on les relie, on les groupe, puis on choisit ce qu'on affiche et dans quel ordre : la base suit cette logique, quel que soit l'ordre d'écriture.

L'analogie

Commander au restaurant : on dit le plat, pas la recette. Le cuisinier choisit l'ordre des gestes, mais le plat doit être celui qu'on a décrit.

À la fin, tu sais

  1. lire une requête dans l'ordre de la base ;
  2. choisir entre JOIN et LEFT JOIN ;
  3. compter par groupe sans erreur ;
  4. éviter les pièges de NULL.
À retenir Les résultats de ce cours ont été obtenus avec node:sqlite, sur une petite base en mémoire qui reprend les tables de Magpie. SQLite suit la norme SQL de près ; PostgreSQL ou SQL Server rendraient les mêmes lignes, à quelques fonctions près.

Schéma 1 · Les jointures

Relier deux tables

Une jointure associe chaque ligne d'une table aux lignes de l'autre qui vérifient une condition, ici l'égalité de la clé étrangère et de la clé primaire. JOIN jette les lignes sans partenaire ; LEFT JOIN garde toutes celles de gauche.

magpie/web/compute-proxy.mjs · lignes 346 à 353, ligne 348 coupée en deuxfunction loadParcoursForAdmin() { const parcoursRows = db.prepare("SELECT * FROM parcours ORDER BY sortOrder, title").all(); const exerciseRows = db.prepare("SELECT id, title, parcoursId, sortOrder FROM exercises ORDER BY sortOrder") .all(); return parcoursRows.map((p) => ({ ...p, exercises: exerciseRows.filter((e) => e.parcoursId === p.id), })); }

Une jointure écrite en JavaScript

Magpie lit les deux tables, puis relie chaque parcours à ses exercices par un filter. C'est un LEFT JOIN : un parcours vide reçoit une liste vide. Le résultat est déjà la forme imbriquée que l'interface attend, ce qu'une jointure SQL, à plat, ne donnerait pas.

Le coût

Chaque parcours parcourt tous les exercices : parcours × exercices comparaisons. Pour quelques dizaines d'exercices, c'est instantané. Un Map des exercices par parcours ramènerait le coût à une seule passe (cours 55).

Piège courant Écrire JOIN quand on veut « tous les parcours, avec leurs exercices ». Le parcours vide disparaît sans erreur : il faut LEFT JOIN, et la table qu'on veut garder entière à gauche.

Schéma 2 · Grouper et compter

Une ligne par groupe

GROUP BY rassemble les lignes qui partagent une valeur, et une fonction d'agrégat résume chaque groupe en une valeur : COUNT, SUM, AVG, MIN, MAX. Le résultat a une ligne par groupe, plus une par ligne de départ.

magpie/web/authorize-components.mjs · ligne 47const total = db.prepare("SELECT COUNT(*) AS n FROM components WHERE isAuthorized = 1").get().n;

Un agrégat sans groupe

Sans GROUP BY, toute la table forme un seul groupe : la requête rend une ligne, et get() la lit. Ici, COUNT(*) est juste, car il n'y a pas de jointure : chaque ligne est un composant.

Nommer le résultat

AS n donne un nom à la colonne calculée. Sans lui, la clé de l'objet JavaScript serait le texte COUNT(*), qu'il faudrait écrire entre crochets. Les scripts de Magpie nomment toujours leurs comptes.

Piège courant Compter avec COUNT(*) après un LEFT JOIN. Le groupe sans partenaire contient une ligne remplie de NULL, que COUNT(*) compte : on compte la colonne de droite, COUNT(e.id).

Schéma 3 · NULL, texte et noms

Ce qui surprend

NULL veut dire « valeur inconnue ». Toute comparaison avec lui rend inconnu, que WHERE traite comme faux. Les fonctions de texte de SQLite ignorent les accents. Et un pilote qui rend des objets doit choisir quand deux colonnes portent le même nom.

magpie/web/authorize-components.mjs · lignes 21 à 26const findExact = db.prepare( "SELECT typeGuid, displayName, name FROM components WHERE LOWER(displayName) = LOWER(?) OR LOWER(name) = LOWER(?)" ); const findSimilar = db.prepare( "SELECT displayName FROM components WHERE LOWER(displayName) LIKE LOWER(?) LIMIT 5" );

Insensible à la casse, pour l'ASCII

Le script retrouve « Panel » quand on tape « panel ». Mais "Circle (Paramètre)" et "circle (PARAMÈTRE)" ne sont pas égaux une fois passés par LOWER : le È reste majuscule (mesuré). Les noms du catalogue n'ont pas de majuscule accentuée, et la saisie habituelle passe.

La recherche approchée

Faute de résultat exact, LIKE '%nom%' propose jusqu'à cinq noms qui contiennent la saisie. Les % sont ajoutés côté JavaScript, la valeur passe par ? : la requête reste paramétrée.

Piège courant Écrire != 'nombres' pour « tous les exercices hors de ce parcours ». Les exercices sans parcours disparaissent aussi : il faut ajouter OR parcoursId IS NULL.

Glossaire

Jointure
L'association des lignes de deux tables selon une condition.
Jointure externe
Une jointure qui garde les lignes sans partenaire, complétées par NULL.
Fonction d'agrégat
Une fonction qui résume un groupe de lignes en une valeur.
NULL
L'absence de valeur ; toute comparaison avec lui est inconnue.
Alias
Un nom donné à une colonne ou une table dans une requête, par AS.
