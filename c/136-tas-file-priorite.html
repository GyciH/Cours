Le concept

Le tas et la file de priorité

Souvent, on n'a pas besoin que tout soit trié : on veut seulement, à chaque instant, le plus petit. Un tas garde exactement cette promesse, et rien de plus. Ajouter et retirer coûtent quelques étages, même pour un million d'éléments. C'est le moteur de PriorityQueue et des plus courts chemins.

45 min de lecture et de QCM Prérequis · 18, 55, 134 Exemples · Magpie, SnapSet, Cuttlefish

L'idée en une phrase

Un tas est un arbre rangé dans un tableau où chaque parent passe avant ses enfants ; il rend le premier élément sans jamais trier les autres.

L'analogie

Les urgences d'un hôpital : on ne classe pas toute la salle d'attente, on sait seulement qui passe maintenant. Un nouvel arrivant grave remonte vite.

À la fin, tu sais

  1. lire un tas dans un tableau ;
  2. rendre une file stable ;
  3. garder les k meilleurs ;
  4. accélérer un Dijkstra.
À retenir Trier, c'est payer pour un ordre complet. Si tu ne lis que le premier, ou les k premiers, ou le prochain d'une liste qui change, un tas fait le même travail pour bien moins cher.

Schéma 1 · Pas trié, juste ordonné

Le minimum, et rien d'autre

On a rempli une PriorityQueue, puis relu son tableau interne par réflexion, son énumération, et sa sortie. Puis on lui a donné dix éléments à égalité.

Exemple autonome · C#, une file de priorité qui respecte l'ordre d'arrivéelong arrivee = 0; var file = new PriorityQueue<Tache, (int Urgence, long Arrivee)>(); file.Enqueue(tache, (tache.Urgence, arrivee++)); // à égalité, le plus ancien d'abord

UnorderedItems porte bien son nom

Énumérer la file rend le tableau interne tel quel : le minimum d'abord, puis un ordre qui ne veut rien dire. Pour lire dans l'ordre, il faut retirer.

Stable ou non

LINQ OrderBy est stable : à égalité, il garde l'ordre d'entrée (documentation). PriorityQueue ne l'est pas : a, puis j, i, h… Un numéro d'arrivée en second critère répare cela.

Piège courant Faire un foreach sur une PriorityQueue en croyant lire dans l'ordre. Sur dix priorités, l'énumération a rendu 0, 2, 1, 3, 5, 8… (mesuré) : seul le premier est à sa place.

Schéma 2 · Les k premiers

Ne pas trier ce qu'on ne lira pas

Garder les dix meilleurs d'un million, c'est un classique : un classement, les points les plus proches, les erreurs les plus fréquentes. On a comparé trier tout, LINQ et un petit tas.

Exemple autonome · C#, les k plus grands avec un tas de k placesvar tas = new PriorityQueue<int, int>(k); // le plus petit des k gardés est en tête foreach (var x in donnees) if (tas.Count < k) tas.Enqueue(x, x); else if (x > tas.Peek()) tas.EnqueueDequeue(x, x); // entre, et chasse le plus petit

Pourquoi un tas de minimum

Pour garder les plus grands, il faut savoir vite qui est le plus faible des gardés : c'est lui qu'un nouveau candidat doit battre. Le tas le met en tête.

Et pour un seul ?

Max, Min, MaxBy et MinBy font un passage, sans tri ni allocation. Ils disent aussi ce que l'on cherche, mieux qu'un OrderBy suivi de First.

Piège courant Trier une copie entière pour en garder dix éléments. Le tri a pris 83 à 195 ms ; le tas de dix places, 1,5 à 15,5 ms et 0,1 Kio (mesuré).

Schéma 3 · Le plus court chemin

Dijkstra : toujours la case la plus proche

Avec des poids, la file du cours 134 ne suffit plus : il faut traiter d'abord la case la plus proche du départ. On a comparé un tas et une recherche du minimum à chaque tour.

Exemple autonome · C#, Dijkstra avec suppression paresseusewhile (file.TryDequeue(out int c, out int dc)) { if (dc > d[c]) continue; // entrée périmée : on a trouvé mieux depuis foreach (int v in Voisins(c)) { int nd = dc + w[v]; if (nd < d[v]) { d[v] = nd; file.Enqueue(v, nd); } } }

Suppression paresseuse

PriorityQueue ne sait pas baisser la priorité d'un élément déjà entré. On en ajoute un second, meilleur, et on jette l'ancien quand il sort.

Les poids doivent être positifs

Dijkstra suppose qu'un chemin ne raccourcit jamais en s'allongeant. Avec des poids négatifs, une case déjà sortie pourrait être améliorée trop tard.

Piège courant Écrire Dijkstra avec une liste et une boucle « chercher le plus petit ». Juste, mais en n² : 1,7 à 1,8 s sur 40 000 cases contre 7 ms avec un tas (mesuré).

Glossaire

Tas
Un arbre rangé dans un tableau où chaque parent passe avant ses enfants.
File de priorité
Une file qui rend toujours l'élément de plus haute priorité.
Tri stable
Un tri qui garde, à égalité de clé, l'ordre d'entrée.
Top-k
La sélection des k meilleurs éléments, sans trier les autres.
Dijkstra
Le calcul des plus courts chemins à poids positifs, case la plus proche d'abord.
