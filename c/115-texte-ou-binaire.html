Le concept

Texte ou binaire

Un fichier n'est qu'une suite d'octets. Ce qui le rend lisible, c'est une règle partagée entre celui qui écrit et celui qui lit. Un fichier texte embarque une grande partie de sa règle avec lui ; un fichier binaire la laisse au programme. Grasshopper sait faire les deux : le .ghx et le .gh portent le même arbre.

45 min de lecture et de QCM Prérequis · 24 Exemples · Magpie web et pédagogie

L'idée en une phrase

Le texte se paie en octets et se lit à l'œil ; le binaire est compact et rapide, mais il faut connaître sa règle octet par octet pour en tirer quoi que ce soit.

L'analogie

La nomenclature d'un plan contre le code-barres de la pièce. La nomenclature se lit sans outil ; le code-barres tient en deux centimètres, mais il faut un lecteur qui connaît la norme.

À la fin, tu sais

  1. reconnaître un fichier par ses premiers octets ;
  2. lire un binaire à longueurs et types annoncés ;
  3. dire ce que coûte le texte, et ce que la compression rend ;
  4. situer le .gh et le .ghx de Magpie.
À retenir Texte ou binaire n'est pas une question de contenu mais d'écriture. Le même arbre GH_IO (chunks, items typés) s'écrit en XML dans un .ghx et en octets compressés dans un .gh ; Magpie web n'écrit que la forme texte.

Schéma 1 · Reconnaître un fichier

La signature, pas l'extension

La plupart des formats binaires commencent par quelques octets fixes, la signature (magic number). Un programme sérieux la lit avant de se fier au nom. On l'a relevée sur tous les fichiers de Magpie.

Exemple autonome · Python, reconnaître un fichier à ses premiers octetsSIGNATURES = {b"\x89PNG": "png", b"PK\x03\x04": "zip", b"MZ": "exécutable", b"BSJB": "pdb"} def nature(chemin): debut = open(chemin, "rb").read(16) return next((n for s, n in SIGNATURES.items() if debut.startswith(s)), "inconnu")

Le .gh n'en a pas

Ses premiers octets (cc ba 63 78 pour A_01.gh) n'annoncent rien : c'est un flux déflaté brut, sans en-tête zlib ni gzip. Seule la décompression, puis le mot « Root », confirment qu'on tient une archive Grasshopper.

Et le texte ?

Il n'a pas de signature, sauf le BOM UTF-8 (ef bb bf) que Visual Studio ajoute : 22 des 51 fichiers .cs de Magpie en ont un. On reconnaît le texte à ce qu'il se décode sans erreur et ne contient pas d'octet nul.

Piège courant Juger un fichier à son extension. Un .docx renommé en .zip s'ouvre très bien, un .gha est une DLL. À l'inverse, un fichier qui porte la bonne extension peut être tronqué ou d'un autre format : la signature se vérifie avant de lire la suite.

Schéma 2 · Lire un binaire

Des longueurs, des types, un ordre d'octets

Sans balises, un format binaire doit dire à chaque pas combien d'octets suivent et comment les lire. L'archive GH_IO le fait avec trois règles, qu'on retrouve dans la plupart des formats binaires.

Exemple autonome · Python, lire une chaîne et un entier GH_IOdef chaine(b, p): # longueur sur 7 bits par octet, puis l'UTF-8 n, dec = 0, 0 while True: c = b[p]; p += 1; n |= (c & 0x7F) << dec; dec += 7 if c < 0x80: return b[p:p + n].decode("utf-8"), p + n entier = struct.unpack_from("<i", b, p)[0] # "<" : petit-boutiste, "i" : 4 octets signés

Octets, pas caractères

« CJ-Développement » compte 16 caractères, mais 17 octets : le « é » en prend deux en UTF-8 (c3 a9). La longueur annoncée, 11 en hexadécimal, compte les octets.

Le type d'abord

Chaque item porte un code : 10 pour une chaîne, 3 pour un entier, 9 pour un GUID (16 octets), 37 pour une image. Le lecteur choisit sa façon de lire d'après ce code ; un code inconnu, et la lecture ne peut plus avancer.

Piège courant Lire un entier dans le mauvais ordre. 50 00 00 00 vaut 80 en petit-boutiste, mais 1 342 177 280 en gros-boutiste. Windows, .NET et les processeurs x86 sont petit-boutistes ; le réseau et certains formats anciens ne le sont pas. Le format doit le dire.

Schéma 3 · Ce que coûte chaque forme

Le texte est gros, puis la compression l'efface

On a converti l'arbre de A_01.gh en XML, avec les conventions de xml-builder.mjs, puis mesuré chaque forme. Le surcoût du texte est réel, mais il fond presque entièrement à la compression.

Exemple autonome · Python, décompresser un .ghimport zlib brut = open("A_01.gh", "rb").read() # 46 710 octets arbre = zlib.decompress(brut, -15) # -15 : déflate brut, sans en-tête print(len(arbre), arbre[1:5]) # 65306 b'Root'

Ce que Git en voit

Le .gh contient des octets nuls (25 dans ses 8 000 premiers), donc Git le traite en binaire : les 275 modifications de .gh de l'historique s'affichent « - - » au numstat, sans aucune ligne de diff. Un .ghx se relirait ligne à ligne.

Pourquoi le base64

JSON ne transporte que du texte. Pour y glisser un fichier, on code 3 octets en 4 caractères sûrs : 186 282 octets deviennent 248 376, exactement un tiers de plus.

Piège courant Choisir le binaire « pour gagner de la place ». Une fois compressé, le texte n'est plus que 7,5 % plus gros ici, et il se relit, se compare et se répare à la main. Le binaire se justifie par la vitesse de lecture ou par des données déjà binaires (images, maillages).

Glossaire

Signature
Les octets fixes qui ouvrent un format (magic number).
Petit-boutiste
L'octet de poids faible écrit en premier (little-endian).
Préfixe de longueur
Le nombre d'octets qui suivent, écrit avant eux.
BOM
Les octets ef bb bf qui marquent un texte UTF-8.
Base64
Un codage du binaire en caractères sûrs, 4 pour 3 octets.
