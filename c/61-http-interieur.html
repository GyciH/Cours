Le concept

HTTP de l'intérieur

Chaque clic sur « Valider » dans Magpie web envoie une requête HTTP au serveur, qui renvoie une réponse. Les deux sont de simples messages texte : une ligne de départ, des en-têtes, une ligne vide, un corps. Savoir les lire, c'est savoir déboguer le web.

50 min de lecture et de QCM Prérequis · 30 et 33 Exemples · compute-proxy.mjs, api.js (Magpie web)

L'idée en une phrase

Le client dit quoi (la méthode : GET, POST…), sur quoi (le chemin) et comment (les en-têtes) ; le serveur répond par un statut à trois chiffres, ses propres en-têtes et, le plus souvent, un corps.

L'analogie

Un courrier administratif. L'objet de la lettre (la ligne de départ), les mentions en marge (les en-têtes : urgent, pièces jointes, à l'attention de), puis le texte. La réponse commence par un tampon : accepté, refusé, adressez-vous ailleurs.

À la fin, tu sais

  1. lire une requête et une réponse brutes ;
  2. choisir la méthode et le statut justes ;
  3. expliquer Content-Type et Cache-Control ;
  4. suivre une requête dans compute-proxy.mjs.
À retenir HTTP est sans état : chaque requête arrive seule, sans souvenir de la précédente. Tout ce dont le serveur a besoin (qui tu es, ce que tu envoies, dans quel format) doit voyager dans la requête elle-même.

Schéma 1 · Méthodes et statuts

Ce qu'on demande, ce qu'on obtient

Le premier chiffre du statut donne la famille ; c'est souvent tout ce qu'un client doit regarder. Les codes ci-dessous sont tous émis quelque part par le serveur Magpie.

Exemple autonome · les méthodesGET /api/catalog lire ; sans corps ; peut être mis en cache ; rejouable sans risque HEAD /index.html comme GET, mais seulement les en-têtes POST /api/submit envoyer des données pour un traitement ; pas rejouable aveuglément PUT /api/item/12 remplacer une ressource entière ; rejouable (même résultat) DELETE /api/item/12 supprimer OPTIONS /api/submit « qu'ai-je le droit de faire ? » : la question préalable de CORS (cours 62)

Idempotent

Une méthode est idempotente si la répéter laisse le même état qu'une seule fois : GET, PUT, DELETE. Un navigateur peut réessayer un GET de lui-même ; il demande confirmation avant de renvoyer un formulaire en POST.

4xx ou 5xx ?

La question est : à qui la faute ? Un JSON mal formé, c'est 400 : le client doit corriger. Rhino Compute qui ne répond pas, c'est 504 : le client peut seulement réessayer plus tard.

Piège courant Répondre 200 avec {"error": …} dans le corps. Le client, les outils de surveillance et le cache croient alors à un succès. Le statut est le premier signal : il doit dire la vérité, le corps donne les détails.

Schéma 2 · Les en-têtes

Ce qui accompagne le corps

Un en-tête est une ligne Nom: valeur. Content-Type dit comment lire le corps ; Cache-Control dit combien de temps le garder. Magpie règle ce dernier selon le nom du fichier, pour que les mises à jour arrivent sans que les visites se ralentissent.

Exemple autonome · en-têtes courantsContent-Type: application/json; charset=utf-8 le format du corps, et son encodage (cours 56) Content-Length: 1834 la taille du corps en octets Cache-Control: no-cache « redemande-moi avant de réutiliser » Location: /admin où aller, avec un statut 3xx WWW-Authenticate: Basic realm="Magpie admin" comment s'identifier, avec un 401 (cours 63)

Le type MIME

Le navigateur ne regarde pas l'extension mais le Content-Type. Un fichier .js servi en text/plain ne s'exécute pas ; un .webmanifest mal typé n'installe pas l'application. D'où la table MIME_TYPES du serveur.

Ouvrir l'onglet Réseau

Dans le navigateur, F12 puis l'onglet Réseau : chaque requête y apparaît avec sa méthode, son statut, ses en-têtes et son corps. C'est le premier réflexe quand une page « ne fait rien ».

Piège courant Mettre en cache longue durée un fichier dont le nom ne change pas. Après une mise en ligne, les visiteurs gardent l'ancien pendant des jours. La règle : cache « pour toujours » seulement pour les noms qui portent une empreinte du contenu.

Schéma 3 · Un serveur sans framework

Le chemin d'une requête dans Magpie

Le serveur Magpie n'utilise pas Express : il lit req.method et req.url et décide lui-même. Le corps arrive en morceaux ; on les assemble, on vérifie la taille, puis on traite. Toute erreur finit en réponse JSON avec le bon statut.

Exemple autonome · Nodeimport http from "node:http"; http.createServer((req, res) => { if (req.method === "GET" && req.url === "/ping") { res.writeHead(200, { "Content-Type": "text/plain; charset=utf-8" }); return res.end("pong"); } res.writeHead(404); res.end(); }).listen(5175);

Pourquoi limiter la taille

Sans limite, un client peut envoyer des centaines de mégaoctets et remplir la mémoire du serveur. Magpie coupe à 1 Mo pour l'apprenant et à 16 Mo pour l'admin authentifié, et répond 413.

Assembler avant de décoder

Un morceau peut couper un caractère UTF-8 en deux (cours 56). On concatène les octets avec Buffer.concat, puis on décode le tout en une fois.

Piège courant Oublier res.end() sur un chemin du code. La connexion reste ouverte, le navigateur attend, et la page tourne jusqu'au délai maximal. Chaque branche du routage doit répondre une fois, et une seule.

Glossaire

Requête
Le message du client : méthode, chemin, en-têtes, corps éventuel.
Statut
Le code à trois chiffres qui ouvre la réponse ; le premier chiffre donne la famille.
En-tête
Une ligne Nom: valeur qui accompagne une requête ou une réponse.
Idempotent
Qu'on peut répéter sans changer le résultat d'une seule exécution.
Type MIME
Le nom du format d'un contenu, comme application/json ou image/png.
