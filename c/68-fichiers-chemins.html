Le concept

Fichiers, chemins et système de fichiers

Le système de fichiers range les octets du disque en un arbre de dossiers et de fichiers. Un chemin est l'adresse d'un nœud de cet arbre. Rien de plus simple en apparence, mais chaque système a ses règles, les dossiers ont des rôles, et une écriture interrompue peut tout abîmer.

50 min de lecture et de QCM Prérequis · 56 et 64 Exemples · EcrivainGeneration, CheminCible (SnapSet), ImportParcours (Magpie)

L'idée en une phrase

On construit les chemins avec les fonctions du langage (jamais à la main), on range chaque donnée dans le dossier fait pour elle, et on écrit de façon qu'une coupure laisse toujours un fichier entier.

L'analogie

Une adresse postale : « 3 rue des Lilas, Lyon » est absolue ; « la maison d'à côté » est relative, et reste juste si tout le quartier déménage ensemble.

À la fin, tu sais

  1. manier chemins absolus et relatifs ;
  2. écrire du code valable sur tout système ;
  3. choisir le bon dossier pour une donnée ;
  4. écrire un fichier de façon atomique.
À retenir Un nom de fichier est du texte, mais un texte contraint : caractères interdits, noms réservés, casse plus ou moins comptée selon le système. Toute donnée qui devient un nom de fichier (un identifiant d'exercice, un titre) se vérifie avant usage.

Schéma 1 · Les règles de chaque système

Un même chemin, deux mondes

Rhino et Grasshopper vivent sous Windows ; le site de Magpie tourne sous Linux. Les deux systèmes ne s'accordent ni sur le séparateur, ni sur la casse, ni sur les caractères permis. Les fonctions Path de .NET et path de Node connaissent ces règles à ta place.

Exemple autonome · C#Path.Combine(dossier, "src", "Capsule.cs"); // le bon séparateur Path.GetFullPath(@"D:\Projets\gh\..\src"); // D:\Projets\src Path.GetRelativePath(@"D:\Projets\gh", @"D:\Projets\src"); // ..\src Path.IsPathFullyQualified(@"..\src"); // false Path.GetInvalidFileNameChars(); // les caractères interdits

En Node

path.join, path.resolve, path.relative et path.sep font la même chose. Le cours 64 a montré normalize(join(…)) qui garde un chemin dans son dossier.

Les fins de ligne

Autre écart entre systèmes : Windows termine les lignes par CR LF, Linux par LF. Le .gitattributes de SnapSet impose LF partout, parce que des tests comparent le texte au caractère près.

Piège courant Path.Combine(dossier, nom) jette dossier si nom est lui-même absolu, ou commence par \. Un nom venu de l'extérieur peut ainsi faire écrire n'importe où. On valide le nom d'abord, ou on vérifie le résultat comme au cours 64.

Schéma 2 · Où ranger quoi

Chaque dossier a son rôle

Windows prévoit un dossier par usage. Un programme qui écrit à côté de son propre exécutable échoue dès qu'il est installé dans Program Files ; un cache rangé dans Documents encombre l'utilisateur. On ne code jamais ces chemins en dur : on les demande au système.

Exemple autonome · C# et NodeEnvironment.GetFolderPath(Environment.SpecialFolder.ApplicationData); // %APPDATA% Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData); Path.GetTempPath(); // %TEMP% os.homedir(); os.tmpdir(); process.env.APPDATA // Node

Et le dossier du plugin ?

Un .gha s'installe souvent dans un dossier de Grasshopper ou du gestionnaire de paquets de Rhino : rien ne garantit qu'on puisse y écrire. Il lit ses ressources depuis lui-même (ressources embarquées) et écrit ailleurs.

Un nom unique pour un temporaire

Deux instances qui écrivent le même temp.txt s'écrasent. Un Guid.NewGuid() dans le nom rend chaque temporaire unique, et un finally le supprime quoi qu'il arrive.

Piège courant Écrire "C:\\Users\\" + nom + "\\AppData". Le profil peut être sur un autre lecteur, redirigé sur le réseau, ou porter un nom avec des accents. GetFolderPath donne le vrai chemin, sur chaque poste.

Schéma 3 · L'écriture atomique

Jamais un fichier à moitié écrit

Écrire un fichier prend du temps. Si le programme plante, si Rhino est fermé, si le courant coupe pendant l'écriture, le fichier reste tronqué. La parade : écrire à côté, dans un temporaire, puis remplacer d'un seul geste. Un renommage dans un même dossier est une opération que le système fait entièrement ou pas du tout.

Exemple autonome · C# (.NET 6 et plus)string tmp = Path.Combine(dossier, ".x-" + Guid.NewGuid().ToString("N") + ".tmp"); File.WriteAllBytes(tmp, octets); File.Move(tmp, chemin, overwrite: true); // remplacement d'un coup, même volume // Node : writeFileSync(tmp, data); renameSync(tmp, chemin);

Le même volume

Le renommage n'est atomique que sur un même disque. Entre deux volumes, « déplacer » devient « copier puis supprimer », ce qui peut s'interrompre au milieu. D'où le temporaire dans le même dossier que la cible.

Le partage sous Windows

Sous Windows, un fichier ouvert par un programme peut refuser les autres (FileShare). Visual Studio qui garde un fichier ouvert peut ainsi bloquer une écriture : on attrape IOException et on l'explique.

Piège courant Supprimer l'ancien fichier, puis écrire le nouveau. Entre les deux, il n'y a plus rien : une coupure à cet instant perd tout. Le remplacement doit être la dernière étape, et la seule qui touche au fichier existant.

Glossaire

Chemin absolu
Un chemin qui part de la racine d'un lecteur ou du système.
Chemin relatif
Un chemin rapporté à un dossier de départ, avec « .. » pour remonter.
Séparateur
Le caractère entre deux noms d'un chemin : \ sous Windows, / ailleurs.
Écriture atomique
Une écriture dont on voit l'avant ou l'après, jamais un état intermédiaire.
Volume
Un disque ou une partition, désigné sous Windows par une lettre.
