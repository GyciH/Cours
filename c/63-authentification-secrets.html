Le concept

L'authentification et les secrets

L'administration de Magpie ne doit s'ouvrir qu'à l'enseignant. Trois questions se succèdent : qui dis-tu être, prouve-le, qu'as-tu le droit de faire. Et la preuve (un mot de passe, une clé) est un secret qui ne doit jamais traîner dans le code.

50 min de lecture et de QCM Prérequis · 61 et 62 Exemples · compute-proxy.mjs, README.md (Magpie web)

L'idée en une phrase

Le client présente des identifiants à chaque requête (HTTP est sans état) ; le serveur les compare à ce qu'il attend, sans rien laisser fuir, et ferme la porte quand il n'a rien pour comparer.

L'analogie

Le gardien d'un chantier. Il demande le nom (identification), vérifie le badge (authentification), puis regarde si ce badge ouvre la zone demandée (autorisation). S'il n'a pas reçu la liste des badges, il ne laisse entrer personne.

À la fin, tu sais

  1. distinguer 401 et 403 ;
  2. lire un en-tête Authorization Basic ;
  3. expliquer la comparaison à temps constant ;
  4. ranger un secret hors du dépôt.
À retenir Une garde de sécurité s'écrit une fois, le plus tôt possible, et fermée par défaut. Une vérification répétée dans chaque route finit toujours par manquer dans la route ajoutée six mois plus tard.

Schéma 1 · HTTP Basic

Le plus simple des schémas

Le serveur répond 401 avec WWW-Authenticate: Basic ; le navigateur affiche sa propre fenêtre, puis renvoie la requête avec Authorization: Basic suivi de « identifiant:mot de passe » codé en base64. Il le refera ensuite tout seul, à chaque requête vers ce site.

Exemple autonome · NodeBuffer.from("enseignant:secret").toString("base64") // "ZW5zZWlnbmFudDpzZWNyZXQ=" Buffer.from("ZW5zZWlnbmFudDpzZWNyZXQ=", "base64").toString() // "enseignant:secret" // curl -u enseignant:secret https://magpie.example/api/admin/parcours

Ses limites

Pas de bouton « Se déconnecter » (le navigateur garde les identifiants jusqu'à sa fermeture), pas de délai d'expiration, un seul compte. Pour un enseignant seul, c'est suffisant ; pour des centaines d'élèves, on passe à des sessions.

Les sessions et les jetons

Après une connexion, le serveur délivre un identifiant de session (dans un cookie HttpOnly, Secure, SameSite) ou un jeton signé. Le mot de passe ne voyage alors qu'une fois.

Piège courant Prendre base64 pour un chiffrement. C'est un simple changement d'alphabet, réversible en une ligne. Sur une connexion HTTP en clair, n'importe quel Wi-Fi public lit le mot de passe. HTTP Basic n'a de sens qu'en HTTPS (cours 66).

Schéma 2 · Comparer sans trahir

Le chronomètre comme espion

Une comparaison ordinaire s'arrête au premier caractère différent. Un attaquant patient mesure le temps de réponse : plus il est long, plus le début de son essai est juste. Il devine alors le secret caractère par caractère, au lieu de tout essayer d'un coup.

Exemple autonome · C# et Node// C# (.NET Core 2.1 et suivants) bool ok = CryptographicOperations.FixedTimeEquals(attendu, recu); // deux byte[] // Node : timingSafeEqual exige deux tampons de même longueur const ok2 = a.length === b.length && crypto.timingSafeEqual(a, b); // la longueur fuit

L'astuce des empreintes

timingSafeEqual refuse deux tampons de longueurs différentes, ce qui révélerait la longueur du secret. Magpie compare donc les empreintes SHA-256 des deux chaînes : toujours 32 octets, quelle que soit la saisie.

Pas de court-circuit

Avec userOk && passwordOk calculés à l'avance, les deux comparaisons ont toujours lieu. Un identifiant faux ne répond pas plus vite qu'un mot de passe faux : l'attaquant n'apprend même pas lequel des deux est juste.

Piège courant Comparer un secret avec == ou string.Equals. Sur un réseau local ou un serveur partagé, l'écart se mesure avec assez d'essais. La parade ne coûte qu'un appel : utiliser la fonction de comparaison à temps constant de la plateforme.

Schéma 3 · Où vivent les secrets

Jamais dans le dépôt

Un mot de passe, une clé d'API, une chaîne de connexion : tout ce qui ouvre une porte. Écrit dans le code, il part dans chaque clone et reste dans l'historique Git même après sa suppression. On le lit dans l'environnement au démarrage.

Exemple autonome · lire un secretconst cle = process.env.COMPUTE_API_KEY || ""; // Node string cle = Environment.GetEnvironmentVariable("COMPUTE_API_KEY"); // C# // Windows (PowerShell) : $env:MAGPIE_ADMIN_PASSWORD = "…" ; node compute-proxy.mjs // .gitignore : .env .env.* !.env.example

Le fichier exemple

Un .env.example versionné liste les variables attendues avec des valeurs factices ; le vrai .env reste hors du dépôt. Le .gitignore de Magpie fait exactement cette exception.

Un secret a fuité ?

Le supprimer du code ne suffit pas : il est dans l'historique, et peut-être déjà copié. On le change d'abord (nouveau mot de passe, nouvelle clé), puis on nettoie.

Piège courant Un mot de passe par défaut « pour le développement » : process.env.PASS || "admin". Oublié en production, il ouvre la porte à quiconque lit le code. Le bon défaut est vide, et vide veut dire fermé.

Glossaire

Authentification
Prouver qu'on est bien celui qu'on dit être.
Autorisation
Décider ce qu'un utilisateur authentifié a le droit de faire.
Base64
Un codage d'octets en 64 caractères imprimables ; réversible, sans aucune clé.
Attaque temporelle
Déduire un secret de la durée des réponses du serveur.
Fermé par défaut
Refuser l'accès quand la configuration manque, plutôt que l'ouvrir.
