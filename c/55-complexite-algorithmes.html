Le concept

La complexité des algorithmes

Un composant Grasshopper qui répond en un clin d'œil sur 50 points peut figer Rhino sur 5 000. La raison n'est pas la vitesse de la machine mais la forme du calcul : combien d'opérations il fait quand les données grandissent. La notation O(…) sert à le dire en une ligne.

50 min de lecture et de QCM Prérequis · 03, 16 et 17 Exemples · Voronoi, Bubble, Outils (Cuttlefish), MagpieExerciseEditor

L'idée en une phrase

La complexité dit comment le nombre d'opérations grandit avec n, la taille des données, en oubliant les constantes : O(n²) veut dire « doubler n multiplie le travail par quatre », quel que soit le processeur.

L'analogie

Saluer les invités d'une fête. Serrer la main de chacun en arrivant, c'est n poignées de main. Que chacun serre la main de tous les autres, c'est n²/2 : à 10 invités on ne le remarque pas, à 1 000 la soirée n'y suffit pas.

À la fin, tu sais

  1. compter les boucles d'un code et en tirer son ordre de grandeur ;
  2. ranger O(1), O(log n), O(n), O(n log n) et O(n²) ;
  3. choisir entre List, HashSet et Dictionary ;
  4. repérer une boucle cachée dans un Contains ou une requête LINQ.
À retenir Passer de O(n²) à O(n log n) fait plus que n'importe quel ordinateur plus rapide. À l'inverse, pour 20 éléments, n² vaut 400 : rien. La complexité sert à prévoir ce qui arrive quand n grandit, pas à optimiser ce qui va déjà vite.

Schéma 1 · Compter les boucles

Ce que coûte chaque forme de boucle

On ne compte pas les opérations une à une : on regarde combien de fois le corps des boucles s'exécute quand n grandit. Une boucle sur n éléments coûte n ; deux boucles imbriquées, n × n ; une boucle qui coupe le problème en deux à chaque tour, log n.

Exemple autonome · C#for (int i = 0; i < n; i++) total += v[i]; // O(n) for (int i = 0; i < n; i++) for (int j = 0; j < n; j++) … // O(n²) for (int i = 0; i < n; i++) for (int j = i + 1; j < n; j++) … // n(n−1)/2 : encore O(n²) int k = liste.BinarySearch(x); // liste triée : O(log n), 20 étapes pour un million liste.Sort(); // O(n log n), le prix d'un tri

On garde le terme qui domine

3n² + 50n + 1 000 s'écrit O(n²) : quand n grandit, n² écrase le reste. De même, n(n−1)/2 est en O(n²) : diviser par deux ne change pas la forme de la courbe.

Deux tailles, deux lettres

Quand deux données grandissent séparément, on garde les deux : comparer n points à m courbes coûte O(n × m). Écrire O(n²) ferait croire qu'il n'y a qu'une taille.

Piège courant Une seule boucle peut cacher une deuxième. liste.Contains(x), IndexOf, Remove, First(…) ou Where(…) parcourent la liste : appelés dans une boucle sur n, ils donnent du n² sans qu'aucun second for n'apparaisse.

Schéma 2 · Choisir la bonne structure

Chercher dans une liste ou dans une table

Une liste ne sait pas où est un élément : elle compare un à un. Un HashSet ou un Dictionary calcule un code de hachage qui désigne directement une case. La recherche passe de O(n) à O(1) en moyenne, au prix d'un peu de mémoire.

Exemple autonome · C# · les coûts usuelsList<T> [i] O(1) Add O(1) Contains O(n) Insert(0, …) O(n) HashSet<T> Add O(1) Contains O(1) pas d'ordre, pas de doublon Dictionary<K,V> [clé] O(1) TryGetValue O(1) SortedSet<T> Add O(log n) Contains O(log n) gardé trié

Le prix du hachage

Le O(1) est une moyenne : deux valeurs peuvent tomber dans la même case, qu'on parcourt alors. Avec un bon GetHashCode, c'est rare. Les types de base (int, string, Guid) en ont un bon.

Construire une fois, chercher souvent

Construire un HashSet de n éléments coûte O(n). Cela vaut la peine dès qu'on y cherche plusieurs fois ; pour une seule recherche, la liste suffit.

Piège courant Un type à toi, mis dans un HashSet ou en clé de Dictionary, est comparé par référence si tu ne redéfinis pas Equals et GetHashCode ensemble. Deux objets « égaux » seront alors vus comme deux clés différentes.

Schéma 3 · Changer d'algorithme

De toutes les paires à un index

Chercher le plus proche voisin de chaque point en comparant tout à tout coûte O(n²). Un index spatial (le R-tree du cours 17) range les points dans des boîtes : chaque point n'interroge que les boîtes proches, et le total tombe autour de O(n log n).

Exemple autonome · C# · mesurer avant d'optimiservar chrono = System.Diagnostics.Stopwatch.StartNew(); var resultat = Calcul(points); chrono.Stop(); RhinoApp.WriteLine($"{points.Count} points : {chrono.ElapsedMilliseconds} ms"); // on relance avec 2 fois plus de points : ×2 → O(n), ×4 → O(n²)

Doubler pour savoir

Sans lire le code, on peut deviner la complexité en mesurant : on double n et on regarde le temps. ×2, c'est linéaire ; ×4, c'est quadratique ; un peu plus que ×2, c'est souvent n log n.

Les trois remèdes classiques

Trier d'abord pour chercher ensuite par dichotomie ; indexer (table de hachage, R-tree) ; ou sortir de la boucle ce qui ne dépend pas d'elle. Les trois remplacent un parcours répété par un travail fait une fois.

Piège courant Mesurer un composant Grasshopper une seule fois trompe : le premier calcul paie le chargement et la compilation à la volée (JIT). On mesure le deuxième ou le troisième, et toujours sur plusieurs tailles.

Glossaire

Complexité
La façon dont le coût d'un calcul grandit avec la taille des données.
O(…)
La notation qui garde le terme dominant et oublie les constantes.
Dichotomie
Chercher dans une liste triée en coupant l'intervalle en deux à chaque étape.
Table de hachage
Une table où un calcul sur la clé désigne directement la case (HashSet, Dictionary).
Code de hachage
Le nombre tiré d'une valeur par GetHashCode, qui choisit sa case.
