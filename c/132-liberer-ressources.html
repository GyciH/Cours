Le concept

Libérer les ressources

Le ramasse-miettes rend la mémoire, mais pas le reste : un fichier ouvert, une police GDI+, un document Rhino ouvert en arrière-plan. Pour ceux-là, c'est le code qui dit « j'ai fini », par Dispose. Le dire trop tard bloque les autres ; ne jamais le dire perd parfois des données.

45 min de lecture et de QCM Prérequis · 127, 130 Exemples · SnapSet, Magpie plugin

L'idée en une phrase

Tout objet qui tient quelque chose hors de la mémoire implémente IDisposable ; celui qui l'a créé l'appelle dès qu'il a fini, de préférence par un using.

L'analogie

Un livre emprunté. Le ménage finira par le retrouver sous le lit, mais d'ici là personne d'autre ne peut l'emprunter : on le rend en sortant.

À la fin, tu sais

  1. repérer ce qui doit être libéré ;
  2. écrire un using qui tient ;
  3. ne pas compter sur le finaliseur ;
  4. garder en vie ce qui doit durer.
À retenir Qui crée libère, sauf s'il confie l'objet à un propriétaire qui s'en charge. Un objet tenu en cache pour toute la session ne se libère pas : c'est un choix, et il s'écrit en commentaire.

Schéma 1 · using

Fermer même quand ça lève

using appelle Dispose à la sortie du bloc, quelle que soit la sortie. On a tracé chaque ouverture et chaque fermeture, avec une exception au milieu.

Exemple autonome · C#, la forme courte depuis C# 8using var ecrivain = new StreamWriter(chemin); // fermé à la fin de la méthode, quoi qu'il arrive ecrivain.WriteLine(ligne);

Ce que using écrit pour toi

Un try avec un finally qui appelle Dispose si la variable n'est pas null. C'est exactement ce que fait Magpie à la main autour du document Rhino du certificat.

Dispose doit tolérer

D'être appelé deux fois sans rien casser ; c'est le contrat, et MemoryStream le tient. Après, toute autre méthode peut lever ObjectDisposedException.

Piège courant Oublier de fermer un StreamWriter. Son tampon n'est jamais vidé : 100 caractères écrits, 0 octet sur le disque, et toujours 0 après un ramassage (mesuré).

Schéma 2 · Le finaliseur

Un filet de sécurité, tardif et cher

Une classe peut déclarer un finaliseur, ~Classe(), que le GC appelle avant de la ramasser. Certaines classes du framework s'en servent pour rattraper un oubli. On a mesuré quand, et combien.

Exemple autonome · C#, une classe qui ne fait que posséderpublic sealed class Rapport : IDisposable // pas de finaliseur : rien de natif en direct { private readonly StreamWriter _sortie; public Rapport(string chemin) => _sortie = new StreamWriter(chemin); public void Dispose() => _sortie.Dispose(); // libère ce qu'elle possède }

Pourquoi c'est cher

Un objet à finaliseur survit au premier ramassage, attend son tour sur un fil dédié, puis est ramassé au suivant. SuppressFinalize, appelé dans Dispose, lui évite ce détour.

Quand en écrire un

Presque jamais. Un handle natif s'enveloppe dans un SafeHandle, qui a déjà le sien ; une classe qui ne possède que des objets .NET n'en a pas besoin.

Piège courant Croire que « le GC finira par fermer ». Il ferme un FileStream, à une heure inconnue ; il ne vide pas le tampon d'un StreamWriter ; et rien ne dit qu'il passera avant la fin du programme.

Schéma 3 · Qui garde quoi en vie

Ni trop tôt, ni trop tard

Libérer, c'est choisir une fin de vie. Trop tard, une ressource reste bloquée ; trop tôt, ou sans personne pour la tenir, elle disparaît en plein travail.

Exemple autonome · C#, une vie calée sur celle du composantpublic override void AddedToDocument(GH_Document d) { _minuteur = new Timer(…); } // tenu par un champ public override void RemovedFromDocument(GH_Document d) { _minuteur?.Dispose(); _minuteur = null; }

Le Timer orphelin

Rien ne retenait le Timer créé sans champ : le GC l'a ramassé, et il s'est arrêté sans erreur. C'est le bug qui n'apparaît qu'après quelques minutes d'usage.

Libérer après coup

SnapSet ne libère pas la zone de saisie dans son propre gestionnaire : il repousse Dispose par BeginInvoke, une fois l'événement en cours terminé.

Piège courant Garder un fichier ouvert « pour plus tard ». Tant qu'il est tenu sans partage, toute autre ouverture lève IOException (mesuré) : l'utilisateur ne peut plus le copier ni l'écraser.

Glossaire

Ressource
Ce qu'un objet tient hors de la mémoire gérée : fichier, handle, police, document.
IDisposable
L'interface d'un objet qui a quelque chose à rendre, par sa méthode Dispose.
Finaliseur
La méthode ~Classe() que le GC appelle avant de ramasser l'objet, quand il peut.
Descripteur
Le numéro qu'un système donne à un fichier ouvert ; leur nombre est limité.
Propriétaire
L'objet chargé de libérer une ressource qu'il a créée ou reçue.
